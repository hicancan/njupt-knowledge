# njupt-knowledge

南京邮电大学的课程知识：把散落的往年试卷、复习资料清洗成 Markdown，按知识点组织起来。

```text
courses/<学科>.md          一个学科的知识目录：按讲授顺序的章节，每章链接若干知识点
topics/<学科>/<知识点>.md      一个知识点；requires 写它依赖的知识点
materials/<来源>/<原课程代码>/  一份资料整理成的 Markdown，图片放在同名 .assets/ 里
tools/                         索引、反链与发布构建
```

- **树加双链**：课程目录是树，知识点之间的 requires 和资料里的“知识点”链接把树连成图。只写正向链接；每个知识点被哪些课程讲、被哪些资料引用、又支撑哪些知识点，由构建算出来。
- **原件可追溯**：每份资料的 `source` 指向原文件。原件不放进这里；“参考解答”“订正”“补充”标明是整理时加的。
- **课程与学科分开**：`courses/<学科>.md` 汇集共同的知识目录，`codes` 列出现行课程代码，`former` 列出旧代码；培养方案按代码引用课程，同一学科可以服务多门课程。

## 构建

```sh
npm ci                     # 共用的 docstream 文档内核
python3 tools/build.py      # 检查所有链接，生成 build/knowledge.json 和文档
```

发布出去的文档去掉了 front matter，链接和图片都改写成从仓库根开始的路径（如 `topics/数据结构/堆栈.md`、`materials/…#选择-2`），各端用同一种方式解析。每次合入 main 都会构建并发布一个 `knowledge-YYYYMMDD-HHMM` Release。

## 持续完善

原件管理和历史资料的批量导入属于上游 `njupt-knowledge-sources`，不参与这里的发布构建。知识一旦形成，人和 AI 都直接修改对应的 Markdown；发现具体错误就更正，历史交给 Git。

文件树表达知识归属，正向链接生成反链，正文帮助读者建立认知框架：从问题、基本事实和约束出发，在关键转折处提问，说明概念的机制、适用条件、关联与区别，并给出算对的例子。组织方式随知识而定，不套统一的文章模板。

## 投稿

欢迎通过 Pull Request 补充资料、订正答案、完善知识点。一份资料一个文件，每道题一个标题，题后写“知识点：”并链接到 `topics/` 里的知识点。
