## ch02 Software Engineering

### 选择 1

Which of the items listed below is not one of the software engineering layers? （）

- A. Process
- B. Manufacturing
- C. Methods
- D. Tools

答案：B

参考解答：**结论**：A

**推理**：瀑布模型是线性顺序的开发流程，每个阶段必须完成后才能进入下一阶段，因此只有当需求在前期已明确且稳定时，它才适用。  
- B 错：瀑布模型不追求快速交付可运行程序，它强调文档和阶段完成。  
- C 错：大团队不一定最适合瀑布，需求不确定时大团队用瀑布反而风险高。  
- D 错：瀑布模型仍在使用，并非完全被弃用，只是需满足特定条件。

知识点：[调试（Debugging）作为诊断过程：调试技术、错误类型与纠正错误](../../../topics/软件工程/调试过程.md)

### 选择 2

Software engineering umbrella activities are only applied during the initial phases of software development projects. （）

- A. True
- B. False

答案：B

参考解答：**结论**  
选 **A**。

**推理**  
瀑布模型是线性顺序的，强调前一阶段完成并文档化后才进入下一阶段。  
- **A 对**：需求明确且稳定时，瀑布模型按计划推进，变更少，契合良好。  
- **B 错**：需要快速交付可工作核心产品是迭代或原型模型的特长，瀑布无法快速出原型。  
- **C 错**：瀑布并不因团队规模大就成为“最佳”；大型团队常需迭代或并行开发，瀑布的刚性反而不利。  
- **D 错**：瀑布并非“革命性模型”，在商业产品中广泛使用过（尽管已非主流），因此描述不符。

知识点：[测试的目标（Goal of Testing）与软件可测试性（Testability）](../../../topics/软件工程/测试目标与可测试性.md)、[软件测试模式（Software Testing Patterns）](../../../topics/软件工程/软件测试模式.md)

### 选择 4

Planning ahead for software reuse reduces the cost and increases the value of the systems into which they are incorporated. （）

- A. True
- B. False

参考解答：**结论**：B

**推理过程**：
原型模型（Prototyping Model）的核心目的是通过快速构建一个可运行的系统雏形，帮助用户和开发者在交互中澄清模糊的需求。

*   **选 B 的原因**：当客户无法清晰定义需求时，原型提供了直观的反馈机制，能有效挖掘隐含需求，降低需求不确定性带来的风险。
*   **A 不对**：若需求已明确定义，直接使用瀑布模型或增量模型更高效，无需原型的迭代探索成本。
*   **C 不对**：大型团队通常涉及复杂的架构和严格的文档规范，原型模型缺乏严格的过程控制，难以协调大规模协作，易导致管理混乱。
*   **D 不对**：虽然存在“原型即最终产品”的质量风险，但它在需求分析阶段极具价值，并非“很少产生有意义产品”，而是常用于辅助最终产品的开发。

知识点：[黑盒测试（Black-Box Testing / Behavioral Testing）：等价类划分与边界值分析](../../../topics/软件工程/黑盒测试.md)、[测试的目标（Goal of Testing）与软件可测试性（Testability）](../../../topics/软件工程/测试目标与可测试性.md)

### 选择 5

The essence of software engineering practice might be described as understand the problem, plan a solution, carry out the plan, and examine the result for accuracy. （）

- A. True
- B. False

参考解答：**结论：C**

**推理：**
增量模型将软件产品划分为若干增量构件，逐次开发、集成并交付。其核心特征是在每个迭代周期内，开发团队都会结合当前增量进行**项目风险评估**（Risk Evaluation），以便尽早识别、分析和缓解潜在问题，从而有效管理复杂性和不确定性。

**其他选项分析：**
- **A 错误**：增量模型的生命周期并非在首次交付后即告终结，而是持续迭代，直至所有预定增量完成并满足最终产品需求。
- **B 错误**：该选项存在逻辑谬误（“比自身更混乱”），且增量模型通过分阶段交付和风险控制，通常比传统瀑布模型更具条理性。
- **D 错误**：由于 A 和 B 均不成立，故“以上全部”选项无效。

知识点：[白盒测试（White-Box Testing）与基本路径测试（Basis Path Testing）](../../../topics/软件工程/白盒测试.md)、[黑盒测试（Black-Box Testing / Behavioral Testing）：等价类划分与边界值分析](../../../topics/软件工程/黑盒测试.md)

### 选择 7

A most software development projects are initiated to try to meet some business need. （）

- A. True
- B. False

答案：A

参考解答：**C. 敏捷宣言（Manifesto for Agile Software Development）的价值观和原则**

- **为什么选 C**：所有敏捷过程模型（如 Scrum、XP、Kanban、Crystal 等）都在不同程度上遵循敏捷宣言提出的核心价值观（个体与互动、可工作的软件、客户协作、响应变化）和十二项基本原则，这是敏捷方法的本质特征。

- **其他选项为什么不对**：
  - **A**：敏捷明确反对“过程和工具优于个体与互动”，该选项与敏捷价值观相悖；
  - **B**：敏捷拥抱变化而非遵循固定计划，严格遵循预定义计划是瀑布模型的特征；
  - **D**：敏捷强调可工作的软件优于详尽的文档，全面文档优先是传统重型过程的特点。

知识点：[白盒测试（White-Box Testing）与基本路径测试（Basis Path Testing）](../../../topics/软件工程/白盒测试.md)、[控制结构测试（Control Structure Testing）：条件测试与循环测试](../../../topics/软件工程/控制结构测试.md)

In general software only succeeds if its behavior is consistent with the objectives of its designers. （）

- A. True
- B. False

答案：B

## ch03 Software Process Structure

参考解答：**D. All of the above.**

**推理：**
形式化方法（Formal Methods）以数学为基础，贯穿软件开发全过程：

1. **定义规范（A）**：用形式化规格说明语言（如 Z、VDM）对系统行为进行精确、无二义的数学描述。
2. **验证正确性（C）**：通过数学证明（如定理证明、模型检测）验证实现满足规范，保证系统正确性。
3. **开发无缺陷系统（B）**：形式化方法的目标正是通过严格的数学推导，尽可能开发出无缺陷的系统。

因此 A、B、C 均是形式化方法的用途，选 **D**。

知识点：[白盒测试（White-Box Testing）与基本路径测试（Basis Path Testing）](../../../topics/软件工程/白盒测试.md)、[控制结构测试（Control Structure Testing）：条件测试与循环测试](../../../topics/软件工程/控制结构测试.md)
