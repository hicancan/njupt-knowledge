### 简答 1

串行通信的三种数据传输方式。

参考解答：**结论**

串行通信的三种数据传输方式为：**单工（Simplex）**、**半双工（Half-Duplex）**和**全双工（Full-Duplex）**。

**推理与解析**

这三种方式根据数据流动的方向性和同时性进行划分：

1.  **单工通信**
    *   **定义**：数据只能沿一个固定方向传输，不能反向。
    *   **特点**：信道单向，一方仅发送，另一方仅接收。
    *   **示例**：广播电台到收音机、键盘到主机。

2.  **半双工通信**
    *   **定义**：数据可以双向传输，但不能在同一时刻进行。
    *   **特点**：双方都有发送和接收能力，但需分时复用信道。通常使用两根信号线或一根信号线配合控制信号。
    *   **示例**：对讲机、RS-485 总线。

3.  **全双工通信**
    *   **定义**：数据可以在同一时刻进行双向传输。
    *   **特点**：通信双方可同时进行发送和接收操作，效率最高。通常需要独立的发送和接收通道（如两根独立的数据线）。
    *   **示例**：电话通话、RS-232 标准接口、以太网。

**推理/计算过程**

**1) 帧格式的基本组成**
异步通信以字符为单位。无数据传输时线路为空闲(高电平)。
*   **起始位**：1位，逻辑“0”低电平，通知接收方数据即将到来，进行同步。
*   **数据位**：紧跟起始位，通常5~8位。传送时**低位(LSB)在前**，高位(MSB)在后。
*   **校验位**：可选，紧跟数据位。用于差错检测，可设为奇校验、偶校验或无校验。
*   **停止位**：逻辑“1”高电平，标志着帧结束。长度可选1位、1.5位或2位，为下一个起始位提供间隔。

**2) 通信速率的概念**
指串行通信中每秒钟传输的二进制数据位数，即**波特率**，单位为 **bps** (bits per second)。异步通信中收发双方的时钟是独立的，必须在通信前约定好完全相同的波特率及帧格式，以正确采样数据。

**3) RS-232C 逻辑电平范围**
RS-232C 使用双极性负逻辑：
*   **逻辑“1” (MARK)**：范围在 **-3V 至 -15V** 之间。
*   **逻辑“0” (SPACE)**：范围在 **+3V 至 +15V** 之间。
注：-3V 到 +3V 为过渡区，电平无效。

**4) RS-232C 引脚连接图**
图中所示为典型的无硬件流控（无握手）DTE-DCE 连接。根据图注，两侧均为9针D型连接器，引脚名称如下：
*   **引脚2**：TXD (发送数据)
*   **引脚3**：RXD (接收数据)
*   **引脚5**：GND (信号地)
连接必须交叉数据流以满足“发送对接收”的原则：
*   本端的 TXD (2) 连接到对端的 RXD (2)。仔细观察两图，左侧设备标注“2 TXD”，右侧设备对应脚标注“2 RXD”，反之亦然。因此连线为 **2-2** 和 **3-3**。
*   信号地用于建立公共参考点，直接相连：**5-5**。

### 简答 3

如果希望8250采用中断方式发送和接收数据，编程时应该采取哪些措施？

参考解答：**结论**

要实现 8250 UART 的中断方式收发，编程时需执行以下关键步骤：
1. **允许中断**：向中断允许寄存器（IER，地址偏移 1）写入数据，置位接收数据可用中断（RDA）和发送保持寄存器空中断（THRE）。
2. **设置中断标识**：向线路控制寄存器（LCR，地址偏移 3）的最高位（DLAB）写 0，以访问 IER 而非波特率除数锁存器。
3. **初始化 FIFO（若为 16550 及以上）**：向 FIFO 控制寄存器（FCR）写入数据以启用 FIFO 并设置触发级别。
4. **CPU 侧开中断**：确保 CPU 的中断标志位 IF 置 1（如执行 `STI` 指令），并正确设置中断向量表或中断服务程序入口。
5. **在中断服务程序中清除中断源**：读取中断标识寄存器（IIR）以确定中断类型，并通过读取接收缓冲寄存器（RBR）或写入发送保持寄存器（THR）来清除中断请求。

**推理与关键步骤**

8250 UART 本身不产生 CPU 可识别的中断信号，除非其内部中断逻辑被使能且 CPU 全局中断开放。具体逻辑如下：

1.  **使能器件级中断**：
    8250 的中断允许寄存器（IER）控制哪些事件可以触发中断请求引脚（INTR）。
    -   接收中断：需将 IER 的 bit 0 (RDAIE) 置 1。
    -   发送中断：需将 IER 的 bit 1 (THRIE) 置 1。
    -   *注意*：访问 IER 前必须确保 LCR 的 bit 7 (DLAB) 为 0，否则地址偏移 1 指向的是波特率除数锁存器的高字节。

    $$ \text{IER} = 0x03 \quad (\text{二进制 } 00000011) $$

2.  **CPU 级中断允许**：
    即使 8250 发出了 INTR 信号，如果 CPU 的 IF 标志为 0，CPU 也不会响应。因此必须执行开中断指令。

3.  **中断处理与清除**：
    8250 的中断是电平触发或边沿触发（取决于具体实现和 FIFO 状态），必须通过软件操作清除。
    -   读取 IIR 寄存器判断中断源。
    -   若是接收中断，必须从 RBR 读取数据，否则中断会持续挂起。
    -   若是发送中断，必须向 THR 写入新数据或暂时禁止发送中断，否则只要 THR 为空，中断就会不断产生。

**易错点说明**
-   仅设置 IER 而不开放 CPU 中断（IF=1），系统无法响应。
-   在中断服务程序中未读取 RBR 或未写入 THR，会导致中断无法撤销，造成“中断风暴”。
-   忘记检查 LCR 的 DLAB 位，导致误写波特率寄存器而非 IER。

### 简答 4

8250 内部有那几种中断类型？请按照优先级由高到低列举。

参考解答：## 结论

8250（UART）内部共有 **4 种中断类型**，按优先级由高到低依次为：

1. **接收线路状态中断**（最高优先级）
2. **接收数据就绪中断**
3. **发送保持寄存器空中断**
4. **调制解调器状态中断**（最低优先级）

## 推理

8250 的中断优先级是**硬件固定**的，不能通过软件改变。当多个中断源同时请求时，8250 内部的中断优先级仲裁电路按上述固定顺序进行响应。

各中断源对应的中断标识寄存器（IIR）编码及含义如下：

| 优先级 | 中断类型 | IIR 编码（b3~b1） | 中断源 |
|--------|----------|-------------------|--------|
| 1（最高） | 接收线路状态中断 | 110 | 奇偶错、帧错、溢出错、中止（Break）等接收线路状态异常 |
| 2 | 接收数据就绪中断 | 100 | 接收缓冲寄存器已收到一个完整字符 |
| 3 | 发送保持寄存器空中断 | 010 | 发送保持寄存器空，可以写入下一个待发字符 |
| 4（最低） | 调制解调器状态中断 | 000 | CTS、DSR、RI、RLSD 等 Modem 控制信号状态发生变化 |

### 简答 5

8255A三种工作方式及其适用端口。

参考解答：**结论：**
- **方式 0（基本输入/输出方式）：** A、B、C 端口均适用。
- **方式 1（选通输入/输出方式）：** 仅 A、B 端口适用。
- **方式 2（双向总线传送方式）：** 仅 A 端口适用。

**推理过程：**

1.  **方式 0：** 这是最基本的工作方式。A 组（PA）和 B 组（PB）均可作为 8 位 I/O 端口；C 组（PC）分为高 4 位和低 4 位，可分别独立设定为输入或输出。因此三个端口都可用。
2.  **方式 1：** 这是带“握手”信号的选通工作方式。此时 PA 和 PB 作为数据端口，而 **PC 的部分引脚被借用**作为固定的联络/控制信号（如 $\overline{STB}$、$\overline{IBF}$、$\overline{ACK}$、$\overline{OBF}$ 等），PC 剩余引脚作为通用 I/O。由于 PC 本身充当辅助角色且无法独立进行选通传输，故该方式仅适用于 PA 和 PB。
3.  **方式 2：** 这是双向数据总线方式。它要求数据线既可以输入又可以输出，且需要复杂的双向握手信号（$\overline{STB}$、$\overline{IBF}$、$\overline{OBF}$、$\overline{ACK}$ 等）来管理总线冲突。仅 **PA** 拥有足够的引脚资源及逻辑支持来实现双向缓冲和完整的握手控制，故仅适用于 PA。

### 简答 6

8255A工作在方式 1时，需要哪些信号联络线，各信号联络线的含义。

参考解答：# 结论

8255A 工作在**方式 1（选通输入/输出方式）**时，A 口和 B 口作为数据口，C 口的某些引脚被用作**联络（握手）信号线**。

- **A 口方式 1 输入**：使用 C 口的 PC3、PC4、PC5
- **A 口方式 1 输出**：使用 C 口的 PC3、PC6、PC7
- **B 口方式 1 输入**：使用 C 口的 PC0、PC1、PC2
- **B 口方式 1 输出**：使用 C 口的 PC0、PC1、PC2

联络信号共三类：**选通信号 STB、输入缓冲器满 IBF、中断请求 INTR**（输入时）；**输出缓冲器满 OBF、响应信号 ACK、中断请求 INTR**（输出时）。

---

# 各联络信号含义

## 输入操作时（A 口：PC4=STB_A，PC5=IBF_A，PC3=INTR_A；B 口：PC2=STB_B，PC1=IBF_B，PC0=INTR_B）

| 信号 | 含义 |
|------|------|
| $\overline{STB}$（Strobe，选通输入） | 外设发出的选通信号，低电平有效。有效时将外设数据打入 8255A 的输入锁存器 |
| $IBF$（Input Buffer Full，输入缓冲器满） | 8255A 发出的状态信号，高电平有效。表示输入锁存器中已有数据但尚未被 CPU 取走 |
| $INTR$（Interrupt Request，中断请求） | 8255A 向 CPU 发出的中断请求信号，高电平有效。当 $IBF=1$ 且中断允许（INTE=1）时产生，请求 CPU 读取数据 |

## 输出操作时（A 口：PC7=OBF_A，PC6=ACK_A，PC3=INTR_A；B 口：PC1=OBF_B，PC2=ACK_B，PC0=INTR_B）

| 信号 | 含义 |
|------|------|
| $\overline{OBF}$（Output Buffer Full，输出缓冲器满） | 8255A 发出的状态信号，低电平有效。表示 CPU 已将数据写入输出锁存器，通知外设可以取走数据 |
| $\overline{ACK}$（Acknowledge，响应信号） | 外设发来的应答信号，低电平有效。表示外设已从 8255A 取走数据 |
| $INTR$（Interrupt Request，中断请求） | 8255A 向 CPU 发出的中断请求信号，高电平有效。当 $\overline{ACK}$ 结束（即外设已取走数据）且中断允许（INTE=1）时产生，请求 CPU 输出下一个数据 |

---

# 补充说明

- **INTE（中断允许）**：方式 1 中，A 口输入时由 PC4 置位/复位控制，A 口输出时由 PC6 控制；B 口输入时由 PC2 控制，B 口输出时由 PC2 控制。INTE 为内部标志，不引出到引脚，通过对 C 口相应位按位置位/复位命令字来设置。
- C 口中未被用作联络线的引脚仍可作为普通 I/O 线使用。

### 简答 7

PC 系统机中8254 芯片有哪些功能？

参考解答：## 结论

PC 系统机中 8254 芯片（可编程间隔定时器）主要提供 **3 个独立功能**，分别由其 3 个计数器通道实现：

1. **计数器 0**：产生系统日时钟定时中断（IRQ0）。
2. **计数器 1**：产生 DRAM 刷新定时请求。
3. **计数器 2**：控制 PC 扬声器发声及对外部事件计数。

---

## 推理与说明

PC/XT 及后续兼容机中，8254 的输入时钟统一为 $f_{CLK} = 1.19318\,\text{MHz}$，三个通道被 BIOS 初始化为不同工作方式以承担不同系统级任务：

| 通道 | 工作方式 | 计数初值 | 核心功能 |
|:---:|:---:|:---:|:---|
| 0 | 方式 3（方波发生器） | $N=0$（即 65536） | 输出频率 $f_0 = \dfrac{1.19318\,\text{MHz}}{65536} \approx 18.2\,\text{Hz}$ 的方波，接至 8259A 的 IR0，每隔约 55 ms 触发一次系统时钟中断（INT 08H），用于维护系统时间、任务调度等。 |
| 1 | 方式 2（速率发生器） | $N=18$ | 输出频率 $f_1 = \dfrac{1.19318\,\text{MHz}}{18} \approx 66.3\,\text{kHz}$（周期约 $15\,\mu\text{s}$）的负脉冲，接至 DMA 控制器，定时触发 DRAM 刷新操作，防止动态存储器数据丢失。 |
| 2 | 方式 3（方波发生器） | 由程序设定 | 输出经门控后驱动 PC 扬声器（Speaker）产生不同音调；也可通过编程改变计数初值和方式，用作通用定时或外部事件计数器。 |

> **关键点**：8254 本身是通用定时器芯片，但在 PC 系统机中其三个通道的功能已被硬件连线固化——通道 0 绑定系统中断、通道 1 绑定内存刷新、通道 2 绑定扬声器，这是 PC 体系结构的标准设计。
