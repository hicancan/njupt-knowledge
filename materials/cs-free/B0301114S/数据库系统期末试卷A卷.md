### SQL 3

**题目：** 查询每位读者的在借图书数，低于 10 本的不予输出；结果按在借图书数降序排列。

**参考解答：**
```sql
SELECT 读者.读者号, 读者.姓名, COUNT(*) AS 在借数量
FROM 读者, 读者借阅
WHERE 读者.读者号 = 读者借阅.读者号
  AND 读者借阅.还期 IS NULL
GROUP BY 读者.读者号, 读者.姓名
HAVING COUNT(*) >= 10
ORDER BY 在借数量 DESC;
```

### 综合题 1

**题目：** 设有关系模式 $R(A, B, C, D, E, F, G, H)$，其基本函数依赖集为 $F = \{A \to B, B \to C, C \to EF, G \to H\}$ （注：原文 $C-EF$ 理解为 $C \to E, C \to F$ 或 $C \to EF$，通常指 $C \to E, C \to F$）。试：

1. 找出关系模式 $R$ 的候选键；
2. 判断关系模式 $R$ 最高已达到第几范式，并说明理由；
3. 如果 $R$ 不属于 3NF，请将 $R$ 无损且保持依赖地分解为符合 3NF 的模式集。

**参考解答：**

**(1) 找出候选键**
*   分析属性闭包：
    *   $A^+ = ABCDEF$ (因为 $A \to B, B \to C, C \to E, C \to F$)
    *   $G^+ = GH$ (因为 $G \to H$)
    *   $D$ 未出现在任何依赖的右边，也不在左边，必须包含在候选键中。
    *   $(ADG)^+ = ADEFGH + B + C + E + F = ABCDEFGH$ (全集)
*   检查最小性：
    *   去掉 $A$：$(DG)^+ = DEFGH$ (缺少 A,B,C,E,F? 不对，E,F 来自 C，C 来自 B，B 来自 A。若没有 A，无法推出 B,C,E,F)。
    *   去掉 $D$：$(AG)^+ = ABCEF GH$ (缺少 D)。
    *   去掉 $G$：$(AD)^+ = ABCDEF$ (缺少 G,H)。
*   **结论：** 候选键为 **$ADG$**。

**(2) 判断范式**
*   **1NF：** 所有属性均为原子值，满足。
*   **2NF：** 检查是否存在非主属性对候选键的部分函数依赖。
    *   候选键 $ADG$。
    *   存在依赖 $A \to B$。$A$ 是候选键 $ADG$ 的真子集。
    *   $B$ 是非主属性（不在 $ADG$ 中）。
    *   因此，存在非主属性 $B$ 对候选键 $ADG$ 的部分函数依赖 ($ADG \to B$ 可由 $A \to B$ 传递得到)。
*   **结论：** 不满足 2NF，最高达到 **1NF**。
*   **理由：** 存在非主属性 $B$ 部分依赖于候选键 $ADG$（依赖于 $A$）。

**(3) 分解为 3NF**
*   消除部分依赖和传递依赖。
*   分解步骤：
    1.  处理 $A \to B$：生成 $R_1(A, B)$。
    2.  处理 $B \to C$：生成 $R_2(B, C)$。
    3.  处理 $C \to E, C \to F$：生成 $R_3(C, E, F)$。
    4.  处理 $G \to H$：生成 $R_4(G, H)$。
    5.  保留原关系中未被覆盖的属性 $D$ 以及作为外键关联的属性。
    *   由于 $A$ 是 $R_1$ 的主键，$B$ 是 $R_2$ 的主键，$C$ 是 $R_3$ 的主键，$G$ 是 $R_4$ 的主键。
    *   原候选键 $ADG$ 需要被保留或组合。
    *   标准 3NF 合成算法（保持依赖）：
        *   $R_1(A, B)$
        *   $R_2(B, C)$
        *   $R_3(C, E, F)$
        *   $R_4(G, H)$
        *   $R_5(A, D, G)$ (用于连接各表，保证无损连接，因为 $D$ 只属于此，$A,G$ 是其他表的外键来源)
*   **最终分解方案：**
    *   $R_1(A, B)$
    *   $R_2(B, C)$
    *   $R_3(C, E, F)$
    *   $R_4(G, H)$
    *   $R_5(A, D, G)$
    *(注：若允许丢失部分连接性或采用不同分解策略，也可合并为 $\{AB, BC, CEF, GH, ADG\}$)*

答案：(原题无明确答案，按逻辑推导)

### 综合题 2

**题目：** 某销售集团公司欲建立一个公司、产品、职工信息管理系统。
*   **业务规则：**
    1.  若干公司，每个公司销售多种产品。
    2.  每一种产品可以由多个公司销售。
    3.  每个公司按照预定的计划量销售产品。
    4.  每种产品固定存放在一个仓库。
    5.  每个仓库专门存放一种产品。
    6.  产品存于仓库都有一个库存量。
    7.  每个公司聘用多名职工，且每名职工只能在一个公司工作。
    8.  公司聘用职工有聘期和工资。
*   **属性：**
    *   公司有：公司编号、公司名、地址。
    *   产品有：产品编号、产品名、规格、单价。
    *   仓库有：仓库编号、仓库名、地点。
    *   职工有：职工编号、姓名、性别、出生日期。
    *   *(补充属性推断)*：销售关系需含“计划量”；聘用关系需含“聘期”、“工资”。

**要求：** 请设计该系统的概念模型（ER 图）及逻辑结构（关系模式）。

**参考解答：**

**1. 实体与联系分析**
*   **实体：** 公司、产品、仓库、职工。
*   **联系：**
    *   **销售** (公司 - 产品)：M:N 联系。属性：计划量。
    *   **存放** (产品 - 仓库)：N:1 联系（每种产品固定存放在一个仓库，每个仓库专门存放一种产品 -> 实际上是 1:1 或 N:1，题目说“每种产品固定存放在一个仓库”，“每个仓库专门存放一种产品”，这暗示 1:1 关系，但通常仓库可能存多种产品，这里严格按题意：产品到仓库是 N:1，仓库到产品是 1:1）。
        *   *修正理解*：题目说“每个仓库专门存放一种产品”，意味着仓库和产品是一一对应？还是仓库可以放多种？“每个仓库专门存放一种产品”通常指仓库的功能单一。结合“每种产品固定存放在一个仓库”，这是典型的 N:1 (产品->仓库) 或 1:1。若严格对应，可视为 1:1。但在数据库设计中，通常仓库是独立实体。
        *   假设：产品与仓库是 1:1 或 N:1。若“每个仓库专门存放一种产品”，则仓库不能存其他产品。
    *   **聘用** (公司 - 职工)：1:N 联系（公司聘用多名职工，职工只能在一个公司）。属性：聘期、工资。

**2. 关系模式设计**
*   **公司** (<u>公司编号</u>, 公司名，地址)
*   **产品** (<u>产品编号</u>, 产品名，规格，单价，<u>仓库编号</u>)
    *   *注*：若产品与仓库是 1:1，可将仓库编号放入产品表，或单独建仓库表。根据“每个仓库专门存放一种产品”，建议将仓库编号作为产品表的外键，或者如果仓库有其他属性（如地点），则产品表含仓库编号。
    *   若仓库有独立属性（地点），则：
        *   **仓库** (<u>仓库编号</u>, 仓库名，地点)
        *   **产品** (<u>产品编号</u>, ..., <u>仓库编号</u>) -> 约束：仓库编号唯一。
*   **仓库** (<u>仓库编号</u>, 仓库名，地点)
*   **职工** (<u>职工编号</u>, 姓名，性别，出生日期，<u>公司编号</u>)
*   **销售** (<u>公司编号，产品编号</u>, 计划量)

**3. 完整性约束**
*   销售表中的公司编号、产品编号分别引用公司和产品表。
*   职工表中的公司编号引用公司表。
*   产品表中的仓库编号引用仓库表。
