# 《面向对象程序设计及C++》期末总复习（2017 年学生版）

原件为八章复习提纲。下面保留原题用到的条件、常量与调用顺序，其余用独立的解释串联。**参考解答**是补做的；讲义用旧式头文件或简略类声明的地方，按标准 C++ 区分语法错误和题目真正想验证的行为。

## 第一章：为什么让状态和操作属于同一个对象

复习的三个支点是**封装、继承、多态**。封装把状态改变集中到能维持不变量的接口；继承能表达可替代关系，但复用代码不自动意味着可以替代；多态则允许调用者通过共同接口请求行为，由对象确定实现。工具链上，课件以 <kbd>.cpp → .obj → .exe</kbd> 举例，分别对应源文件、目标文件和链接结果。**补充：**具体后缀随平台变化；托管环境的程序入口是 <kbd>main</kbd>，但某些静态对象的初始化可能先于进入 <kbd>main</kbd>。

## 第二章：先看作用域和类型，再追赋值

<kbd>std::cin &gt;&gt;</kbd> 执行格式化提取，读字符串通常在空白处停；<kbd>std::cout &lt;&lt;</kbd> 按类型格式化输出，普通输出不自动换行。局部名称隐藏同名全局名称时，可用 <kbd>::name</kbd> 找全局对象。动态分配中，单对象与数组分别用 <kbd>delete</kbd> 和 <kbd>delete[]</kbd> 匹配；补充做法是让对象通过 RAII 管理生命周期，尤其要考虑异常使控制流提前退出。默认参数是调用缺少实参时的补全规则，不是新的重载签名；<kbd>inline</kbd> 并不强制编译器展开函数。<kbd>try</kbd> 界定受保护代码，<kbd>throw</kbd> 抛出异常，<kbd>catch</kbd> 处理匹配的类型。

| 指针声明的形状 | 可以改指针指向？ | 可以经此指针改字符？ |
| --- | --- | --- |
| <kbd>const char* p</kbd> | 可以 | 不可以 |
| <kbd>char* const p</kbd> | 不可以 | 指向可写字符时可以 |
| <kbd>const char* const p</kbd> | 不可以 | 不可以 |

**订正：**第二种不能用字符串字面量初始化，这是原件排版之外的类型问题；考察“常指针”时可先定义可写字符数组 <kbd>char a[] = "chen";</kbd>，再写 <kbd>char* const p = a;</kbd>。

**原题：重载选择。参考解答：B。** 两个 <kbd>disp(Myclass)</kbd> 的参数列表相同，不能仅靠返回类型是 <kbd>int</kbd> 还是 <kbd>char*</kbd> 来重载；其余各组分别改变参数类型或个数，即使其中一组也改变返回类型，仍不是错误的原因。

**原题：引用与指针交换。参考解答：输出 <kbd>1000 1000</kbd>。** 入参使 <kbd>a</kbd> 指向 <kbd>x=500</kbd>，<kbd>b</kbd> 引用 <kbd>y=1000</kbd>。局部指针 <kbd>t=a</kbd> 只是另一个别名；写 <kbd>*a=b</kbd> 后，<kbd>x</kbd> 成了 1000，随后 <kbd>b=*t</kbd> 读到的是刚改过的 <kbd>x</kbd>，所以 <kbd>y</kbd> 仍是 1000。**订正：**按标准头与 <kbd>int main()</kbd> 整理旧例而不改核心操作；若真要交换，要先存值而非地址，例如保存 <kbd>int old = *a</kbd>。

> [!TIP]
> ==赋值以前先画出谁给谁取别名。== 两个指针指同一个对象，改对象后从任一路读都会看到新值。要记住过去的值，必须复制值或使用系统提供的交换操作。

## 第三、四章：对象何时诞生，数据究竟属于谁

类常用三个访问级别：<kbd>public</kbd>、<kbd>protected</kbd>、<kbd>private</kbd>。构造函数负责建立对象可用的不变量，析构函数收尾；非静态成员函数中 <kbd>this</kbd> 指向当前对象。传值取得单独的形参对象，指针和引用可以观察同一对象，但指针可能为空且可改指向。对象数组会构造各元素，未逐个指定的元素要满足相应初始化条件；友元函数、友元成员或友元类具有被授予的访问权限，权限不是凭函数名称或所属继承关系自动得到。

**原题：构造顺序。参考解答：**以下按 A 的完整类定义已给出、相应操作可用来判断；原件的 <kbd>class A;</kbd> 单独出现只是前向声明，不够直接构造对象。默认构造是“可以无实参调用”，不意味着每个类必定隐式生成可用版本。

| 原题语句形式 | 判断 |
| --- | --- |
| <kbd>A a;</kbd>、<kbd>A* p = new A;</kbd> | 以无实参形式构造 A；后一条分配动态对象并构造该对象 |
| <kbd>A a, b=a;</kbd>、<kbd>A a, b(a);</kbd> | 先默认构造 a，b 还未存在，因此从 a 拷贝构造 b |
| <kbd>A a,b; b=a;</kbd> | a、b 已分别默认构造，后一条调用拷贝赋值，不再构造 b |
| <kbd>void fun(A x); A a; fun(a);</kbd> | a 是左值，按值形参 x 从它拷贝构造；不应把这个结论扩展成所有返回对象总有一次拷贝 |

静态数据成员属于类，不随每个对象复制一份；普通数据成员各对象各自保存。思考“某对象析构后，别的对象是否还能读这份状态”，能分辨生命周期和共享范围。对象持有的资源与拷贝方式相关：若只复制原始指针，两个对象可能共同指向同一存储，不能凭“调用了拷贝构造”推断资源已经独立。

## 第五章：基类子对象仍在，但名字未必能直接用

组合是“拥有成员对象”，继承产生“基类子对象”。构造最派生对象时，先按语言规定的次序构造虚基类（共享的虚基只建一次），再按基类声明顺序构造直接非虚基类，随后按**成员声明顺序**构造对象成员，最后执行派生类构造函数体；析构总体反向。初始化列表中交换成员条目的书写顺序，不会改变这个次序。

```mermaid
flowchart LR
  V["最派生类负责初始化虚基"] --> B["直接非虚基：按声明顺序"]
  B --> M["成员对象：按声明顺序"]
  M --> S["执行派生类构造函数体"]
  S --> D["析构总体反向"]
```

**订正：**原件说“基类 private 成员不能被继承”，答题应区分“子对象确实包含这部分状态”和“派生类成员函数不能直接访问它”。公有、无歧义的基类转换可以让派生对象绑定到基类引用，或让派生指针转换成基类指针，对象仍然存在；若把派生对象按值赋给一个基类对象，只写基类部分，会切掉派生状态。虚基能让菱形两条路径共享一个公共基类，但不能凭空合并两个独立基类中的同名成员；可以显式写限定名说明选哪一边。

**原题：多重继承输出。参考解答：**<kbd>C c1(400,500,600)</kbd> 初始化 A 部分的 <kbd>x=401</kbd>、B 部分的 <kbd>y=499</kbd>、C 自己的 <kbd>y=600</kbd>。随后 <kbd>c1.y=200</kbd> 改的是 C 的 y，B 的 y 不变。依次调用 C、A、B 的 <kbd>Show</kbd>，输出为：

```text
C: y=200
A: x=401
B: y=499
```

> [!WARNING]
> ==同名不等于同一个成员，隐藏也不等于虚函数覆盖。== 原题三个 <kbd>Show</kbd> 无须靠虚派发；加 <kbd>A::</kbd> 或 <kbd>B::</kbd> 明确选各自实现。真正的运行时覆盖还要检查基类函数是否为虚函数以及签名是否匹配。

## 第六章：什么时候由编译器定下来，什么时候等到运行时

重载按静态可见的类型和候选函数选择；经基类引用或指针调用虚函数，才可能按对象实际类型分派。纯虚函数用 <kbd>=0</kbd> 声明；若类仍有未实现的纯虚函数，不能直接实例化。**补充：**要通过基类指针销毁派生对象，通常要给基类虚析构函数。

| 运算符用法 | 成员函数形式 | 非成员函数形式，可选择声明为友元 |
| --- | --- | --- |
| 二元加法 | 一个显式参数，左操作数由 <kbd>*this</kbd> 提供 | 两个显式参数 |
| 一元负号 | 无显式参数 | 一个显式参数 |
| 前缀自增 | 无显式参数；常按惯例返回修改后的对象引用 | 一个对象参数 |
| 后缀自增 | 多一个作为区分的 <kbd>int</kbd> 参数；常返回旧值副本 | 在对象参数后再加 <kbd>int</kbd> |
| 流输出／输入 | 通常不写成用户类型的成员，因为左操作数是流 | 输出 <kbd>operator&lt;&lt;</kbd> 取常对象引用，输入 <kbd>operator&gt;&gt;</kbd> 取可改对象引用，均返回流引用以支持串接 |

讲义点名不能重载的 <kbd>.</kbd>、<kbd>.*</kbd>、<kbd>::</kbd>、<kbd>sizeof</kbd>、<kbd>?:</kbd>；重载也不改变既有运算符的优先级或操作数个数。**订正：**原件把输出运算符一处标成 <kbd>&gt;&gt;</kbd>，应为 <kbd>&lt;&lt;</kbd>。非成员没有访问私有状态的需要时，不一定要声明为友元。

## 第七、八章：让类型可变，让读写协议稳定

函数模板描述一族函数，普通调用的实参可用于推导模板参数；类模板描述一族类型，如 <kbd>Box&lt;int&gt;</kbd> 和 <kbd>Box&lt;double&gt;</kbd> 是不同类型。以“按值返回较大值”为例，<kbd>larger(2,5)</kbd> 可以推导同一种参数类型，<kbd>larger(2,5.0)</kbd> 对仅有一个类型参数的签名可能推导冲突，需明确转换或改变接口。类型被选定不代表操作可用，该类型还要支持实现中的比较。

流插入、提取运算符形成可连用的格式化接口。原件最后的 <kbd>get()</kbd>、<kbd>put()</kbd> 用于文件逐字符读写；例如以字符引用接收时，<kbd>while (in.get(ch)) out.put(ch);</kbd> 会处理空白并在读取失败时停止，不能用 <kbd>while (!in.eof())</kbd> 先猜下一次读取是否成功。是否逐字节原样复制还取决于文件的打开模式，不能拿格式化提取替换它。
