### 选择 2

假设进程用户的 umask 是 054，该用户创建的文件的默认权限是（）。

- A. 723
- B. 722
- C. 622
- D. 623

参考解答：**答案：D. 623**

**解析：**  
Linux 中新建文件的默认权限为 `666`（即所有用户可读写，无执行权限），`umask` 用于屏蔽相应权限位。计算方式为：


$$
\text{实际权限} = \text{默认权限} \ \&\ \sim\text{umask}
$$


即：


$$
666 \ \&\ \sim054 = 666 \ \&\ 723 = 622
$$


但注意：**`umask` 中的执行位（如 `054` 中的 `4`）对文件默认权限无影响**，因为文件默认无执行权限，屏蔽写权限即可。

逐项分析 `umask = 054`：
- `0`：用户（owner）不屏蔽任何权限 → 保留 `rw-`（6）
- `5`：组（group）屏蔽 `r-x`（4+1），但文件默认无执行权限，实际屏蔽 `r--`（4）→ 剩余 `-w-`（2）
- `4`：其他（others）屏蔽 `r--`（4）→ 剩余 `-w-`（2）

因此，最终权限为 `rw--w--w-`，即 **622**。

**选项分析：**
- **A. 723**：错误，包含执行权限，文件默认不会创建执行权限。
- **B. 722**：错误，组权限 `2` 正确，但用户权限 `7` 错误（不应有执行权限）。
- **C. 622**：**正确**，符合计算结果。
- **D. 623**：错误，其他用户权限 `3` 包含执行权限，不可能出现。

> 注：题目选项中 **C. 622** 为正确答案，原题目标注“选择 2”可能为笔误或选项顺序错乱。

知识点：[文件访问权限与umask掩码](../../../topics/Linux系统编程/文件访问权限.md)

### 选择 8

下列哪种不是 Linux 的用户类型？（）

- A. 超级用户
- B. 虚拟用户
- C. 实体用户
- D. 普通用户

参考解答：**结论**：B

**推理过程**：
Linux 系统中的用户通常分为以下三类：
1.  **超级用户（Root）**：UID 为 $0$，拥有系统最高权限。对应选项 A。
2.  **普通用户（Regular User）**：由管理员创建，用于日常操作，权限受限。对应选项 D。
3.  **系统用户/伪用户（System/Pseudo User）**：UID 通常在 $1 \sim 999$ 之间，用于运行后台服务或守护进程（如 `bin`, `daemon`, `www-data`），不能登录 shell。

**选项分析**：
*   **A、D**：属于 Linux 标准的用户分类。
*   **C**：“实体用户”并非 Linux 标准术语，但在部分中文教材语境中，常用来指代“可以登录系统进行交互的真实人类用户”（即区别于系统账号的普通用户或管理员），在此语境下可被视为对“非系统账号”的一种描述。
*   **B**：“虚拟用户”通常是 FTP 服务器（如 vsftpd）或特定应用层面的概念，指映射到某个系统真实用户上的逻辑用户，**不是** Linux 操作系统内核层面的原生用户类型分类。因此 B 是最不符合 Linux 系统底层用户分类定义的选项。

知识点：[Linux操作系统的特点与体系结构](../../../topics/Linux系统编程/Linux系统特点.md)

### 选择 13

下面（）写法表示如果 cmd1 不成功执行，则执行 cmd2 命令。

- A. cmd1 && cmd2
- B. cmd1 | cmd2
- C. cmd1;cmd2
- D. cmd1 || cmd2

参考解答：**答案：D**

**解析：**

- **D. `cmd1 || cmd2`**：逻辑或，仅当 `cmd1` 执行失败（退出状态非 0）时才执行 `cmd2`，符合题意。
- A. `cmd1 && cmd2`：`cmd1` **成功**时才执行 `cmd2`，与题意相反。
- B. `cmd1 | cmd2`：管道，将 `cmd1` 的**输出**作为 `cmd2` 的输入，与执行成功与否无关。
- C. `cmd1;cmd2`：顺序执行，无论 `cmd1` 成败都会执行 `cmd2`。

命令 `ln -s test king` 完成（）。

- A. 创建一个从 test 到 king 的符号链接
- B. 创建一个从 king 到 test 的硬链接
- C. 创建一个从 king 到 test 的符号链接

- `test` 是**源文件**（被指向的文件）
- `king` 是**链接文件**（新创建的符号链接）

### 简答 1

请简述静态库、共享库、动态链接库的概念，并简述他们各自的优缺点。

参考解答：## 结论

**静态库**（Static Library）是在链接阶段被完整复制进可执行文件的库；**共享库**（Shared Library）是在程序运行时被加载进内存、供多个进程共享的库；**动态链接库**（Dynamic Link Library, DLL）是共享库在 Windows 平台上的具体实现形式，本质上属于共享库的范畴。

---

## 概念与优缺点

### 1. 静态库

**概念**：静态库（如 Linux 下的 `.a` 文件）由一组目标文件（`.o`）打包而成。在链接阶段，链接器将程序引用的库代码**完整复制**到最终的可执行文件中。

**优点**：
- **部署简单**：可执行文件自包含，无需依赖外部环境，拷贝即可运行。
- **运行速度快**：代码已嵌入可执行文件，运行时无需额外加载和解析，无动态链接开销。

**缺点**：
- **浪费空间**：多个程序使用同一库时，每个可执行文件都包含一份副本，造成磁盘和内存的冗余。
- **更新困难**：库代码被静态嵌入，库升级后必须**重新编译链接**所有依赖它的程序。

---

### 2. 共享库

**概念**：共享库（如 Linux 下的 `.so` 文件）在链接阶段仅记录所需的符号信息，程序运行时由动态链接器（如 `ld-linux.so`）将其加载到内存，**多个进程可以共享同一份库代码**。

**优点**：
- **节省资源**：多个进程共享内存中同一份库代码，减少内存占用和磁盘冗余。
- **易于更新**：库升级只需替换 `.so` 文件，无需重新编译依赖程序（前提是接口保持兼容）。

**缺点**：
- **部署复杂**：目标系统必须安装对应版本的共享库，否则会出现"依赖缺失"错误。
- **运行时开销**：程序启动时需进行动态链接和符号解析，带来一定的性能损耗。

---

### 3. 动态链接库（DLL）

**概念**：动态链接库是共享库在 Windows 平台上的称谓（如 `.dll` 文件），本质上与共享库是同一类事物，均实现运行时的动态加载与代码共享。在 Linux/Unix 世界通常称"共享库"，在 Windows 世界则称"动态链接库"。

**优点**：
- 与共享库相同：节省内存、便于模块化开发和更新。

**缺点**：
- 与共享库相同：存在依赖管理问题（如 Windows 上常见的"DLL Hell"——不同程序所需 DLL 版本冲突）。

知识点：[GCC编译器的使用与编译过程（预处理、编译、汇编、链接）](../../../topics/Linux系统编程/GCC编译器.md)

在某一目录下通过 `ls -al` 打印出如下结果，请解释所有的输出分别是什么意思？

drwxr-xr-x 30 ubuntu ubuntu 4096 12月 4 19:39 ..

- `d`：目录（`.`、`..`）
- `-`：普通文件（`king.sh`）
- `p`：命名管道/FIFO（`stone`）

**权限（每行第 1 字段第 2–10 位，按 user/group/other 各 3 位）**
- `rwx`：读、写、执行
- `r-x`：读、执行（无写）
- `rw-`：读、写（无执行）
- 最后一位的 `x` 对目录表示“可进入并列出内容”，对普通文件表示“可执行”；无权限用 `-` 表示。

- `.`：`rwxrwxr-x` → user `rwx`、group `rwx`、other `r-x`
- `..`：`rwxr-xr-x` → user `rwx`、group `r-x`、other `r-x`

- `27`（`.`）：该目录的硬链接数，等于其子目录数 + 2（`.`、来自父目录的链接）
- `30`（`..`）：父目录的硬链接数，同理 = 父目录的子目录数 + 2
- `1`（`king.sh`、`stone`）：没有其他硬链接指向它们

**属主 / 属组（第 3、4 字段）**
- 都是 `ubuntu`：文件所有者和所属组均为用户 `ubuntu`，`ls` 默认按登录名/组名显示（可用 `ls -aln` 看数字 UID/GID）

**大小（第 5 字段，字节）**
- `4096`（`.`、`..`）：目录项占用的目录文件大小（一个文件系统块）
- `0`（`king.sh`）：空文件，内容为空
- `0`（`stone`）：FIFO 在文件系统中不保存数据，故大小为 $0$，数据通过管道传递

**修改时间（第 6 字段）**
- `12月 4 19:39`：最后修改时间 mtime，四项都是 12 月 4 日 19:39，说明这些条目在同一时间创建/修改（`ls` 默认对 6 个月内文件显示 `月 日 时:分`，更久的显示 `月 日 年`，可用 `--time-style` 改变）

**文件名（第 7 字段）**
- `.`：当前目录自身
- `..`：父目录
- `king.sh`：普通空文件
- `stone`：命名管道

**第一列长度说明**
- `drwxrwxr-x` 共 10 字符（类型 + 9 位权限）；Linux 若设置特殊位，最后一位可能为 `s`/`t`/`S`/`T`（SUID/SGID/Sticky），本例均为普通权限，所以以 `x` 或 `-` 结束。
- FIFO 在 GNU `ls` 中以 `p` 开头；SUID/SGID/Sticky 只影响执行位的显示符号（如 `rwsr-xr-x`），不影响其他位的解释。

### 设计 1

编写 shell 脚本，提示用户输入起始数字 A 和终止数字 B。要求：

1. 计算并输出从 A 到 B 所有数的乘积；
2. 在用户输入完 A 和 B 两个值后，通过调用函数 `check()` 判断 A、B 哪个值比较大；
3. 在主程序中，如果 A>B 则计算 A 的阶乘，否则输出 B 的阶乘。

参考解答：**结论**

```bash
#!/bin/bash

# 定义 check 函数，判断 A 和 B 的大小关系
check() {
    if [ "$1" -gt "$2" ]; then
        echo "A ($1) 比较大"
    elif [ "$1" -lt "$2" ]; then
        echo "B ($2) 比较大"
    else
        echo "A 和 B 相等"
    fi
}

# 提示用户输入
read -p "请输入起始数字 A: " A
read -p "请输入终止数字 B: " B

# 调用 check 函数判断大小
check "$A" "$B"

# 1. 计算并输出从 A 到 B 所有数的乘积
product=1
if [ "$A" -le "$B" ]; then
    for (( i=A; i<=B; i++ )); do
        product=$((product * i))
    done
else
    for (( i=A; i>=B; i-- )); do
        product=$((product * i))
    done
fi
echo "从 $A 到 $B 所有数的乘积为: $product"

# 3. 主程序中根据 A、B 大小计算阶乘
if [ "$A" -gt "$B" ]; then
    # A > B，计算 A 的阶乘
    fact=1
    for (( i=1; i<=A; i++ )); do
        fact=$((fact * i))
    done
    echo "A($A) 的阶乘为: $fact"
else
    # A <= B，计算 B 的阶乘
    fact=1
    for (( i=1; i<=B; i++ )); do
        fact=$((fact * i))
    done
    echo "B($B) 的阶乘为: $fact"
fi
```

---

**推理与关键步骤**

1. **`check()` 函数设计**：接收两个位置参数 `$1`（即 A）和 `$2`（即 B），用 `-gt`（大于）、`-lt`（小于）进行比较并输出结果。在输入完成后立即调用 `check "$A" "$B"`。

2. **区间乘积计算**：
   - 需考虑 $A \le B$ 和 $A > B$ 两种方向，分别使用递增和递减的 `for` 循环。
   - 累乘公式：$\text{product} = \prod_{i=\min(A,B)}^{\max(A,B)} i$
   - 关键语句：`product=$((product * i))`，利用 `$(( ))` 进行算术运算。

3. **阶乘计算**：
   - 条件分支：`if [ "$A" -gt "$B" ]` 成立则算 $A!$，否则算 $B!$。
   - 阶乘公式：$n! = \prod_{i=1}^{n} i$
   - 通过 `for (( i=1; i<=N; i++ ))` 循环累乘实现，关键语句：`fact=$((fact * i))`。

在 Linux 环境下，分别用 shell 脚本和 C 语言将斐波那契数列的前 20 个数写入 fib.txt 文件中。同时，分别写出两种程序编写完成后付诸运行所需的所有命令。斐波那契数列是指除第一个数和第二个数之外所有数均是前两个数之和，如 1, 1, 2, 3, 5……

参考解答：### 1. Shell 脚本实现

**程序代码 (fib.sh)**

```bash
#!/bin/bash

# 初始化前两个数
a=1
b=1

# 清空文件（若存在）或创建文件
> fib.txt

# 循环 20 次，计算并写入前 20 个数
for ((i=1; i<=20; i++))
do
    # 将当前数追加写入文件，以空格分隔
    echo -n "$a " >> fib.txt
    
    # 计算下一个数：利用临时变量或算术运算交换
    # 逻辑：next = a + b; a = b; b = next
    next=$((a + b))
    a=$b
    b=$next
done

# 写入一个换行符，美化文件格式
echo "" >> fib.txt
```

**运行所需命令**

1.  **赋予执行权限**（使脚本可执行）：
    ```bash
    chmod +x fib.sh
    ```
2.  **执行脚本**：
    ```bash
    ./fib.sh
    ```
    *(或者使用 `bash fib.sh` 运行，无需赋予执行权限)*

---

### 2. C 语言实现

**程序代码 (fib.c)**

```c
#include <stdio.h>

int main() {
    // 使用 long long 防止数据溢出（第20个数为6765，int亦可，但long long更稳妥）
    long long fib[20];
    FILE *fp;
    int i;

    // 初始化斐波那契数列前两项
    fib[0] = 1;
    fib[1] = 1;

    // 递推计算后续 18 项
    for (i = 2; i < 20; i++) {
        fib[i] = fib[i-1] + fib[i-2];
    }

    // 打开文件用于写入 ("w" 模式会覆盖旧内容)
    fp = fopen("fib.txt", "w");
    if (fp == NULL) {
        printf("文件打开失败！\n");
        return 1;
    }

    // 将数组内容写入文件
    for (i = 0; i < 20; i++) {
        fprintf(fp, "%lld ", fib[i]);
    }
    fprintf(fp, "\n"); // 末尾换行

    // 关闭文件
    fclose(fp);
    
    printf("斐波那契数列前20项已写入 fib.txt\n");

    return 0;
}
```

**运行所需命令**

1.  **编译源代码**（生成名为 `fib` 的可执行文件）：
    ```bash
    gcc fib.c -o fib
    ```
2.  **运行可执行程序**：
    ```bash
    ./fib
    ```

### 3. 结果验证

两种方法运行后，均可通过以下命令查看文件内容：

```bash
cat fib.txt
```
