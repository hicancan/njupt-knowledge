# isTmin：为什么把一个位型加两次会得到零

原件是实验提示，只指向一条[位运算讨论](https://stackoverflow.com/questions/15962682/bitwise-checking-if-a-number-is-1-or-not/78260004#78260004)，没有列题面、运算符限制或操作数预算。以下以独立的 32 位补码位型为例，解释怎样区分最小补码整数与零。具体实验提交仍须用本班给出的题面和检查器。

## 先问什么时候只有最高位亮着

**补充（自编）**：把 32 位补码的最小整数位型输入一个函数。要求对这个位型返回真，对包括零在内的其余位型返回假。不把所求位型直接写成常量，怎样借模运算来判定？

**参考解答**：先把同一组比特解释为[无符号整数](../../../topics/计算机系统基础/无符号整数编码.md) $u$，只保留和的低 32 位。若两倍为零，则有
$$
2u\equiv 0\pmod{2^{32}}
\quad\Longleftrightarrow\quad
2^{31}\ \text{整除}\ u.
$$
在 $0\le u<2^{32}$ 的范围里只有两个解：$0$ 与 $2^{31}$。排除 $0$，剩下的位型只设了最高位。按[补码编码](../../../topics/计算机系统基础/补码编码.md)，这个最高位权重是 $-2^{31}$，因此就是最小值。

| 无符号位型 | 两倍只保留低 32 位 | 判定 |
| --- | --- | --- |
| `0x00000000` | `0x00000000` | 假；零也是加倍为零的解 |
| `0x80000000` | `0x00000000` | 真 |
| `0x80000001` | `0x00000002` | 假 |
| `0xffffffff` | `0xfffffffe` | 假；它的补码数值是 $-1$，不是最小值 |

## 把“只看低位”写进 C 的类型里

下面的参考实现先在明确够宽的无符号类型里相加，再转换回 32 位。由于原件未给操作符限制，它不是对某个 Data Lab 评分器的通过承诺。

```c
#include <stdint.h>

int is_tmin_bits(uint32_t u)
{
    uint32_t doubled = (uint32_t)((uint64_t)u + (uint64_t)u);
    return u != 0 && doubled == 0;
}
```

> [!WARNING]
> 硬件保留低位不等于 C 允许有符号结果溢出。若在有符号 `int32_t` 中直接写最小值的两倍或相反数，常见 32 位 `int` 平台发生有符号溢出，C 不保证回绕。先在上述无符号模型里固定宽度，再谈位模式；不能用某次偶然跑出来的结果替代语言规则。

想检查推导有没有漏掉上界，可先在 3 位世界里列出八个数：只有 `000` 与 `100` 加倍后低三位是零。改变位宽只改变模数，不改变“加倍后在模环里归零，再排除零”这个条件。课程中的操作约束另见具体[位级实验说明](../../../topics/计算机系统基础/DataLab位级运算.md)。
