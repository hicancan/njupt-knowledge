## 推理与计算过程

### (1) 相关类型分析

- **数据相关**：后续指令的操作数依赖于前面指令的运算结果或加载数据（如 RAW 写后读相关）。
- **控制相关**：由分支/跳转指令引起，后续指令是否执行取决于分支条件的判定结果。
- **为什么是数据相关**：控制相关可通过分支预测或延迟槽处理，而题目所指的具体指令间依赖本质上是前一条指令的结果被后一条指令使用，属于数据相关。

### (2) 需要 2 个 nop 的原因

**关键步骤**：在经典的 5 级流水线（IF、ID、EX、MEM、WB）中，若 **无数据旁路**，且存在 **Load-Use 冒险**（即 `lw` 后立即使用其结果）：

- `lw` 在 MEM 阶段末尾才产生数据；
- 下一条指令在 EX 阶段就需要该数据；
- 两者之间相差 2 个周期，因此必须插入 **2 个 `nop`**（气泡）来等待数据就绪。

$$t_{\text{可用}} = \text{MEM 末} ,\quad t_{\text{需要}} = \text{EX 初} \implies \Delta = 2 \text{ cycles} \implies 2 \text{ nops}$$

### (3) 需要 1 个 nop 及解决方法

**关键步骤**：若流水线已实现 **数据旁路（Forwarding）**，对于 Load-Use 冒险：

- 旁路可将 MEM 阶段产生的数据直接送到下一周期的 EX 输入端；
- 但仍存在 **1 个周期** 的间隔无法通过旁路消除（数据在 MEM 结束时才从存储器读出，而紧接的下一条指令在同一周期已进入 EX）；
- 因此只需插入 **1 个 `nop`**。

$$\text{有 Forwarding 时：} \Delta = 2 - 1 = 1 \text{ cycle} \implies 1 \text{ nop}$$

> **注**：题面中"避免使用/加载技术"疑为"**数据旁路/转发（Forwarding）**"技术的笔误。Forwarding 正是将 Load 的数据直接旁路给后续 ALU 使用，从而将 2 个 nop 减少到 1 个。另一种软件层面的方法是编译器进行 **指令调度（Instruction Scheduling）**，在不相关的指令间插入其他无关指令来填充延迟槽，避免显式 `nop`。

### 分析 3

（5 分）

(1) `printf` -> 调用 C 语言 I/O 标准函数 -> 系统调用封装函数 `write()` -> `system_call` 从用户态陷入内核态 -> 从 `.system_call` 中找到相应 `system_write()` 函数进行处理 -> 文件系统 -> 显卡驱动 -> 在显示屏中显示

参考解答：**结论：**

`printf` 输出字符串到屏幕的完整过程可概括为：

`printf` → C 标准 I/O 库处理与缓冲 → `write()` 封装函数 → 执行 `int $0x80` 触发系统调用 → `system_call` 入口 → 根据系统调用号调用 `sys_write` → 文件系统及字符设备驱动 → 控制台/显卡驱动 → 屏幕显示。

**简要过程：**

1. **用户态库函数处理**  
   `printf` 是 C 标准 I/O 库函数，先按格式串生成待输出内容，并写入 `stdout` 的用户态缓冲区；满足换行、缓冲区满或刷新等条件后，才通过 `write()` 请求内核输出。

2. **陷入内核态**  
   `write()` 是系统调用的用户态封装函数，将文件描述符、缓冲区地址和字节数等参数放入约定寄存器，并设置系统调用号，再执行 `int $0x80`，CPU 由用户态切换到内核态。

3. **系统调用分派**  
   内核从 `system_call` 入口开始执行，保存现场，根据系统调用号查 `sys_call_table`，调用对应的 `sys_write()`，而不是“从 `.system_call` 中找到 `system_write()`”。

4. **内核完成输出**  
   `sys_write()` 根据文件描述符找到打开文件及相应设备，经文件系统和字符设备驱动，将数据交给控制台/终端驱动，最终由显示相关驱动把字符送到显存或显示设备，在屏幕上呈现。

5. **返回用户态**  
   `sys_write()` 返回实际写出的字节数或错误码，内核恢复现场并返回用户态，`write()` 将返回值交给 C 库，后续 `printf` 执行流程继续。

**对原表述的修正：**

- 标准 Linux 内核中的名称通常是 `system_call`、`sys_call_table` 和 `sys_write`，不是 `.system_call` 和 `system_write()`。
- `printf` 不一定立即调用 `write()`，因为标准 I/O 库可能先进行用户态缓冲。
- 若只讨论早期 Linux 0.11 等特定实验内核，则应按该内核源码中的实际函数名和调用链作答。

## 三、应用题（50 分）

参考解答：### 分析 4

**(1) 硬布线与微程序控制器对比**

- **原理**：硬布线控制器由组合逻辑电路直接生成控制信号；微程序控制器通过读取控制存储器中的微指令序列产生控制信号。
- **执行速度**：硬布线快（纯硬件延迟）；微程序慢（需访存读取微指令）。
- **灵活性**：硬布线差（修改需重构电路）；微程序好（仅需修改微代码）。

**(2) 指令执行流程分析**

a. **取指阶段**：$\mathrm{PC} \to \mathrm{MAR} \to \text{地址总线}$，读出指令 $\to \mathrm{IR}$，同时 $\mathrm{PC} \leftarrow \mathrm{PC} + 1$。  
b. **译码/微地址形成**：根据 $\mathrm{IR}$ 中操作码字段，经微地址形成逻辑计算下一条微指令地址。  
c. **执行阶段**：ALU 执行 $\mathrm{R1} + \mathrm{R2}$，结果写回 $\mathrm{R2}$（即 $\mathrm{R2} \leftarrow \mathrm{R1} + \mathrm{R2}$）。  
d. **公操作返回**：当前微指令执行完毕后，无条件跳转至公共微程序入口（如取指微指令），为下一条机器指令做准备。

## 推理与计算

虚拟地址为 14 位，因此虚拟地址空间共有：

$$
2^{14}\ \mathrm{B}
$$

按页大小 $2^6=64\ \mathrm{B}$ 分页，共有：

$$
\frac{2^{14}}{2^6}=2^8=256
$$

个虚拟页，故虚拟页号为 $\mathrm{VA}_{13}\sim\mathrm{VA}_6$，页内偏移量为 $\mathrm{VA}_5\sim\mathrm{VA}_0$。

TLB 使用 $\mathrm{VA}_{13}\sim\mathrm{VA}_8$ 作为标记、$\mathrm{VA}_{7}\sim\mathrm{VA}_6$ 作为索引。其中：

$$
(0x0E\gg6)\&0x3FF=0x0E
$$

因此：

$$
\mathrm{VPN}=0x0E
$$

根据题目给出的地址划分，TLB 中该索引对应的标记与当前虚拟地址的标记不匹配，所以 **TLB 不命中**；但页表中已存在该虚拟页，且对应物理页已驻留内存，因此 **不缺页**。

物理地址为 12 位，按 64 字节分页，共有 $2^6=64$ 个物理页，因此物理页号为 $\mathrm{PA}_{11}\sim\mathrm{PA}_6$，页内偏移量为 $\mathrm{PA}_5\sim\mathrm{PA}_0$。

TLB 未命中后，通过页表得到物理地址，并继续访问数据高速缓存。按题目给出的高速缓存地址格式：

- 高速缓存组索引取 $\mathrm{PA}_{11}\sim\mathrm{PA}_7$，故

  
$$
\mathrm{CI}=(0xC2\gg7)\&0x1F=0x7
$$

- 高速缓存标记取其余高位，故

  
$$
\mathrm{CT}=0xC2\gg5=0x23
$$

高速缓存中的对应标记与地址中的标记一致，因此 **高速缓存命中**，返回字节：

$$

    *   块 3 初始为空 $\rightarrow$ **Miss**。
    *   状态：块 3 载入 Tag `0000000`。

2.  **访问 b**: `0000001 00 000`
    *   Index = $00_2 = 0$。
    *   块 0 初始为空 $\rightarrow$ **Miss**。
    *   状态：块 0 载入 Tag `0000001`。

3.  **访问 c**: `0000001 00 010`
    *   Index = $00_2 = 0$。
    *   块 0 已有数据，检查 Tag：当前 Tag `0000001` 与内存 Tag `0000001` 一致 $\rightarrow$ **Hit**。

    *   Index = $10_2 = 2$。
    *   块 2 初始为空 $\rightarrow$ **Miss**。

5.  **访问 e**: `0010000 10 000`
    *   Index = $10_2 = 2$。
    *   块 2 已有数据，检查 Tag：当前 Tag `0001000` $\neq$ 内存 Tag `0010000` $\rightarrow$ **Miss + Eviction**（替换旧数据）。

    *   状态：块 0 更新为 Tag `0000101`。

*   **Misses**: 5 (步骤 a, b, d, e, f)
