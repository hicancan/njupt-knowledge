### 简答 1

简述采用了多道程序设计技术操作系统的特性。

参考答案：
采用了多道程序设计技术的操作系统具有如下特性：
①并发性。它是指两个或两个以上的事件或活动在同一时间间隔内发生。操作系统是一个并发系统，并发性是它的重要特征，操作系统的并发性指计算机系统中同时存在若干个运行着的程序，因此，它应该具有处理和调度多个程序同时执行的能力。
②共享性。共享指计算机系统中的资源可被多个并发执行的用户程序和系统程序共同使用，而不是被其中某一个程序所独占。共享有两种形式：其一是顺序共享。其二是并发共享。
③不确定性。不确定性也称异步性。在多道程序并发执行的环境中，各程序之间存在着直接或间接的联系，程序的推进速度会受到运行环境的影响，若不能正确控制，则执行结果会因为运行环境的不同而不同。
④虚拟性。虚拟性是指操作系统中的一种管理技术，它是把物理上的一个实体变成逻辑上的多个对应物，或把物理上的多个实体变成逻辑上的一个对应物的技术。所谓虚拟是指物理上没有提供，但是逻辑上却具备的功能。在用户看来好像是物理上原来就具有的功能一样。采用虚拟技术的目的是为了提高资源利用率和为用户提供易于使用、方便高效的操作环境。

参考解答：采用了多道程序设计技术的操作系统具有以下四个基本特性：

1. **并发性**：指两个或多个程序在同一时间间隔内运行，宏观上同时推进，微观上交替执行。操作系统需具备处理和调度多个程序同时执行的能力，这是多道程序系统最基本的特征。

2. **共享性**：系统中的资源（如 CPU、内存、设备等）可被多个并发执行的程序共同使用，而非被某一程序独占。共享方式分为**互斥共享**（如打印机，一段时间内只允许一个程序访问）和**同时共享**（如磁盘，允许多个程序并发访问）。

3. **虚拟性**：通过某种技术把一个物理实体变为若干个逻辑上的对应物，或把多个物理实体变为一个逻辑对应物。例如，通过分时技术将单 CPU 虚拟为多个逻辑 CPU，通过虚拟存储技术将物理内存扩展为逻辑上的大内存。其目的是提高资源利用率，为用户提供方便高效的操作环境。

4. **异步性（不确定性）**：多道程序并发执行时，由于资源共享和相互制约，各程序的推进速度不可预知，执行顺序和完成时间具有不确定性。若缺乏同步控制，同一程序多次运行的结果可能不同。

其中，**并发性和共享性是多道程序操作系统最基本的两个特征**，二者互为存在条件；虚拟性以并发性和共享性为基础，异步性则是并发执行的必然结果。

知识点：[现代操作系统的特征（并发、共享、虚拟、异步）](../../../topics/操作系统/操作系统特征.md)、[分时系统的工作原理与特征](../../../topics/操作系统/分时系统工作原理.md)、[进程的定义与特征（动态性、并发性、独立性、制约性、异步性、结构性）](../../../topics/操作系统/进程定义与特征.md)

### 简答 2

请简单叙述进程的三态模型的状态转化。

参考答案：
①就绪态→运行态：当调度程序选择一个新的进程运行时，进程会由就绪态切换到运行态；
②运行态→就绪态：当运行进程用完了获得的时间片时运行进程就会被中断由运行态切换到就绪态，或是因为一高优先级进程处于就绪状态，正在运行的低优先级进程即会被中断而由运行态切换到就绪态；
③运行态→等待态：以下几种情况会导致进程会由运行态切换到等待态，例如当一进程必须等待时，或是操作系统尚未完成服务，进程对一资源的访问尚不能进行时，还有初始化 I/O 且必须等待结果时，在进程间通信时 IPC（Inter-process Communication）进程等待另一进程提供输入时；
④等待态→就绪态：当进程所等待的事件发生时，例如资源申请获得满足，或是等待的数据或信号到来时，进程就可能由等待态切换到就绪态。

参考解答：进程三态模型包含就绪态、运行态和等待态，其状态转化共有四种合法路径，不存在等待态直接到运行态的转化。

-   **就绪态 $\to$ 运行态**：由进程调度程序选中该进程并分配 CPU 引起，是唯一进入运行态的途径。
-   **运行态 $\to$ 就绪态**：由时间片用完或被更高优先级进程抢占引起，进程仍具备执行条件但暂时让出 CPU。
-   **运行态 $\to$ 等待态**：由进程主动请求 I/O、等待事件或资源阻塞引起，此时进程无法继续执行直至外部条件满足。
-   **等待态 $\to$ 就绪态**：由所等待的事件（如 I/O 完成、信号到达）发生引起，进程恢复可执行资格但需重新排队等待调度；**不能直接进入运行态**，因为 CPU 分配必须经过调度程序决策。

知识点：[进程的基本状态（就绪、执行、阻塞）及状态转换](../../../topics/操作系统/进程状态转换.md)、[进程的定义与特征（动态性、并发性、独立性、制约性、异步性、结构性）](../../../topics/操作系统/进程定义与特征.md)、[原语的概念与进程控制原语（创建、撤销、阻塞、唤醒）](../../../topics/操作系统/原语.md)

### 简答 3

简述段式存储管理和页式存储管理的共同点和区别。

参考答案：
页式存储管理和段式存储管理的共同点体现在两者都采用离散分配方式，且都要通过地址映射机构来实现地址变换。但在概念上两者完全不同，其主要区别表现在以下三点：
①页是信息的物理单位，页式管理是为实现离散分配方式，以减少内存的外零头，提高内存的利用率，或者说，页式管理是出于系统管理的需要；而段是信息的逻辑单位，含有一组意义相对完整的信息，段式管理的目的是为了能更好地满足用户的需要。
②页的大小固定且由系统确定，逻辑地址由页号和页内地址组成，可由机器硬件实现；段长不固定，取决于用户所编写的程序，通常由编译程序在对源程序进行编译时，根据信息的性质来划分。
③页式管理中，进程地址空间是一维的，是单一的线性地址空间；而段式管理中，进程地址空间是二维的，程序员在标识一个地址时，既需给出段名，又需给出段内地址。

参考解答：共同点：两者都采用离散分配方式，不要求程序在内存中连续存放；都需要通过地址映射机构实现逻辑地址到物理地址的转换。

区别：

① **管理单位不同**：页是信息的物理单位，页式管理主要为减少外零头、提高内存利用率，是系统管理的需要；段是信息的逻辑单位，含有一组意义相对完整的信息，段式管理更面向用户需求。

② **大小是否固定**：页的大小固定，由系统确定；段长不固定，取决于程序逻辑，由编译程序根据信息性质划分。

③ **地址空间维度不同**：页式管理中进程地址空间是一维线性地址空间；段式管理中地址空间是二维的，地址需由“段名 + 段内地址”给出。

知识点：[段式存储管理的基本原理与地址转换](../../../topics/操作系统/分段存储管理.md)、[页式存储管理的基本原理与地址转换](../../../topics/操作系统/分页存储管理.md)、[分页与分段的区别](../../../topics/操作系统/分页与分段区别.md)

### 简答 4

简述 SPOOLing 技术的特点。

参考答案：
①提高了 I/O 速度。对数据进行的 I/O 操作，已从对低速 I/O 设备进行的 I/O演变为对输入井或输出井中数据的存取，如同脱机输入输出一样，提高了 I/O 速度，缓和了CPU与低速 I/O 设备之间速度不匹配的矛盾。
②设备不被任何进程独占。因为在 SPOOLing 系统中，实际上并未为任何进程分配设备，而只是在输入井或输出井中为进程分配一存储区和建立一张I/O 请求表。
③实现了虚拟设备功能。宏观上，虽然是多个进程在同时使用一台独占设备，即对每个进程而言，它们都认为是自己在独一个设备，但该设备只是逻辑上的设备。可见，SPOOLing系统实现了将独占设备变换为若干台对应逻辑设备的功能。

参考解答：SPOOLing 技术的核心特点为：**提高 I/O 速度**、**设备不被进程独占**、**实现虚拟设备功能**。

1.  **提高 I/O 速度**：将原本针对低速物理设备的 I/O 操作转化为对磁盘输入井/输出井的高速存取，模拟脱机 I/O 行为，有效缓解 CPU 与低速外设间的速度差异。
2.  **设备不被进程独占**：系统并不真正分配物理设备给进程，仅在磁盘上分配存储区并建立 I/O 请求表，物理设备由 SPOOLing 系统统一调度管理。
3.  **实现虚拟设备功能**：通过多道程序并发共享磁盘缓冲区，将一台物理独占设备逻辑上虚拟化为多台对应设备，使每个进程都感觉自己在独享一台专属设备。

### 简答 5

请简单叙述缓冲的基本思想及常见的缓冲技术。

参考答案：
缓冲技术的基本思想是：当一个进程输出数据时，先向系统申请一块内存作为输出缓冲区；然后，将输出数据高速输出到缓冲区；不断把数据填到缓冲区，直到缓冲区被装满为止；此后，进程可以继续它的计算，同时，系统将缓冲区内容写到 I/O 设备上。当一个进程执行读操作输入数据时，过程与此类似。常见的缓冲技术有：单缓冲、双缓冲、循环缓冲和缓冲池。

## 四、综合题（40分，共 4 题）

参考解答：## 简答 5

### 结论

缓冲的基本思想是在内存中设置缓冲区，将进程与速度较慢的 I/O 设备隔离开，使进程计算与设备输入/输出并行进行，从而减少因等待 I/O 造成的阻塞。常见缓冲技术包括：**单缓冲、双缓冲、循环缓冲和缓冲池**。

### 简明说明

- **单缓冲**：在设备与用户进程之间设置一个缓冲区。设备先向缓冲区输入一批数据，缓冲区装满后，进程再从中取用数据。
- **双缓冲**：设置两个缓冲区，一个用于接收 I/O 数据，另一个供进程处理；两个缓冲区交替使用，更有利于实现并行操作。
- **循环缓冲**：由多个大小相等的缓冲区组成并首尾相连形成循环队列，适用于数据输入、输出速率相差较大的情况。
- **缓冲池**：设置多个公共缓冲区，并按用途划分为空闲缓冲队列、输入队列、输出队列等，供多个进程共享，适合多进程环境。

缓冲通过“**内存中暂存数据**”实现计算速度与 I/O 速度的匹配，提高 CPU 与 I/O 设备的并行程度。

知识点：[缓冲技术的引入目的与类型（单缓冲、双缓冲、循环缓冲）](../../../topics/操作系统/缓冲技术.md)

问题描述：若干进程通过有限的共享缓冲区交换数据。其中，生产者进程不断写入，而消费者进程不断读出，共享缓冲区有N个；任何时刻只能有一个进程可对共享缓冲区进行操作。使用信号量和 P、V 操作来实现两组进程之间的同步和互斥。

参考解答：根据题意，需要实现生产者—消费者问题，且缓冲区数为 N，同时保证缓冲区操作的互斥。下面给出同步与互斥方案。

**结论**：  
设置三个信号量：

- `mutex = 1`：互斥访问缓冲区；
- `empty = N`：表示缓冲区中空位数；
- `full = 0`：表示缓冲区中已用数。

生产者—消费者伪代码如下：

```c
semaphore mutex = 1;
semaphore empty = N;
semaphore full = 0;

Producer:
while (true) {
    生产一个数据;
    P(empty);
    P(mutex);
    将数据放入缓冲区;
    V(mutex);
    V(full);
}

Consumer:
while (true) {
    P(full);
    P(mutex);
    从缓冲区取出数据;
    V(mutex);
    V(empty);
    消费数据;
}
```

**说明**：  
- `P(empty)` 在生产者放入前保证有空位，避免缓冲区满时继续写；  
- `P(full)` 在消费者取出前保证有数据，避免缓冲区空时继续读；  
- `mutex` 保证任意时刻只有一个进程操作缓冲区，实现互斥；  
- P、V 顺序不能颠倒，否则可能死锁。例如生产者先 `P(mutex)` 后 `P(empty)`，当缓冲区满时会被阻塞在 `P(empty)`，而消费者因拿不到 `mutex` 无法取数据，造成死锁。

### 综合 3

考虑一个共有 150 个存储单元的系统，如下分配给三个进程，P1 最大需求 70,己占有25；P2最大需求60,己占有40；P3最大需求60,己占有 45。使用银行家算法，以确定下面的任何一个请求是否安全。(1)P4 进程到达，P4最大需求60,最初请求25 个。(2)P4进程到达，P4最大需求60,最初请求 35。

参考答案：
（1）安全
（2）不安全

参考解答：**结论**

(1) 安全
(2) 不安全

**推理与计算过程**

首先计算系统当前的可用资源数（Available）：
$$ \text{Available} = \text{Total} - \sum \text{Allocated} = 150 - (25 + 40 + 45) = 150 - 110 = 40 $$

各进程的最大需求（Max）、已分配（Allocation）及尚需（Need）如下表所示：

| 进程 | Max | Allocation | Need ($Max - Allocation$) |
| :--- | :---: | :---: | :---: |
| P1 | 70 | 25 | 45 |
| P2 | 60 | 40 | 20 |
| P3 | 60 | 45 | 15 |

**(1) P4 到达，最大需求 60，请求 25**

1.  **预分配检查**：请求 $25 \le \text{Available } 40$，且 $25 \le \text{Max } 60$，请求合法。
2.  **试探分配**：
    *   $\text{Available} = 40 - 25 = 15$
    *   P4 的 $\text{Allocation} = 25$，$\text{Need} = 60 - 25 = 35$
3.  **安全性检查**：当前状态为 Available=15。
    *   P1 Need 45 > 15，不可执行。
    *   P2 Need 20 > 15，不可执行。
    *   P3 Need 15 $\le$ 15，**可执行**。P3 运行完毕释放资源：$\text{Available} = 15 + 45 = 60$。
    *   此时 Available=60：
        *   P2 Need 20 $\le$ 60，**可执行**。P2 运行完毕释放资源：$\text{Available} = 60 + 40 = 100$。
        *   P1 Need 45 $\le$ 100，**可执行**。P1 运行完毕释放资源：$\text{Available} = 100 + 25 = 125$。
        *   P4 Need 35 $\le$ 125，**可执行**。P4 运行完毕释放资源：$\text{Available} = 125 + 25 = 150$。
    *   存在安全序列 $\{P3, P2, P1, P4\}$（或 $\{P3, P2, P4, P1\}$ 等），故系统**安全**。

**(2) P4 到达，最大需求 60，请求 35**

1.  **预分配检查**：请求 $35 \le \text{Available } 40$，且 $35 \le \text{Max } 60$，请求合法。
2.  **试探分配**：
    *   $\text{Available} = 40 - 35 = 5$
    *   P4 的 $\text{Allocation} = 35$，$\text{Need} = 60 - 35 = 25$
3.  **安全性检查**：当前状态为 Available=5。
    *   P1 Need 45 > 5，不可执行。
    *   P2 Need 20 > 5，不可执行。
    *   P3 Need 15 > 5，不可执行。
    *   P4 Need 25 > 5，不可执行。
    *   所有进程的 Need 均大于当前 Available，系统进入死锁状态，找不到任何安全序列，故系统**不安全**。

假定磁盘有 200 个柱面，编号 0~199，当前存取臂的位置在 100 号柱面上，且向磁道号增加方向访问。如果请求队列的先后次序是：55、58、39、18、90、160、150、38、184。试问：为完成上述请求，下列算法存取臂移动的总量是多少？并计算平均寻道长度。

（4） 扫描算法 SCAN 总寻道长度 250 平均寻道长度 27.8

参考解答：- **结论**

  - SCAN：总寻道长度 $250$，平均寻道长度 $27.8$

## （1）先来先服务算法 FCFS

- **推理过程**
  - 初始位置：$100$
  - 按请求队列顺序访问：$55,58,39,18,90,160,150,38,184$
  - 每次寻道长度为当前柱面与下一请求柱面之差的绝对值

- **关键计算步骤**
  $$
  \begin{aligned}
  &|100-55|=45\\
  &|55-58|=3\\
  &|58-39|=19\\
  &|39-18|=21\\
  &|18-90|=72\\
  &|90-160|=70\\
  &|160-150|=10\\
  &|150-38|=112\\
  &|38-184|=146
  \end{aligned}
  $$

- **总寻道长度**
  $$
  45+3+19+21+72+70+10+112+146=498
  $$

- **平均寻道长度**
  $$
  \frac{498}{9}\approx 55.3
  $$

## （2）扫描算法 SCAN

- **推理过程**
  - 初始位置：$100$
  - 存取臂向**磁道号增加方向**移动，因此先处理 $100$ 以上的请求
  - $100$ 以上请求按从小到大排列：$150,160,184$
  - 到达最高请求柱面后，再反向处理 $100$ 以下请求
  - $100$ 以下请求按从大到小排列：$90,58,55,39,38,18$

- **关键计算步骤**
  - 从 $100$ 向外扫描到最大请求 $184$：
    $$
    184-100=84
    $$
  - 再从 $184$ 反向扫描到最小请求 $18$：
    $$
    184-18=166
    $$

- **总寻道长度**
  $$
  84+166=250
  $$

- **平均寻道长度**
  $$
  \frac{250}{9}\approx 27.8
  $$
