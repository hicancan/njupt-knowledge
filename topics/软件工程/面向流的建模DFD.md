# 面向流的建模：数据流图（DFD）符号、指导原则与创建

## 什么是 DFD

**数据流图（DFD, Data Flow Diagram）**是一种图形化的系统模型，在一张图中将新软件系统建模为**输入、处理、输出和数据存储**。它是结构化分析（SA）的核心工具，而 SA 正是**面向数据流**的需求分析方法。

结构化分析的完整公式：

$$\text{结构化分析} = \text{数据流} + \text{数据处理（加工）} + \text{数据存储} + \text{端点} + \text{处理说明} + \text{数据字典}$$

为什么需要 DFD？需求分析的原则要求"侧重表达理解问题的数据域和功能域""需求问题应分解细化，建立问题层次结构"。DFD 恰好同时满足两点：它刻画数据在系统中的流向及变化方式，又通过逐层精化实现功能分解。

## DFD 建模符号

| 成分 | 含义 | 说明 |
|---|---|---|
| 外部实体（端点） | 系统之外的数据源或终点 | 如用户、传感器、其他系统 |
| 处理（加工/变换） | 对数据进行转换或计算 | 用泡泡（圆/圆角矩形）表示 |
| 数据流 | 数据通过系统的流向及变化方式 | 带箭头的线，由数据元素构成 |
| 数据存储 | 静态存放的数据 | 如文件、数据库 |

## 指导原则

> [!IMPORTANT]
> ==第 0 层 DFD（环境图）把整个软件或系统描述成一个泡泡==，代表系统整体；精化每一层 DFD 时，==必须维护信息流的连续性==——某一层的输入和输出必须和精化后的输入和输出相同。

其指导思想即结构化方法的基本思想：**自顶向下、逐步求精**，基本原则是**抽象与分解**。此外，DFD 只描述数据流动与处理，不描述控制逻辑、时间顺序或具体算法。

## 怎么创建

1. **提取 DFD 四个成分**：外部实体、处理、数据流、数据存储；
2. **画出高层 DFD**：先创建第 0 层（level 0 / context diagram），一个泡泡加外部实体；
3. **开发第 1 层 DFD**：把整体泡泡分解为若干主要处理；
4. **持续求精**：对仍需细化的处理画第 2 层、第 3 层……直到每个处理都足够简单；
5. **编写 PSPEC**：最低求精层的每个处理（变换）都配一份"小型规格说明"（mini-spec），描述其处理逻辑，为后期构件设计提供指南。

求精过程一举两得：① DFD 逐层细化完成系统的**功能分解**；② 数据在多个处理之间流动，细化同时也**精化了数据**。

以课件 SafeHome 为例：第 0 层只有"SafeHome 系统"一个泡泡，与用户、传感器交互；第 1 层分解出"监控传感器"等处理；对"监控传感器"继续精化出第 2、3 层，每层都保持父泡泡的输入输出不变。

## 与相近概念的区别

| 模型 | 关注点 | 与 DFD 的关系 |
|---|---|---|
| 用例图 | 用户可见的场景与交互 | 一个圈代表一个场景，是需求获取的起点 |
| 状态图 | 系统如何响应事件在状态间迁移 | 补充 DFD 不表达的行为/控制信息，如 SafeHome 第 1 层的状态图 |
| 数据模型（ER） | 数据对象及其关系 | DFD 中的数据存储、数据字典与之对应 |
| 软件体系结构图 | 模块及调用结构 | 设计阶段由 DFD 映射而来 |

> [!NOTE]
> DFD 与软件设计：先建立信息流类型、绘制 DFD，再判定其呈现**变换流**还是**事务流**特征，最后将 DFD 中的每个变换映射为程序结构中相应模块——变换中心的数据转换/计算类变换，映射为变换控制器的从属模块。

## 常见的坑

> [!WARNING]
> - **破坏信息流连续性**：子图凭空多出或丢掉父泡泡的输入输出，是画分层 DFD 最典型的错误。
> - **把控制流画进 DFD**：箭头只能表示数据流动，不表示调用或事件触发。
> - **漏写 PSPEC**：图精化到最低层后，没有小规格说明，处理逻辑仍然无二义性表达，无法指导构件设计。
> - **第 0 层画得太细**：环境图只能有一个泡泡，细节留给后续层次。

> [!TIP]
> 记忆口诀：**"一个泡泡起头，进出守恒求精，最底层配小说明。"** 答题时先写定义（输入、处理、输出、数据存储四要素），再写连续性原则，基本分就拿到了。
