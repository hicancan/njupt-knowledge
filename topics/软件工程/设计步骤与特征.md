# 设计步骤与指导良好设计演化的3个特征

## 设计步骤

在开始编码之前，软件设计可以理解为一座从需求通往构造的桥梁。设计过程不是一步到位的，它遵循一种逐层递进的结构，通常包含以下步骤：

1.  **分析需求模型**  
    把需求阶段产出的用例、数据流图等作为输入，区分==显式需求==（用户明确说的功能）和==隐式需求==（非功能性需求，如性能、安全性）。

2.  **建立整体架构**  
    进行总体设计，将系统划分为子系统或模块。重点考虑模块大小是否适当、层次结构是否清晰。一个典型的软件层次结构图需要关注以下指标：

    ```mermaid
    flowchart TD
        A["主控模块"] --> B["模块 1"]
        A --> C["模块 2"]
        A --> D["模块 3"]
        C --> E["模块 2.1"]
        C --> F["模块 2.2"]
        C --> G["模块 2.3"]
        F --> H["工具模块"] & I["工具模块"]
    ```

    -   **深度**：模块的层次数。
    -   **宽度**：同一层中模块的跨度。
    -   **扇出**：一个模块直接控制的下属模块数（如主控模块扇出为 3）。
    -   **扇入**：一个模块被多少个上级模块直接调用（如公用工具模块扇入高）。

3.  **细化逐个模块**  
    进入详细设计，运用各类设计概念（如抽象、信息隐藏）精炼每个模块内部的数据结构和算法。

4.  **评估与演化设计**  
    设计完成后，需要根据质量特征反复评估，指导设计演化成更优秀的版本。

## 指导良好设计演化的 3 个特征

要判断一个设计是否优秀，并在后续演化中保持质量，可以用以下三个特征作为核心指南：

### 1. 功能独立性
这是高内聚与低耦合共同作用的结果。

-   **高内聚**：模块内部元素职责单一，集中完成一个明确功能。
-   **低耦合**：模块之间接口简单，彼此依赖极小。

> [!IMPORTANT]
> 独立模块像乐高积木，可以独立开发、测试和维护，且修改时不易引发连锁反应。
> 在设计演化中，你需要始终问自己：拆分出来的模块是否做到了==做完一件事且只做一件事==？

### 2. 信息隐藏
每个模块对外屏蔽自己的内部实现细节，仅通过公共接口通信。其他模块只能通过授权的方法访问数据，而不用关心背后的算法或数据结构。

> [!TIP]
> 接口引用指向具体类对象时，调用者无需知道具体实现如何在运行时被绑定。例如，`Pet myPet = new Cat();`，其他组件调用 `myPet.feed()` 时，隐藏了是猫还是狗的细节，这是动态联编带来的多态优势。

### 3. 逐步求精
优秀的软件设计从来不是一蹴而就的。它从顶层宏观的功能描述开始，通过许多次连续的精细化迭代，逐层分解为更小的处理单元。它要求你在每一个层次上都能完整描述功能，再进入下一层细节。

> [!WARNING]
> **多态 ≠ 重载**：很多人以为多态就是方法名相同，但这是常见误区。重载是静态联编（编译时确定），多态是运行时才决定具体调用哪个对象的方法。它必须满足==继承/实现 + 方法重写 + 父类/接口引用指向子类/具体类对象==三个条件。

**综合形成一个“算对了”的设计核查清单：**

| 设计质量特征 | 检查内容 | 关联概念 |
| :--- | :--- | :--- |
| **模块化** | 系统是否由功能明确的独立模块组成？ | 高内聚、低耦合 |
| **抽象** | 模块接口是否只暴露必要信息？ | 信息隐藏 |
| **设计演化指南** | 迭代中是否保持了逐步求精，仍满足所有显式与隐式需求？ | 功能独立性、可扩展性 |

最终，一个良好的设计在演化后应具备：==功能独立==的模块能轻松替换，==信息隐藏==保证了底层修改不影响上游，而==逐步求精==让设计能灵活响应变化。
