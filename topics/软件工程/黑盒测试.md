# 黑盒测试（Black-Box Testing / Behavioral Testing）：等价类划分与边界值分析

## 黑盒测试：等价类划分与边界值分析

如果无法查看代码内部逻辑，仅凭需求规格说明书，如何用最少的测试用例发现最多的错误？这正是 ==Black-Box Testing（黑盒测试）== 要解决的核心问题。它关注软件的 ==Behavioral Testing（行为测试）==，即验证“输入-输出”是否符合预期，而非内部实现是否正确。在众多黑盒技术中，==Equivalence Partitioning（等价类划分）== 与 ==Boundary Value Analysis（边界值分析）== 是构建级测试最基础、考查频率最高的两种方法。

### 为什么需要这两种方法？

穷举测试（Exhaustive Testing）在现实中不可行。若一个函数接受两个整数输入，组合数可能高达 $2^{64}$。我们必须采用 ==Selective Testing（选择性测试）== 策略：

-   **等价类划分**：将所有可能的输入数据划分为若干子集（等价类），从每个子集中选取少数代表性数据进行测试。其假设是：若某类中一个值能发现错误，则该类其他值也能；反之亦然。
-   **边界值分析**：大量实践表明，==错误往往发生在输入/输出范围的边界上==，而非中间区域。因此需针对边界值及其邻近值设计用例。

> [!IMPORTANT]
> 两者通常 ==联合使用==：先用等价类划分确定有效/无效区间，再用边界值分析在每个区间的端点处“精准打击”。

### 怎么做：以 NextDate 函数为例

假设 `NextDate(year, month, day)` 要求：$1900 \le year \le 2099$，$1 \le month \le 12$，$1 \le day \le 31$。

**Step 1：等价类划分**

| 输入变量 | 有效等价类         | 无效等价类             |
| :------- | :----------------- | :--------------------- |
| year     | $[1900, 2099]$     | $<1900$, $>2099$       |
| month    | $[1, 12]$          | $<1$, $>12$            |
| day      | $[1, 31]$          | $<1$, $>31$            |

**Step 2：边界值分析**

对每个变量的边界取值：最小值、最小值+1、正常值、最大值-1、最大值。例如 `year` 的边界测试点为：1899, 1900, 1901, 2098, 2099, 2100。

```mermaid
flowchart LR
    A["等价类划分"] --> B["确定有效/无效区间"]
    B --> C["边界值分析"]
    C --> D["取边界及邻值"]
    D --> E["生成测试用例"]
```

> [!TIP]
> 边界值选取口诀：==“上点、离点、内点”==。上点即边界值本身，离点为紧邻边界的内外值，内点为区间内任意典型值。

### 与白盒测试的区别

| 维度           | Black-Box Testing        | White-Box Testing        |
| :------------- | :----------------------- | :----------------------- |
| 关注点         | 功能/行为                | 内部结构/逻辑路径        |
| 设计依据       | 需求规格                 | 源代码                   |
| 典型方法       | 等价类、边界值、正交数组 | Basis Path、Loop Testing |
| 测试阶段       | 集成/系统/验收           | 单元/组件                |
| 能否发现遗漏需求 | ==能==                   | 不能                     |

### 常见误区与注意事项

> [!WARNING]
> 边界值分析 ≠ 只测边界点！必须同时覆盖 ==有效边界== 和 ==无效边界==。例如 `month=0` 和 `month=13` 都是关键无效边界测试点，遗漏任一都可能漏测异常处理逻辑。

> [!CAUTION]
> 等价类划分时，==无效等价类之间不能合并==。每个无效条件应单独测试，否则无法定位具体是哪个非法输入触发了错误。例如 `month=0` 和 `day=32` 必须分属不同测试用例。

> [!NOTE]
> 在 OO 测试中，Partition Testing 是等价类划分在类方法级别的延伸，需结合类的状态和行为模型设计用例，而非孤立看待单个参数。

掌握这两个方法的关键在于：==先划类、再取边、无效类不合并==。它们不仅是考试高频考点，更是实际工程中性价比最高的测试设计起点。
