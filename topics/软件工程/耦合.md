# 耦合（Coupling）的类型：内容、共用、控制、标记、数据、例程调用、类型使用、包含导入、外部耦合

## 什么是耦合

**耦合（Coupling）** 表示模块之间相互依赖的相对程度，即模块与其他模块及外部世界的连接程度。它取决于三个方面：

- 模块间**接口的复杂程度**；
- 对模块进行调用或引用的**位置与方式**；
- 通过接口传递的**数据内容与数量**。

例如，模块 A 只调用模块 B 的公开操作并传入必要参数，依赖较少；若 A 直接修改 B 的内部变量，则两者紧密绑定。构件级设计追求 ==高内聚、低耦合==，通过接口建立构件之间的**可控连接**，使构件更容易理解、测试、替换和复用。

> [!IMPORTANT]
> 内聚（Cohesion）表示模块内部功能的相对强度；耦合表示模块之间相互依赖的相对程度。前者关注“模块内部是否专注”，后者关注“模块之间连接多紧”。

## 常见类型

耦合类型可从不同角度分类，不能简单地把下面九项都排成唯一的强弱序列。其中，内容、共用、控制、标记、数据耦合常按依赖程度由高到低理解。

| 类型 | 含义与典型表现 | 设计建议 |
|---|---|---|
| 内容耦合 Content | 一个构件直接修改另一构件的内部数据，或进入其内部逻辑 | 最强，应避免 |
| 共用耦合 Common | 多个构件共享全局变量、公共数据区等 | 限制共享范围 |
| 外部耦合 External | 多个构件共同依赖外部数据格式、协议、设备或环境约定 | 集中封装外部约定 |
| 控制耦合 Control | 调用者传入控制标志，决定被调用者执行哪段逻辑 | 拆分职责明确的操作 |
| 标记耦合 Stamp | 传递整个数据结构或对象，但接收者只使用其中一部分 | 只传真正需要的信息 |
| 数据耦合 Data | 仅通过参数传递必要数据，不借此控制对方内部逻辑 | 通常较低，优先采用 |
| 例程调用耦合 Routine call | 一个构件调用另一构件的操作，形成调用依赖 | 保持接口简单稳定 |
| 类型使用耦合 Type use | 构件使用另一构件定义的类型，如类、接口或数据类型 | 优先依赖抽象类型 |
| 包含或导入耦合 Inclusion/import | 通过 `include`、`import` 等引入另一构件的内容或定义 | 删除无必要依赖 |

> [!NOTE]
> **数据耦合不等于“只要传参数就低耦合”。** 若传入大量无关数据，可能属于标记耦合；若参数用于选择对方内部执行路径，则属于控制耦合。

## 如何降低耦合

降低耦合不是取消所有联系，而是让必要联系**清晰、少量且可控制**：

1. 通过公开接口交互，隐藏内部数据结构和实现细节。
2. 减少参数数量，只传递完成操作所需的数据。
3. 避免全局数据和被调用者内部的随意跳转、修改。
4. 运用依赖倒置原则（DIP）：高层模块与低层模块都依赖抽象，而不是直接依赖具体实现。
5. 将外部协议、格式等易变约定集中封装，避免扩散到多个构件。

例如，`Motion` 构件依赖 `ImageObserver` 接口并调用 `imageUpdate()`，无需了解 `Imaging` 的具体实现。更换图像处理实现时，只要新构件仍实现该接口，`Motion` 通常不必修改。这体现了可控连接和可替换性。

## 易错点与例题

> [!WARNING]
> “低耦合”不等于“零耦合”，也不等于“内聚越低越好”。构件必须协作才能完成系统功能；正确目标是减少不必要的相互依赖，同时提高模块内部的功能集中度。

**例题：** Coupling is a qualitative indication of the degree to which a module（　）

A. can be written more compactly.  
B. focuses on just one thing.  
C. is able to complete its function in a timely manner.  
D. is connected to other modules and the outside world.

**答案：D。** 它直接对应耦合的定义。B 描述的是模块是否专注单一职责，更接近内聚；A 是代码紧凑性，C 是及时完成功能的性能要求，都不是耦合度。

> [!TIP]
> 判断题“内聚表示模块内部功能的相对强度，耦合表示模块间相互依赖的相对程度”应选 **True**。记忆：**内聚看内部，耦合看之间。**
