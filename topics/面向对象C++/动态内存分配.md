# 用new申请和delete释放动态内存空间

## 用 new 申请动态内存

C 语言中用 `malloc` 和 `free` 管理堆内存，但它们在 C++ 中显得笨拙：`malloc` 只分配原始字节，不知道类型，也不会调用构造函数。C++ 引入 `new` 和 `delete`，让动态内存管理更安全、更自然。

`new` 的基本语法有两种形式：

```cpp
int *p = new int;       // 申请 1 个 int 空间，值未初始化
int *q = new int(5);    // 申请 1 个 int 空间，同时初始化为 5
int *arr = new int[10]; // 申请连续 10 个 int 空间
```

> [!IMPORTANT]
> `new int(5)` 的圆括号是**初始值**，分配的是 1 个 `int` 并赋值为 5。`new int[5]` 的方括号才是申请连续 5 个 `int` 空间。这俩非常容易混淆。

`new` 做三件事：计算类型大小、在堆上分配内存、返回类型匹配的指针。如果内存不足，`new` 会抛出 `std::bad_alloc` 异常，而不是像 `malloc` 那样返回 `NULL`。

---

## 用 delete 释放动态内存

有借有还。用 `new` 申请的空间，必须用 `delete` 释放，否则会造成**内存泄漏**。释放时要和申请方式严格对应：

| 申请方式 | 释放方式 |
|---------|---------|
| `new int` | `delete p;` |
| `new int(5)` | `delete p;` |
| `new int[10]` | `delete[] arr;` |

> [!WARNING]
> 用 `new[]` 申请的空间如果混用 `delete`（没带 `[]`）释放，行为是==未定义的==，程序可能崩溃或悄悄泄漏。同样，`new` 申请的用 `delete[]` 释放也不对。

释放后，指针变量本身还在，值仍然是原来的地址，但它指向的内存已经归还给系统。此时再访问 `*p` 就是**悬垂指针**。养成释放后置空的习惯：

```cpp
delete p;
p = nullptr;   // C++11 起推荐
```

## 与 malloc/free 的对比

```mermaid
flowchart LR
    A["malloc 分配字节"] --> C["需手动算大小"]
    B["new 分配类型化内存"] --> D["自动算大小并初始化"]
    D --> E["能否调用构造函数"]
    C --> F["不能调用构造/析构"]
    E --> G["能调用构造/析构"]
```

| 特性 | `malloc` / `free` | `new` / `delete` |
|------|-------------------|------------------|
| 是否需要指定字节数 | 需要（`sizeof`） | 自动按类型计算 |
| 返回类型 | `void*`，要强转 | 类型匹配的指针 |
| 初始化 | 不能初始化 | 可用 `()` 给初值 |
| 构造函数/析构函数 | 不调用 | 会调用 |
| 失败时 | 返回 `NULL` | 抛异常 |

## 动态数组与字符串

课件中的 `book` 类是一个典型场景：数据成员 `char *title` 需要一个动态字符串来保存书名，因为书名长度在编译期不可知。

```cpp
book::book(char *t, float p)
{
    title = new char[strlen(t) + 1];  // +1 给 '\0' 留位置
    strcpy(title, t);
    price = p;
}

book::~book()
{
    if (title) delete[] title;  // 释放动态字符串
}
```

构造函数里 `new char[n+1]` 申请了 n+1 个字符的空间来装字符串，析构函数中用 `delete[]` 完整释放。这里如果漏了析构或者写成 `delete title`，前者泄漏，后者可能只释放了首元素。

## 常见坑点

**坑 1：`new int(5)` vs `new int[5]`。**单选题里最常考。圆括号是单个元素的初始值，方括号是数组的大小。`int *p = new int(5)` 申请了 **1 个** `int`，值设为 5。

**坑 2：`delete` 之后没有置空。**析构函数中虽然不会再把析构函数退出的指针拿来用，但在其他代码中释放后不复用是基本纪律。

**坑 3：浅拷贝引起二次释放。**如果类里只有默认拷贝构造函数，两个对象会共享同一块 `title` 指向的内存。第一个对象析构时释放了这块内存，第二个对象析构时再次 `delete[]` 同一地址，程序崩溃。需要自定义拷贝构造函数和赋值运算符完成**深拷贝**。

> [!TIP]
> 判断该用 `delete` 还是 `delete[]` 的诀窍：==申请时带了 `[]`，释放时也要带 `[]`==。一对一，有借有还。
