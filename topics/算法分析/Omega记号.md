# 渐近表示法：Ω记号（下界）

## $\Omega$ 记号的本质与定义

当我们评价一个算法“足够快”时，通常关注其上界 $O$；但若要断言某个问题“不可能更快”，或者证明某算法已达理论极限，就必须使用 ==渐近下界记号 $\Omega$==。它回答的核心问题是：当输入规模 $n$ 充分大时，函数 $f(n)$ 的增长率是否**至少**不低于 $g(n)$？

> [!IMPORTANT]
> $\Omega(g(n))$ 的严格数学定义
> $$ \Omega(g(n)) = \{ f(n) \mid \exists c > 0, n_0 \in \mathbb{N}^+, \forall n \geq n_0, 0 \leq c \cdot g(n) \leq f(n) \} $$
> 即存在正常数 $c$ 和阈值 $n_0$，使得当 $n \geq n_0$ 时，$f(n)$ 始终位于 $c \cdot g(n)$ 上方。

这一定义与 $O$ 记号形成镜像对称：$O$ 寻找“天花板”，$\Omega$ 寻找“地板”。在算法最优性判定中，若某算法最坏时间复杂度为 $O(h(n))$，而该问题的理论下界为 $\Omega(h(n))$，则该算法是==最优算法==。例如，基于比较的排序问题下界为 $\Omega(n \log n)$，堆排序最坏情况为 $O(n \log n)$，故堆排序是最优排序算法。

## 如何构造 $\Omega$ 证明

证明 $f(n) = \Omega(g(n))$ 的关键在于找到合适的常数 $c$ 和 $n_0$，使不等式 $f(n) \geq c \cdot g(n)$ 恒成立。这与证 $O$ 时放缩方向相反，需要**缩小** $f(n)$ 或**放大** $g(n)$。

```mermaid
flowchart LR
    A["确定目标 g(n)"] --> B["对 f(n) 做下界放缩"]
    B --> C["解出 c 与 n₀"]
    C --> D["验证 n≥n₀ 时不等式成立"]
    D --> E["结论 f=Ω(g)"]
```

以课后习题为例，证明 $5n^2 - 8n + 2 = \Omega(n^2)$：
1.  **观察低阶项影响**：当 $n$ 较小时，$-8n$ 可能使左边小于右边，需选取足够大的 $n_0$。
2.  **放缩推导**：当 $n \geq 4$ 时，$8n \leq 2n^2$，故 $5n^2 - 8n + 2 \geq 5n^2 - 2n^2 = 3n^2$。
3.  **确定参数**：取 $c = 3, n_0 = 4$。
4.  **验证**：$n=4$ 时，左边 $= 50$，右边 $= 3 \times 16 = 48$，$50 \geq 48$ 成立。因此 $5n^2 - 8n + 2 = \Omega(n^2)$。

> [!TIP]
> 放缩技巧：处理多项式时，可将负的低阶项用高阶项的一部分“吸收”。如 $-8n \leq -kn^2$（需 $n$ 足够大），从而保留正的高阶主项系数作为 $c$。

## $\Omega$ 与 $O$、$\Theta$ 及分支限界中的区别

| 记号 | 含义 | 不等式方向 | 典型用途 |
| :--- | :--- | :--- | :--- |
| $O(g(n))$ | 渐近上界 | $f(n) \leq c \cdot g(n)$ | 算法最坏/最好执行时间上限 |
| $\Omega(g(n))$ | 渐近下界 | $f(n) \geq c \cdot g(n)$ | 问题固有难度、算法最优性 |
| $\Theta(g(n))$ | 紧确界 | $c_1 g \leq f \leq c_2 g$ | 精确刻画增长率 |

> [!WARNING]
> 切勿混淆两个“下界”概念
> - **渐近分析中的 $\Omega$**：描述函数增长率的数学下界，与具体算法无关。
> - **分支限界法中的损失下界 $\hat{c}$**：针对特定结点估算的目标函数最小值，用于剪枝（当 $\hat{c} \geq U$ 时舍弃）。前者是理论工具，后者是搜索策略中的动态估值，二者语境完全不同。

## 常见误区警示

> [!CAUTION]
> $\Omega$ 不是“最好情况时间复杂度”
> 许多同学误以为 $O$ 对应最坏情况、$\Omega$ 对应最好情况，这是==严重错误==。$\Omega$ 仅表示增长率的数学下界，可用于描述最坏、平均或最好情况。例如，“快速排序最坏情况是 $\Omega(n^2)$”是完全正确的表述。

此外，证明时 $n_0$ 的选取必须保证不等式在 $[n_0, +\infty)$ 上**恒成立**。如上例中若取 $n_0 = 3$，则 $f(3)=23 < 27=c \cdot g(3)$，证明失败。务必通过代入验证边界点，避免想当然。
