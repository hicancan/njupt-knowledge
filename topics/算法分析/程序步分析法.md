# 使用程序步分析算法的时间复杂度

程序步（program step）是算法分析中的一个基本概念，指**在语法或语义上有意义的一段指令序列，其执行时间与问题实例的特征无关**。例如，一条赋值语句、一次算术运算或一次条件判断都可以视为一个程序步。通过统计算法中程序步的执行次数，我们可以精确地描述算法的时间复杂度，而不必依赖于具体的机器性能或编译器优化。

## 为什么需要程序步分析

直接测量算法的运行时间会受到硬件、编译器、输入数据等多种因素的影响，难以公平比较不同算法的效率。程序步分析提供了一种**与机器无关**的抽象方法：我们只需关注算法中关键操作的执行次数，并将其表示为问题规模 $n$ 的函数 $T(n)$，进而得到渐进时间复杂度（如 $O(n)$、$O(n^2)$ 等）。这种方法特别适合分析循环结构和递归算法。

## 怎么做：程序步分析步骤

1. **确定问题规模 $n$**：例如数组长度、输入数字的二进制位数等。
2. **识别关键语句**：通常是循环体内的语句或递归调用，它们的执行次数决定了算法的主要耗时。
3. **计算执行次数**：根据循环边界、条件判断等，用求和公式或递归方程表示总程序步数。
4. **求渐进复杂度**：保留最高阶项，忽略常数系数和低阶项。

> [!TIP]
> 对于嵌套循环，内层循环的执行次数可能依赖于外层循环变量，此时需要用求和公式 $\sum$ 逐层计算。

## 例子：计算画线语句的执行次数

考虑以下程序段（习题 2-8 第（2）问）：

```c
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= i; j++)
        for (int k = 1; k <= j; k++)
            x++;   // 画线语句
```

**分析过程**：

- 最内层循环 `k` 执行 $j$ 次；
- 中间循环 `j` 执行 $i$ 次；
- 最外层循环 `i` 执行 $n$ 次。

因此，画线语句的总执行次数为：
$$
\sum_{i=1}^{n} \sum_{j=1}^{i} \sum_{k=1}^{j} 1 = \sum_{i=1}^{n} \sum_{j=1}^{i} j = \sum_{i=1}^{n} \frac{i(i+1)}{2} = \frac{n(n+1)(n+2)}{6}
$$

渐进时间复杂度为 $O(n^3)$。

## 常见误区与注意事项

> [!WARNING]
> **不要简单地将循环层数相乘**。例如，若内层循环边界为 `j <= i/2`，则执行次数为 $\sum_{i=1}^{n} \lfloor i/2 \rfloor \approx n^2/4$，复杂度仍是 $O(n^2)$，但精确次数需要求和计算。

> [!NOTE]
> **对数级循环**：若循环变量每次翻倍（如 `i *= 2`），则循环次数为 $\lceil \log n \rceil$，复杂度为 $O(\log n)$。

> [!IMPORTANT]
> ==程序步分析的核心是准确计算关键语句的执行次数==，而不是简单地看循环层数或代码行数。对于递归算法，通常需要建立递归方程并用展开法求解。

## 与相近概念的区别

| 概念 | 说明 | 与程序步分析的关系 |
|------|------|-------------------|
| **时间复杂度** | 算法执行时间随输入规模增长的趋势 | 程序步分析是计算时间复杂度的具体方法 |
| **空间复杂度** | 算法所需内存空间随输入规模增长的趋势 | 程序步分析主要关注时间，但也可用于统计空间相关的操作次数 |
| **渐近符号（$O, \Omega, \Theta$）** | 描述函数增长阶的数学工具 | 程序步分析得到精确次数后，用渐近符号表示其增长阶 |

通过程序步分析，我们能够从代码层面精确推导出算法的时间复杂度，为算法设计和优化提供可靠依据。
