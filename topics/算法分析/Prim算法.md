# 最小代价生成树的Prim算法（点集扩展）

## 算法思想与核心定义

Prim 算法是求解**最小代价生成树（MST）**的经典贪心策略。其核心思想是**“点集扩展”**：从任意一个顶点出发，逐步将距离当前生成树集合最近的顶点加入，直到所有顶点都被包含。

> [!IMPORTANT]
> ==核心结论==：Prim 算法每次选择连接“已选点集 $U$”与“未选点集 $V-U$”之间权值最小的边。它保证每一步局部最优，最终得到全局最优解。

想象一下铺路工程：我们从一个城市开始，每次都找一条通往未连通城市的**最短新路**，直到所有城市连通。这种“由点及面”的扩张方式，使其在稠密图中表现优异。

## 算法执行流程

算法维护两个集合：已入选顶点集 $U$ 和未入选顶点集 $V-U$。初始化时，任选一点 $v_0 \in U$。

```mermaid
flowchart TD
    Start([开始: 任选 v0]) --> Init[初始化 U={v0}<br>V-U=其余点]
    Init --> Find{查找最小边}
    Find -- "(u, v) 最小<br>u∈U, v∉U" --> Add[将 v 加入 U<br>边加入 MST]
    Add --> Check{U == V?}
    Check -- 否 --> Find
    Check -- 是 --> End([结束: 输出 MST])
    
    style Start fill:#e1f5fe
    style End fill:#e8f5e9
    style Find fill:#fff3e0
```

> [!TIP]
> **关键操作**：每次迭代需扫描所有连接 $U$ 和 $V-U$ 的边，找出权值最小者。若使用邻接矩阵，时间复杂度为 $O(n^2)$；若使用二叉堆优化，可降至 $O(m \log n)$。

## 与 Kruskal 算法的对比

很多同学容易混淆 Prim 和 Kruskal。两者的本质区别在于**贪心选择的对象**不同：Prim 选“点”，Kruskal 选“边”。

| 特性 | Prim 算法 | Kruskal 算法 |
| :--- | :--- | :--- |
| **贪心策略** | 加点（点集扩展） | 加边（边排序） |
| **适用场景** | ==稠密图== ($m \approx n^2$) | ==稀疏图== ($m \ll n^2$) |
| **数据结构** | 邻接矩阵/优先队列 | 并查集 |
| **时间复杂度** | $O(n^2)$ 或 $O(m \log n)$ | $O(m \log m)$ |

> [!NOTE]
> **南邮考题指引**：如习题 6-9 所示，当 $m = O(n^{1.99})$ 时，边数接近完全图，属于稠密图。此时 Kruskal 的 $O(m \log m) \approx O(n^2 \log n)$ 劣于 Prim 的 $O(n^2)$，故应选 **Prim 算法**。

## 常见误区与性质证明

### 1. 边权增加是否影响 MST？
若图中每条边的权值都增加常数 $c$，原 MST $T$ 是否仍为新图的 MST？

> [!IMPORTANT]
> **答案：是。**
> **证明思路**：设 $T$ 有 $n-1$ 条边。新代价 $\text{cost}'(T) = \text{cost}(T) + c(n-1)$。对于任意其他生成树 $T'$，同样增加 $c(n-1)$。若原图中 $\text{cost}(T) \le \text{cost}(T')$，则新图中不等式依然成立。相对大小未变，最优性保持。

### 2. 唯一性问题
若图中所有边权互不相同，MST 是否唯一？

> [!CAUTION]
> **是的，唯一。**
> 如果存在两棵不同的 MST，必然存在权值相同的边进行替换，这与“边权互异”矛盾。见习题 6-11 证明。

### 3. 易错坑
*   **回路检测**：Prim 算法天然避免回路，因为新加入的点必须来自 $V-U$。而 Kruskal 需要显式判断回路（并查集）。
*   **起点选择**：Prim 的结果与起点无关，但中间过程可能不同。

## 典型例题解析

**题目**：给定无向连通图 $G$， $m=O(n^{1.99})$，求 MST 选哪种算法？

**解析**：
1.  分析密度：$m \approx n^2$，为稠密图。
2.  比较复杂度：
    *   Prim (邻接矩阵): $O(n^2)$
    *   Kruskal: $O(m \log m) \approx O(n^2 \log n)$
3.  结论：$O(n^2) < O(n^2 \log n)$，故选 **Prim 算法**。
