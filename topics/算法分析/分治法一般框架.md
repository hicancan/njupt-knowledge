# 分治法的一般思想与算法框架

分治法（Divide and Conquer）是《算法分析与设计》中的核心策略。其本质是将一个难以直接解决的**复杂大问题**，分解为若干个**规模较小**、**相互独立**且**类型相同**的子问题。通过递归求解子问题，最后将子问题的解**合并**为原问题的完整答案。

> [!IMPORTANT]
> 分治法适用的四大特征：
> 1. 规模缩小到一定程度可容易解决；
> 2. 可分解为若干规模较小的相同问题；
> 3. ==子问题的解可以合并为原问题的解==；
> 4. ==子问题之间相互独立==（无公共子问题）。

## 算法框架与执行流程

分治法的标准伪代码框架如下，包含三个关键步骤：**分解（Divide）**、**解决（Conquer）**、**合并（Combine）**。

```mermaid
flowchart TD
    Start[开始: 问题 P] --> Check{规模足够小?}
    Check -- Yes --> Solve[直接求解 S(P)]
    Check -- No --> Divide[分解: Divide(P)]
    Divide --> Sub1[子问题 P1]
    Divide --> Sub2[子问题 P2]
    Divide --> SubN[...]
    Sub1 --> Rec1[递归求解 DandC(P1)]
    Sub2 --> Rec2[递归求解 DandC(P2)]
    SubN --> RecN[递归求解 DandC(Pn)]
    Rec1 --> Merge[合并: Combine]
    Rec2 --> Merge
    RecN --> Merge
    Solve --> End[返回结果]
    Merge --> End
```

若子问题规模为 $n$，分解为 $a$ 个规模为 $n/b$ 的子问题，合并代价为 $f(n)$，则时间复杂度递归式为：
$$ T(n) = aT(n/b) + f(n) $$

> [!TIP]
> **平衡子问题思想**：尽量使分解出的子问题规模大致相等（如二分）。若分解极不平衡（如 $1$ 和 $n-1$），递归深度可能退化为 $O(n)$，导致效率从 $O(n \log n)$ 降至 $O(n^2)$。

## 典型应用对比：合并排序 vs 快速排序

两者均符合分治策略，但在“分解”与“合并”的难易度上截然相反：

| 特性 | 合并排序 (Merge Sort) | 快速排序 (Quick Sort) |
| :--- | :--- | :--- |
| **分解过程** | **简单**：直接一分为二 | **困难**：需调用 Partition 分区，依赖主元选择 |
| **合并过程** | **困难**：需 $O(n)$ 时间合并有序子序列 | **简单**：子序列排好序后，整体自然有序 |
| **时间复杂度** | 最好/平均/最坏均为 $O(n \log n)$ | 最好/平均 $O(n \log n)$，最坏 $O(n^2)$ |
| **空间复杂度** | $O(n)$ (需辅助数组) | $O(\log n)$ (递归栈) |

> [!WARNING]
> **易错点辨析**：
> *   **独立性**：分治法要求子问题**相互独立**。若子问题重叠（如斐波那契数列），应使用**动态规划**而非分治，否则会产生大量重复计算。
> *   **合并排序稳定性**：合并排序是**稳定**排序，而快速排序通常是不稳定的。

## 实例演示：最佳合并模式

分治思想也体现在贪心策略的最佳合并中。设有 5 个有序文件，记录数分别为 `(30, 10, 20, 15, 20)`。求最少读写记录总数（即构建哈夫曼树）。

1.  取最小两个 `10, 15` 合并，代价 $25$。新集合：`{20, 20, 25, 30}`
2.  取最小两个 `20, 20` 合并，代价 $40$。新集合：`{25, 30, 40}`
3.  取最小两个 `25, 30` 合并，代价 $55$。新集合：`{40, 55}`
4.  合并最后两个 `40, 55`，代价 $95$。

总代价 = $25 + 40 + 55 + 95 = 215$。此过程体现了自底向上合并子问题解的思想。
