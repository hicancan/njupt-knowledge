# 语法分析的任务与方法分类

## 它是什么与为什么需要

在编译过程中，词法分析把源程序拆成单词（记号）流；接下来要判断这些记号是否**按文法规则组成了合法句子**。这一步就是==语法分析==：==核心任务是从记号流识别出句子结构，并构造分析树/语法树==。若不合文法，要报错并恢复。

为什么需要它？因为只看到“单词合法”不够。例如 `i+i` 是合法表达式，而 `i+)` 单词都对，但结构不合法，必须由语法分析拦截。

## 方法分类

按分析方向分，主要两类：

| 类别 | 代表方法 | 关键思想 | 南邮课件重点 |
|---|---|---|---|
| 自顶向下 | 递归下降、LL(1) | 从开始符推导，匹配输入 | ==LL(1)分析表构造== |
| 自底向上 | 算符优先、LR | 从输入串归约到开始符 | ==简单优先/算符优先分析== |

LL(1) 看“下一个输入符”选产生式；算符优先看终结符之间 `<`、`=`、`>` 优先关系找句柄归约。两者都服务于“判断句子+建树”。

## 怎么做：一个算对了的 LL(1) 例子

以考题文法为例：

$$
\begin{aligned}
S &::= aAd \\
A &::= BC \\
B &::= b \mid \varepsilon \\
C &::= c \mid \varepsilon
\end{aligned}
$$

先算 FIRST / FOLLOW：

$$
\begin{aligned}
FIRST(S) &= \{a\} \\
FIRST(A) &= \{b, c, \varepsilon\} \\
FIRST(B) &= \{b, \varepsilon\} \\
FIRST(C) &= \{c, \varepsilon\} \\
FOLLOW(S) &= \{\#\} \\
FOLLOW(A) &= \{d\} \\
FOLLOW(B) &= \{d, c\} \\
FOLLOW(C) &= \{d\}
\end{aligned}
$$

填表规则很容易错：若非终结符 $X$ 的产生式右部 FIRST 含当前符 $t$，填该产生式；若右部可推 $\varepsilon$，且 $t\in FOLLOW(X)$，也填该 $\varepsilon$ 产生式。于是得到：

| | a | b | c | d | # |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **S** | $S ::= aAd$ | | | | |
| **A** | | $A ::= BC$ | $A ::= BC$ | $A ::= BC$ | |
| **B** | | $B ::= b$ | $B ::= \varepsilon$ | $B ::= \varepsilon$ | |
| **C** | | | $C ::= c$ | $C ::= \varepsilon$ | |

> [!TIP]
> 记忆：==FIRST 管“能不能开头”，FOLLOW 管“空了后面接谁”==。

## 相近概念区别与常见坑

- 简单优先/算符优先是自底向上；LL(1) 是自顶向下。考题里 `((aa)a)#` 用优先关系表分析后不是句子，说明优先关系不匹配就失败。
- 坑一：FOLLOW 集漏加 `#`，导致开始符归约判断错。
- 坑二：LL(1) 表中 $\varepsilon$ 行只看 FOLLOW，不混进 FIRST。
- 坑三：递归子程序遇 $\varepsilon$ 选择项时，输入符若属于 FOLLOW 就自动匹配，不消耗输入。

> [!WARNING]
> ==`(i+)` 不是表达式文法句子==：LL(1) 表驱动会在 `+` 后缺 `T` 时报错，别误认为 `)` 能直接归约。
