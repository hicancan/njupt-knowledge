# 中缀表达式转换为后缀表达式（栈内优先级isp与栈外优先级icp）

## 中缀转后缀：为什么非要让栈里栈外“两个优先级”？

先想一个问题：`a + b * c` 扫描到 `+` 时，能直接输出 `+` 吗？不能，因为后面可能紧跟 `*`，而 `*` 应当先算。**中缀转后缀的核心矛盾**是：当前运算符能不能输出，取决于==后面是否会出现更高优先级的运算符==。栈恰好能“压住”暂时不能输出的运算符，等确认了右侧情况再弹出。

### 两个优先级到底在比什么

南邮课件用两个记号描述比较规则：

| 记号 | 全称 | 含义 |
|------|------|------|
| `isp` | in-stack priority | 运算符**已在栈内**时的优先级 |
| `icp` | incoming priority | 运算符**即将进栈**时的优先级 |

比较规则一句话：当新运算符的 `icp` **大于**栈顶的 `isp` 时，新运算符进栈；否则，栈顶运算符出栈并输出。

> [!IMPORTANT]
> `isp` 与 `icp` 的差异集中体现在括号上：`(` 在栈外地位极高（icp 最大），一旦进栈后地位骤降（isp 最小），以便后续运算符都能顺利入栈；直到遇到 `)` 时，再一路弹到 `(`。

常见优先级表（数值越大优先级越高）：

| 运算符 | isp（栈内） | icp（栈外） |
|--------|-------------|-------------|
| `(` | 1 | 6 |
| `* /` | 5 | 4 |
| `+ -` | 3 | 2 |
| `)` | — | 1 |

### 操作规则

1. **操作数**直接输出。
2. **运算符**：若 `icp > isp`，进栈；否则不断弹栈输出，直到 `icp > isp` 才进栈。
3. **左括号 `(`**：无条件进栈。
4. **右括号 `)`**：弹栈输出直到弹出 `(`，`()` 都不输出。
5. 表达式扫描完后，把栈中剩余运算符全部弹栈输出。

> [!TIP]
> 记忆口诀：**“栈外想进，栈内不让，谁大听谁”**——新来的权利大就压进去，栈里的资历老就弹出来。括号是“进去就失势，出来前要清场”。

### 一个算对了的例子

以 `a*b+c/d` 为例：

| 步 | 扫描 | 栈 | 输出 |
|----|------|-----|------|
| 1 | `a` | 空 | `a` |
| 2 | `*` | `*` | `a` |
| 3 | `b` | `*` | `a b` |
| 4 | `+`：icp=2 < isp(*)=5，弹 `*` | 空 → `+` 进栈 | `a b *` |
| 5 | `c` | `+` | `a b * c` |
| 6 | `/`：icp=4 > isp(+)=3，进栈 | `+ /` | `a b * c` |
| 7 | `d` | `+ /` | `a b * c d` |
| 8 | 结束，弹栈 | 空 | `a b * c d / +` |

所以答案：`a b * c d / +`。

再看带括号的 `(a+b)*c+d/(e+f)`：

```mermaid
flowchart LR
    A["扫描 (a+b)*c+d/(e+f)"] --> B["遇 ( 进栈"]
    B --> C["+ 进栈, ) 弹 +"]
    C --> D["* 压过栈内 ("]
    D --> E["+ 弹出 *"]
    E --> F["遇 ( 进栈, / 进栈"]
    F --> G["收尾弹空栈"]
    G --> H["ab+c*de+f/+"]
```

### 常见坑

> [!WARNING]
> **括号的优先级搞反**：如果认为 `(` 在栈内外优先级相同，扫描 `a+(b*c)` 时会误把 `(` 弹出来。必须记住 `(` 的 `icp` 高、`isp` 低。

> [!CAUTION]
> **只记“优先级相等就弹”**：对 `+ -` 和 `* /` 这类同级运算符，转后缀必须**从左到右**，因此相等时也弹栈（栈内老资格先出）。这和中缀求值表里“同级从左到右”完全一致，但初学者容易只比大小不比相等。

> [!NOTE]
> 后缀表达式不需要括号：`a+(b*c)` 与 `(a+b)*c` 转后缀后完全不同（`abc*+` 与 `ab+c*`），括号的约束已经“编码”进运算符的顺序里，这正是后缀式适合计算机计算的原因。
