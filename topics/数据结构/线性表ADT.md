# 线性表的定义与抽象数据类型（ADT）

好的，这是为你准备的《数据结构》讲解正文。

## 什么是线性表

线性表是数据结构中最基础、最常用的一种结构。你可以把它想象成一条有方向的队伍：队伍里有若干个“人”（数据元素），除了排在第一个的人没有“前一个人”，排在最后的人没有“后一个人”外，队伍里的其他每个人，都恰好有一个“前一个人”和一个“后一个人”。

更形式化地说，一个**线性表**是 $n (n \geq 0)$ 个具有相同特性的数据元素组成的有限序列，通常记作：

$$L = (a_1, a_2, …, a_i, …, a_n)$$

其中，$a_1$ 被称为**表头**，$a_n$ 被称为**表尾**。这就是线性表的**逻辑结构**——它规定的是元素之间一对一的相邻关系，不关心这些元素在内存里到底是怎么存放的。

>[!IMPORTANT]
> 线性表与前驱后继：在线性表中，除表头$a_1$无前驱、表尾$a_n$无后继外，其余任意元素$a_i$均有且仅有一个直接前驱$a_{i-1}$和一个直接后继$a_{i+1}$。这是线性结构区别于树、图等非线性结构的==核心特征==。

## 为什么要抽象成 ADT

了解了逻辑结构后，你可能会问：那我直接用代码把它写出来不就行了？这里就引出一个重要概念——**抽象数据类型（Abstract Data Type, ADT）**。

ADT 的精髓在于**接口与实现分离**。它定义了一组数据和在这组数据上允许的操作，但完全不规定这些操作具体怎么实现。这就像你使用遥控器，你只需要知道按“+号”能调高音量，而不需要关心遥控器内部是红外、蓝牙还是射频技术。

>[!TIP]
> **记忆口诀**：ADT = 一组数据模型 + 定义在该模型上的一组操作。

有了 ADT，我们就能先**抽象**地定义“线性表应该能做什么”，而不必过早陷入具体实现的细节。下面，我们以南邮课件中使用的 ADT `List` 为例来进行说明。

## 线性表的 ADT 样貌

ADT 用一套规范语言来描述数据对象和操作集。对于线性表 `List`，其 ADT 规范定义如下：

**ADT 2.1 LinearList {**

**数据对象 (Data Object):**
$D = \{ a_i \ | \ a_i \in \text{ElemSet}, i = 1,2,…,n, n \geq 0 \}$

**结构关系 (Structural Relationship):**
$R = \{ \langle a_{i-1}, a_i \rangle \ | \ a_{i-1}, a_i \in D, i=1,2,…,n \}$

**基本操作集：**
- `InitList(&L)`: 初始化，构造一个空的线性表 $L$。
- `DestroyList(&L)`: 销毁线性表 $L$。
- `ListLength(L)`: 返回表 $L$ 的长度，即元素个数。
- `GetElem(L, i, &e)`: 取值，用 $e$ 返回表 $L$ 中第 $i$ 个元素。
- `LocateElem(L, e)`: 定位，返回元素 $e$ 在表 $L$ 中的位序。
- `ListInsert(&L, i, e)`: 插入，在表 $L$ 的第 $i$ 个位置插入元素 $e$。
- `ListDelete(&L, i, &e)`: 删除，删除表 $L$ 的第 $i$ 个元素，并用 $e$ 返回其值。
- `PriorElem(L, cur_e, &pre_e)`: 求前驱，用 $pre_e$ 返回 $cur_e$ 的直接前驱。
- `NextElem(L, cur_e, &next_e)`: 求后继，用 $next_e$ 返回 $cur_e$ 的直接后继。
- `TraverseList(L)`: 遍历，依次访问 $L$ 中的每个元素。

**} // ADT LinearList**

这个 ADT 清晰地回答了“线性表是什么”和“线性表能做什么”两个问题，为后续的两种具体实现——顺序表和链表——提供了统一的接口蓝图。

## 辨析与坑点：从 ADT 到具体实现

理解了 ADT，再看一个能帮你避坑的辨析题：

“采用顺序存储结构时`Find(i,x)`操作为什么是 $O(1)$？”

这里的 `Find(i,x)` 并不是按值查找 `LocateElem`，而是指**按位置读取** `GetElem`。

- **顺序表**：采用一段连续的存储单元。它支持随机存取，只要知道首地址和每个元素的大小，第 `i` 个元素的地址可以直接计算出来：`LOC(a_i) = LOC(a_1) + (i-1) * size`。因此，访问任何一个位置的元素，时间开销是常数级的，即 ==$O(1)$==。
- **链表**：采用链式存储，结点在内存中是零散分布的。要访问第 `i` 个元素，必须从头结点开始，顺着指针域一个个往下找。因此，它的按位置读取操作时间复杂度是 ==$O(n)$==。

>[!WARNING]
> **最常见的坑**：把“按位置查找 ($O(1)$)”和“按值查找 ($O(n)$)”混为一谈。ADT 中的操作和它们在不同存储结构下的复杂度是期末考试的绝对核心。务必看清题目问的到底是 `GetElem(i)` 还是 `LocateElem(e)`！

---

**`平均移动元素个数`怎么算？**

这也是一个经典考点。假设在长度为 $n$ 的顺序表第 $i$ 个位置插入一个元素，需要将第 $i$ 到 $n$ 个元素都向后移动一位，共移动 $n-i+1$ 个元素。假设在表中任何位置插入的概率相等，即 $p_i = \frac{1}{n+1}$，则平均移动次数为：
$$E_{ins} = \frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1)$$
这个求和就是 $n + (n-1) + … + 0$，结果等于 $\frac{n(n+1)}{2}$。代入公式得平均移动次数为 $\frac{n}{2}$ 次。这就是复习提纲里“顺序表插入平均移动$\frac{n}{2}$”这个结论的由来，也是你解答相关填空题的思考过程。
