# 算法的定义、描述及五个特性

## 算法的定义与五个特性

什么是算法？简单说，==算法是求解问题的一系列有限、确定、可执行的操作步骤==。它不依赖某一种具体的编程语言——你可以用 C、Java 甚至伪代码来描述同一个算法，算法的核心逻辑不会因此改变。

为什么需要正式定义“算法”？因为不是任何一段“操作描述”都能叫算法。比如“把书架上所有的书整理整齐”就不是算法——它没有说明具体怎么整理、何时停止。数据结构课程里，我们讨论的每个操作（查找、插入、排序、建堆……）最终都要落成一个算法，所以必须先建立判断标准。

### 五个特性

一个合格的算法必须同时满足以下五个特性：

| 特性 | 含义 | 违反时的反例 |
|---|---|---|
| ==有穷性== | 步骤有限，执行必然在有限时间内结束 | `while (true) { ... }` 若无退出条件 |
| ==确定性== | 每一步的含义唯一，不可有歧义 | “取一个较大的数”——多大算大？ |
| ==可行性== | 每一步都是可通过基本运算完成的 | 把“判断命题真假”写成一步操作 |
| ==输入== | 有 0 个或多个输入 | 算法可有零输入（如打印固定表格） |
| ==输出== | 至少有 1 个输出 | 算完不返回、不打印、不写文件 |

> [!IMPORTANT]
> 判断“是不是算法”时，==有穷性==是最容易被忽略的一条。程序可以是死循环，但算法不允许——算法必须在有限步内终止。

> [!WARNING]
> “确定性”和“可行性”容易混淆。确定性关心的是**含义是否唯一**，可行性关心的是**操作能否用基本指令完成**。例如 `x = y / 0` 每一步含义都确定，但除法不可行，违反的是可行性。

### 算法与相近概念的区别

| 概念 | 区别 |
|---|---|
| 算法 vs 程序 | 程序可以不满足有穷性（如操作系统常驻进程）；算法是程序的逻辑核心，必须满足五特性 |
| 算法 vs 数据结构 | 数据结构是数据在计算机中的组织方式；算法是对这些数据执行的**操作步骤**。二者结合才构成完整解题方案 |
| 算法评价 vs 算法描述语言 | 评价看时间和空间复杂度，与用 C 还是伪代码描述**无关**，也与所用计算机软硬件环境**无关** |

> [!NOTE]
> 判断题常考：**“算法的优劣与所用计算机软硬件环境有关”是错的。** 我们讨论算法效率时，看的是它作为 n 的函数的增长趋势（渐进复杂度），而不是某台机器上跑多少秒。

### 常见误区

1. **“输入为 0 就不是算法”**——错。算法可以没有输入，但不能没有输出。
2. **“程序就是算法”**——错。程序是算法的实现，可以包含死循环或与算法无关的资源管理代码。
3. **“算法描述语言决定算法优劣”**——错。同一个算法用 C 或 Python 写，逻辑相同，复杂度相同。

### 一个例子：理解五特性与时间分析

看下面这段代码：

```c
for (i = 1; i <= n; i++)
    if (2 * i < n) y++;
```

**问题**：语句 `y++;` 执行了多少次？

这需要算出满足 $2i < n$ 的 $i$ 的个数，即 $i < \frac{n}{2}$。因为 $i$ 从 $1$ 开始取整数，所以 $i$ 的最大取值为：

- 当 $n$ 为奇数时，$i$ 可取到 $\frac{n-1}{2}$；
- 当 $n$ 为偶数时，$i$ 可取到 $\frac{n-2}{2}$。

统一写成 ==$\left\lfloor \frac{n-1}{2} \right\rfloor$== 次。

**这个例子说明了什么？** 它展示了一个算法片段中循环体的执行次数如何被**精确计算**出来——这正是分析算法时间复杂度的基础工作。同时，这段代码满足算法五特性：有穷（循环 $n$ 次结束）、确定（条件判断唯一）、可行（乘法和比较都是基本操作）、输入 $n$、输出 $y$ 的最终值。

再看一个混淆点的实例：

> 选择 1 中，选项 B 说“健壮的算法不会因非法的输入数据而出现莫名其妙的状态”——这才是正确的说法（健壮性正是对异常输入的处理能力）。而选项 A 错在“与所用计算机软硬件环境因素有关”，选项 C 错在逻辑结构应**独立于**存储结构。

> [!TIP]
> 学算法时先问自己：**有穷吗？确定吗？可行吗？输出在哪？** 这五个问题能挡住大多数概念判断的失分。
