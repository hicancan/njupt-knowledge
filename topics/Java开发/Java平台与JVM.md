# Java平台、JVM定义及编译解释执行原理

> [!IMPORTANT]
> Java平台是一种==仅由软件构成的平台==，它运行在其他基于硬件的操作系统平台之上。

## 什么是Java平台与JVM

我们平时说的“Windows平台”或“Linux平台”，通常指硬件加操作系统的组合。但Java平台不同，它纯粹是软件。为什么需要这样一个“软件平台”？因为如果程序直接编译成特定操作系统的机器码（如 `.exe`），换个系统就跑不了。Java平台通过引入一个中间层——==JVM（Java虚拟机）==，屏蔽了底层硬件和操作系统的差异。

Java平台包含两个核心组成部分：
1. **JVM**：负责执行字节码的虚拟计算机。
2. **Java API**：提供标准类库支持。

## 编译与解释执行原理

写完 `HelloWorldApp.java` 后，程序是怎么跑起来的？整个过程分为两步：先编译，后解释。

```mermaid
flowchart LR
    A["源代码 .java"] -->|javac 编译| B["字节码 .class"]
    B -->|JVM 载入| C["联接阶段"]
    C -->|解释器执行| D["输出结果"]
```

1. **编译阶段**：Java编译器将 `.java` 源程序文件编译为 `.class` 字节码文件。注意，字节码不是机器码，而是一种中间格式。
2. **运行阶段**：在运行时，Java平台中的==Java解释器==对这些字节码进行解释执行。
3. **联接阶段**：执行过程中需要的类，会在联接阶段被动态载入到运行环境中。

> [!TIP]
> 记忆口诀：“一次编译，到处运行”。`.java` 变 `.class` 靠编译，`.class` 跨平台靠 JVM 解释。

## 与相近概念的区别

初学者常把Java的执行方式和C/C++混淆，可以通过下表区分：

| 特性 | C/C++ 传统方式 | Java 平台方式 |
| :--- | :--- | :--- |
| 编译产物 | 特定平台的机器码（如 `.exe`） | 跨平台的字节码（`.class`） |
| 执行方式 | 操作系统直接执行 | JVM 解释执行字节码 |
| 跨平台性 | 需重新编译 | ==无需重新编译==，有JVM即可 |

## 常见的坑

> [!WARNING]
> 不要以为编译通过了就万事大吉！编译期只检查语法和类型错误，逻辑错误或未初始化变量导致的编译报错要仔细排查。

> [!CAUTION]
> 局部变量使用前必须初始化。例如某考题中：
> ```java
> class B {
>     public static void main(String args[]) {
>         int p;
>         int j = 10;
>         j = p; // 编译错误：p未初始化
>     }
> }
> ```
> 这里 `int p;` 声明了局部变量但未赋初值，随后 `j = p;` 尝试使用它，这会产生==1处编译错误==（选A）。这与Java平台的运行机制无关，而是编译阶段就会被拦截的语法规则。

## 经典例题解析

来看课件练习中必考的基础题：

**题目**：编译 Java Application 源程序文件将产生相应的字节码文件，这些字节码文件的扩展名为（ ）。
- A. `.java`
- B. `.class`
- C. `.html`
- D. `.exe`

**解析**：
根据Java平台工作原理，源程序文件（`.java`）经过编译器处理后，生成的目标文件格式是字节码文件。字节码文件的标准扩展名就是 `.class`。`.exe` 是 Windows 下的可执行文件，Java 不生成这种文件。

因此，正确答案是 **B**。你在 NetBeans 练习 2 中关闭“在保存时编译”后手动构建项目，在项目文件夹里找到的正是这个 `.class` 文件。
