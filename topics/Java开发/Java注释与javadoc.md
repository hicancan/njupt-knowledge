# Java注释类型及javadoc文档生成工具的使用

## 注释是什么，为什么需要

注释是写给“读代码的人”看的说明文字，==编译器会忽略注释内容，不影响程序运行==。它用于解释设计思路、参数含义、算法步骤和注意事项，也便于大作业报告中的代码分析。注释不是越多越好，应说明“为什么这样做”，而不是逐句翻译代码。

## Java 的三种注释

| 类型 | 写法 | 主要用途 | 能否被 javadoc 提取 |
|---|---|---|---|
| 单行注释 | `// 注释内容` | 解释一行或局部代码 | 否 |
| 多行注释 | `/* 注释内容 */` | 跨行说明、临时屏蔽代码 | 否 |
| 文档注释 | `/** 注释内容 */` | 描述类、方法、字段等 API | 是 |

```java
/**
 * 计算两个整数的和。
 *
 * @param a 第一个加数
 * @param b 第二个加数
 * @return 两数之和
 */
public static int add(int a, int b) {
    // 局部计算说明
    return a + b;
}
```

文档注释通常放在所说明的类、方法或字段**前面**，常用标签包括 `@param`、`@return`、`@throws`、`@author` 和 `@version`。

> [!IMPORTANT]
> 选择题中，`//`、`/*···*/`、`/**···*/` 都是可用形式；`/**···**/` 的结束符错误，正确结束符只能是 `*/`。文档注释符 `/**···*/` 是 Java 语言特有的注释符。

## 用 javadoc 生成文档

`javadoc` 是 JDK 提供的文档生成工具，它读取源文件中的文档注释，生成 HTML 格式的 API 文档。基本流程如下：

```mermaid
flowchart LR
    A["编写文档注释"] --> B["执行 javadoc"]
    B --> C["生成 HTML"]
    C --> D["浏览器查看"]
```

在命令行中可执行：

```bash
javadoc -d doc -encoding UTF-8 -charset UTF-8 Hello.java
```

其中，`-d doc` 指定输出目录，`-encoding UTF-8` 指定源文件编码，`-charset UTF-8` 指定生成网页的字符集。生成后打开 `doc/index.html` 即可浏览。若源文件使用了第三方类库，还可能需要通过 `-classpath` 指定类路径。

> [!TIP]
> 写文档注释时，先回答“它做什么”，再补充参数、返回值和异常情况；这样生成的 API 文档才真正便于调用者使用。

## 文档注释与注解的区别

文档注释以 `/**` 开头，主要供人和 `javadoc` 阅读；注解以 `@` 开头，如 `@Override`，是代码的元数据，可被编译器或其他工具处理。二者都可能出现在方法前，但作用不同：

| 对比项 | 文档注释 | 注解 |
|---|---|---|
| 典型形式 | `/** ... */` | `@Override` |
| 主要作用 | 生成说明文档 | 编译检查、代码分析等 |
| 是否改变程序逻辑 | 否 | 本身通常不直接改变逻辑 |
| 相关工具 | `javadoc` | 编译器、注解处理器等 |

`@Documented` 是元注解，表示被标注的注解类型应包含在 Javadoc 文档中；它不等于文档注释，也不会把普通 `//` 注释变成 API 文档。

> [!WARNING]
> 常见错误包括：把文档注释写成 `/**···**/`；将文档注释放错位置，导致无法关联目标方法；只写 `@param` 却漏写参数名；中文文档乱码。另一个易混点是：多行注释不能简单嵌套，内部的 `*/` 会提前结束注释。
