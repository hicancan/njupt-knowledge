# 关联类（Association Class）与多重性（Multiplicity）

> [!IMPORTANT]
> ==关联类既是关联又是类==，用于描述两个类之间联系本身所具有的属性或操作；==多重性规定了参与关联的对象个数或属性值的个数==。

## 为什么需要它们？

先看一个场景：`学生` 和 `课程` 之间存在"选课"关联。如果我们要记录某位同学选了某门课后的**成绩**，这个成绩该放在哪？

- 放在 `学生` 类里？一个学生选多门课，成绩会混在一起。
- 放在 `课程` 类里？一门课有多个学生，同样无法区分。

成绩既不属于单独的学生，也不属于单独的课程，而是属于"选课"**这个联系本身**。这就是引入 **关联类（Association Class）** 的原因。

同时，一个学生能选几门课？一门课能被几个学生选？我们需要用 **多重性（Multiplicity）** 来精确约束这种数量关系。

## 关联类怎么做

关联类在 UML 中用一条虚线将关联连线与一个类框相连来表示。它拥有普通类的特征（属性、操作），但它的实例依附于关联存在。

```mermaid
classDiagram
    class Student["学生"]
    class Course["课程"]
    class Enrollment["选课(关联类)"] {
        +成绩: float
        +选课时间: Date
    }
    Student "1" -- "0..*" Course : 选课
    Enrollment .. "选课"
```

> [!NOTE]
> 课件指出："关联本身也有特性，通过关联类可以进一步描述关联的属性、操作，以及其他信息。" 当 $M:N$ 的多重性关联需要附带额外信息时，通常就需要提取出关联类。

## 多重性的表示规则

多重性用多值表达式表示。根据课件定义，它在两类位置出现：

1. **属性的多重性**：格式为 `可视性 属性名 [多重性]: 类型 = 初始值`。其值是该类的每个实例的==属性值的个数==。例如 `- emails[0..*]: String` 表示一个对象可以有 0 到多个邮箱。
2. **关联端的多重性**：标在关联连线的两端，规定该类中有==多少个对象参与该关联==。

常见多重性表达式：

| 表达式 | 含义 |
| :---: | :--- |
| `1` | 恰好 1 个 |
| `0..1` | 0 个或 1 个 |
| `*` 或 `0..*` | 0 个或多个 |
| `1..*` | 至少 1 个 |
| `m..n` | 最少 $m$ 个，最多 $n$ 个 |

> [!TIP]
> 记忆口诀：**看线端，定边界**。读多重性时，站在关联的一端，看向另一端，问自己："这**一个**对象，对应那端**几个**对象？"

## 算对了的例子

**题目场景**：建模"公司"与"员工"的雇佣关系，需记录入职日期，且一个员工只能在一个公司任职，一个公司有多个员工。

**分析步骤**：
1. 确定类：`公司`、`员工`。
2. 确定关联：`雇佣`。公司端多重性 `1`（员工必属一家公司），员工端多重性 `1..*`（公司至少一名员工）。
3. 发现附加属性："入职日期"属于雇佣联系，故引入关联类 `雇佣记录`。

```mermaid
classDiagram
    class Company["公司"]
    class Employee["员工"]
    class HireRecord["雇佣记录"] {
        +入职日期: Date
    }
    Company "1..*" -- "1" Employee : 雇佣
    HireRecord .. "雇佣"
```

## 相近概念的区别

| 概念 | 本质 | 适用场景 |
| :--- | :--- | :--- |
| **普通关联** | 类之间的结构联系 | 不需要为联系本身附加属性 |
| **关联类** | 既是关联又是类 | $M:N$ 联系需附带专属属性/操作 |
| **限定关联** | 带有限定符的关联 | 用某个键值（如账号）在集合中唯一查找对象 |
| **自关联** | 类与自身的关联 | 同一类的两个对象间的联系（如员工的管理者也是员工） |

> [!WARNING]
> 常见坑：把关联类的属性错误地塞进参与关联的两个主类中。记住，==只要属性是由两端的对象共同决定的，就必须建关联类==。

> [!CAUTION]
> 高危误区：在二元关联中，若两端多重性都是 `1`（即 $1:1$），通常不需要关联类，直接把属性放到任意一端即可。关联类最典型的用武之地是 $M:N$ 关联。
