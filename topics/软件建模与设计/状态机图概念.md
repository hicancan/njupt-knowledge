# 状态机图（State Machine Diagram）的概念与适用场景

---

## 从一个对象的一生说起

想象一下，你正在设计一个“图书馆借阅系统”。其中，“图书”是一个核心对象。请你思考一下，一本图书从进入图书馆到最终被淘汰，它的“生命”中可能经历哪些不同的“状况”？而这些“状况”之间，又是被什么“事件”触发了改变？

这正是状态机图要回答的核心问题。

## 什么是状态机图

> [!IMPORTANT]
> 状态机图，就是一张描述一个对象（或系统元素）从生到死，在其生命周期内所有可能经历的**状态**，以及导致状态发生变化的**转移**的“地图”。

它聚焦于**一个对象**的行为，展示了它的**事件驱动**的响应过程。在 UML 的动态建模中，它和活动图、交互图是三大支柱。

### 核心元素解剖

一个完整的状态机图由以下关键元素构成：

| 核心元素 | 图形标记 | 说明 |
| :--- | :--- | :--- |
| **状态** | 圆角矩形 | 对象在生命周期中的一种状况。状态是**时段性**的，如“已借出”、“在馆内”。 |
| **转移** | 带箭头的实线 | 表示从一种状态到另一种状态的改变，通常由**事件**触发。 |
| **事件** | 标在转移线上的文字 | 引发状态改变的触发器，如 `借书()` 操作被调用。 |
| **初始状态** | 实心圆⚫ | 一个**伪状态**，表示状态机的起点。 |
| **终结状态** | 内含实心圆的圆圈⭕ | 一个**伪状态**，表示对象生命周期的终点。 |

### 深入理解状态

一个状态并非只是一个名字。为了表达更复杂的情况，我们可以使用**组合状态**。

```mermaid
stateDiagram-v2
    state “已借出” as Borrowed {
        [*] --> 正常借阅
        正常借阅 --> 即将到期
        即将到期 --> 逾期
        --
        正常借阅: 借阅天数 < 30
        即将到期: 30 <= 借阅天数 <= 45
        逾期: 借阅天数 > 45
    }
```

> [!TIP]
> **组合状态**是破解复杂状态图的利器。当一个状态内部还包含了一系列子状态及其转移时，它就是组合状态。上面的“已借出”状态便是一个组合状态，它隐藏了内部“正常”、“即将到期”、“逾期”等细节，让顶层图更清晰。不使用组合状态，这些内部转移线可能会与外部转移线交叉，使模型难以理解。

### 并发子状态

当一个对象同时有几个相互独立的行为时，我们需要用到**并发状态机图**。

```mermaid
stateDiagram-v2
    state “车辆行驶中” as Driving {
        [*] --> 引擎系统
        [*] --> 娱乐系统

        state 引擎系统 {
            [*] --> 怠速
            怠速 --> 加速
            加速 --> 怠速: 松油门
            加速 --> 巡航
            巡航 --> 加速
            巡航 --> 怠速: 退出巡航
        }
        --
        state 娱乐系统 {
            [*] --> 收音机开
            收音机开 --> 音乐播放
            音乐播放 --> 收音机开
            收音机开 --> [*]: 熄火
            音乐播放 --> [*]: 熄火
        }
    }
```

这表示汽车在“行驶中”这个大状态下，引擎和娱乐系统是**并发**工作的，互不干扰。

## 为什么需要状态机图：与活动图的区别

你可能会问：“都是描述动态行为，它和活动图有什么不同？”

这是一个非常容易混淆的点，让我们用一张表来辨析：

| 对比维度 | **状态机图** | **活动图** |
| :--- | :--- | :--- |
| **关注点** | 一个对象的**状态变迁** | 一个操作的**工作流/控制流** |
| **驱动方式** | **事件驱动** | 活动完成**自动驱动** |
| **建模视角** | 对**一个对象**的生命周期建模 | 对**一系列活动**的流程建模 |
| **典型场景** | 描述图书、订单、设备的状态变化 | 描述一次下单、一次审批的处理流程 |

> [!WARNING]
> **常见的坑**：别用状态机图去描述多个对象如何协作完成一个任务（如“用户下单”的全流程），那是交互图（如顺序图）或活动图的强项。**状态机图的镜头，永远聚焦在一个对象身上。**

## 什么时候使用状态机图

> [!NOTE]
> 状态机图特别擅长描述那些**行为明显受其当前状态影响**的对象。

这类对象通常具有以下特征：
1.  **经历了多个不同的、有意义的状态**：如订单对象有“待支付”、“已支付”、“发货中”、“已完成”等状态。
2.  **在不同状态下，对同一事件的反应不同**：例如，对“取消”这一事件，“待支付”的订单会直接取消，而“已发货”的订单则无法取消。
3.  **其行为序列对系统正确性至关重要**，最典型的就是**实时系统**和**嵌入式系统**中的控制器、通信协议等。

### 一个算对了的例子

题目：状态机类封装了什么？

A. 状态转换表
B. 状态图
C. 机器当前状态
D. ==**状态转换表和机器的当前状态**==

**解析**：一个“状态机类”在代码实现层面，其核心职责就是维护并管理状态机。它不仅需要知道所有状态之间是如何转换的（即**状态转换表**或对应的规则），还必须时刻知道自己**当前的“活动”状态**是哪一个。因为当事件到达时，它必须根据当前状态和转换规则，才能决定下一个状态是什么以及执行什么动作。
