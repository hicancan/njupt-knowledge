# 移位与循环移位指令（SHL、SHR、ROL、ROR等）

## 移位与循环移位指令

移位指令解决的问题是：如何在不使用乘除法的情况下，快速实现乘/除以 $2^n$、位提取、位拼装、串行数据收发等操作。8086 提供四类移位指令：

| 类型 | 助记符 | 操作 |
|------|--------|------|
| 逻辑左移 | `SHL` / `SAL` | 最低位补 0，最高位移入 CF |
| 逻辑右移 | `SHR` | 最高位补 0，最低位移入 CF |
| 算术右移 | `SAR` | 最高位**保持符号不变**，最低位移入 CF |
| 循环左移 | `ROL` | 最高位移入 CF **和** 最低位（首尾相接） |
| 循环右移 | `ROR` | 最低位移入 CF **和** 最高位 |
| 带进位循环左移 | `RCL` | CF 参与循环，最高位移入 CF，原 CF 进入最低位 |
| 带进位循环右移 | `RCR` | CF 参与循环，最低位移入 CF，原 CF 进入最高位 |

> [!IMPORTANT]
> 逻辑移位针对==无符号数==，空位补 0；算术右移针对==带符号数==，空位补符号位，因此 `SAR` 相当于有符号数除以 $2^n$（向下取整），而 `SHR` 才是无符号数除以 $2^n$。

**为什么需要移位指令？** 8086 的乘除法指令（`MUL`、`DIV`）执行周期长，若只乘除 2 的幂，用移位只需 2 个时钟周期/位，远快于乘法指令。此外，位操作（如读取状态寄存器某一位、拼装字节）本质上只能靠移位和逻辑运算实现。

**格式与限制**：`SHL dst, cnt`，其中 `cnt` 为 1 时直接写 `1`；大于 1 时必须用 `CL` 寄存器存放（8086 限制）。例如 `SHL AL, CL`。

**标志位影响**（南邮考点）：

- 移位指令影响 `OF, SF, ZF, PF, CF`，`AF` 未定义。
- 循环移位指令只影响 `OF` 和 `CF`。
- 移位 1 位且最高位发生变化（符号翻转）时，`OF=1`；否则 `OF=0`。移位多位时 `OF` 不定。

**常见的坑**：

> [!WARNING]
> `SAL` 与 `SHL` 在 8086 中机器码完全相同，不要纠结它们的区别。真正要区分的是 `SAR`（算术）与 `SHR`（逻辑）——对负数右移，`SAR` 补 1，`SHR` 补 0，结果完全不同。

> [!CAUTION]
> 循环移位中 `RCL/RCR` 的 CF 是==旧 CF== 参与循环，执行后 CF 变为被移出的那一位。若不先 `CLC` 清零 CF，结果会与预期不符。

### 一个算对了的例子

**题目**：写出下列指令执行后的结果。

```assembly
MOV BL, 43H
MOV AL, 0AFH
SAL AL, 2
ADD AL, BL
```

逐步推导：

1. `AL = 0AFH = 1010 1111B`，`SAL AL, 2` 逻辑左移 2 位，低 2 位补 0：
   $$1010\,1111 \xrightarrow{\text{左移2位}} 1011\,1100 = 0BCH$$
   最高两位 `10` 依次移入 CF，最后 CF=0。
2. `BL = 43H = 0100 0011B`，`ADD AL, BL`：
   $$0BCH + 43H = 0FFH$$

**结果**：`CF=0`，`AL=0FFH`，`BL=43H`（`BL` 不变）。

### 应用：位拼装

把 AL 低四位与 AH 低四位拼成一个字节（AL 低四位作高四位）：

```assembly
SHL AL, 4      ; AL 低四位移至高四位，如 0x0B → 0xB0
AND AH, 0FH    ; AH 保留低四位，如 0x3C → 0x0C
ADD AH, AL     ; 拼装结果在 AH，如 0xB0 + 0x0C = 0xBC
```

### 移位与串行通信的关联

课件中反复出现“读状态口检查发送移位寄存器是否空闲”，这正对应 UART 内部的工作方式：CPU 把数据写入发送保持寄存器后，硬件自动将其并行载入==发送移位寄存器==，再由移位寄存器按位从 TXD 引脚移出。判断“是否发完一帧”，就要查状态口的 D6 位（发送移位寄存器空标志）。类似地，接收端由==接收移位寄存器==逐位移入，拼满一个字节后移入接收缓冲寄存器，状态口 D0 位（接收数据准备好）置 1，CPU 才可读取。理解移位指令的硬件语义，有助于理解这些状态位的含义。
