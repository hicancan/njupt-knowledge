# 目标程序的生成过程（汇编、链接）

好的，我们来讲解目标程序从源代码到可执行文件的生成过程。

在南京邮电大学《微型计算机接口技术》这门课里，我们编写的 `.ASM` 汇编源文件，CPU 是无法直接读懂的。把它变成一个能在内存中运行的程序，需要经历两个核心步骤：==汇编== 和 ==链接==。

我们不妨带着两个问题来理解这个过程：
1. 我的源程序里调用了 `DOS` 中断，但 CPU 只认二进制，这个“中断号”是怎么变成最终的内存地址的？
2. 如果一个项目由多个模块组成，模块A要调用模块B里的子程序，A在编译时怎么知道B的地址？

这两个问题，正好分别对应了“汇编”和“链接”要解决的核心任务。

### 从 .ASM 到 .OBJ：汇编过程

汇编程序（如 MASM）的工作，就像一次“机械翻译”，主要完成两件事：

1.  **语法检查与指令翻译**：把助记符（如 `MOV AX, BX`）和伪指令（如 `DB`, `DUP`）逐一翻译成机器码或数据。比如 `MOV AL, 20H` 会变成 `B0 20` 两个字节。
2.  **生成目标模块(.OBJ)**：这个文件里已经包含了翻译后的二进制机器码和数据。但是，==对于那些暂时无法确定的地址，比如外部子程序或 DOS 中断的入口，它会留下一个“空洞”并做好标记==。

**常见误区**：汇编过程不解决跨模块的符号引用。它只能让所有“未解决的引用”浮出水面，并记录在案，等待下一步处理。

### 从 .OBJ 到 .EXE：链接过程

链接程序（如 LINK）像一位“装配工”，它要完成地址的重定位与模块组装：

-   **模块合并**：将你程序生成的各个 `.OBJ` 模块，以及调用的库文件（如 C 库或系统库）中的相关模块，逻辑地拼接到一起。
-   **地址重定位**：最关键的一步。链接程序根据汇编时留下的记号，把所有“空洞”填上真实的内存地址。比如，你写的 `INT 21H`，链接程序会找到对应的系统模块，将其入口地址填入你的代码中。同理，程序中 `SERVICE` 子程序的标号，也会被替换为它所在代码段中的真实偏移地址。
-   **生成可执行文件(.EXE)**：最终形成一个有完整的分段结构、重定位表，可直接被 DOS 系统加载运行的文件。

[!TIP]
**记忆技巧**：汇编做“翻译”，链接做“装配”。.OBJ 是“零件”，.EXE 是“成品整机”。

### 一个直观的例子：`DATA` 段的内存分配

我们可以结合前面复习提纲里的数据段定义，看看汇编器是如何“翻译”数据的。源代码如下：

```assembly
DATA SEGMENT USE16
    X1 DB ‘012’
    X2 DW 34H
    X3 DB 2 DUP (32), 13, 10
    X4 EQU $-X1
DATA ENDS
```

【汇编过程】`USE16` 告诉汇编器这是一个 16 位数据段。汇编器会在其内部维护一个偏移地址计数器（初值为 0），然后逐行处理并生成 `.OBJ` 文件中的数据区。
【链接过程】这个 `DATA` 段会被放入最终 `.EXE` 文件的某个段中。程序加载时，DOS 会为它分配实在的内存，并将段寄存器 `DS` 指向这个段的基址。这样，代码中通过 `OFFSET X1` 获取的偏移地址，结合 `DS`，就能精确访问到具体的数据了。

### 避坑指南与考试重点

-   **伪指令不生成机器码**：像 `EQU`、`SEGMENT`、`ENDS` 这类伪指令，是给汇编器的命令，在 `.OBJ` 和 `.EXE` 文件中没有对应的机器代码，千万不要在分析内存时给它们预留存储空间。
-   **变量是地址的替身**：`X1`, `X2` 这类变量名，本质上代表了一个内存地址（段基址：偏移地址）。在最终生成的目标码中，它们都会被替换成具体的数值。
-   **标号地址在链接时确定**：程序中的标号（如子程序名 `SERVICE`），其最终的物理地址只有在链接时才能完全确定。汇编过程只为它生成一个待重定位的条目。

以刚才的 `DATA` 段为例，它的最终内存分配图（假设段基址为 0000H）如下：

| 偏移量 (Offset) | 符号 (Variable) | 值 (内容) | 长度 (字节) |
|:----------------|:----------------|:----------|:-----------|
| 0000H | X1 | ‘0’, ‘1’, ‘2’ | 3 |
| 0003H | X2 | 34H, 00H | 2 |
| 0005H | X3 | 20H, 20H, 0DH, 0AH | 4 |
| – | X4 | 9 | (不占内存) |

-   汇编器翻译 `‘012’` 得到 `30H, 31H, 32H` 3个字节。
-   `34H` 按字存储，低地址存低位，所以是 `34H, 00H` 2个字节。
-   `2 DUP (32)` 生成两个 `20H`（32 的十六进制），`13, 10` 就是回车换行的 ASCII 码 `0DH, 0AH`，共 4 个字节。
-   `X4 EQU $-X1`：汇编器计算当前偏移地址（9）与 `X1` 偏移地址（0）的差，得到 9。 ==`EQU` 是纯文本替换，不会在内存镜像中占据任何空间。==
