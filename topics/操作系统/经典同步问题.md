# 经典进程同步问题（生产者-消费者、读者-写者、哲学家进餐）

## 它是什么

经典进程同步问题主要包含**生产者-消费者**、**读者-写者**和**哲学家进餐**三类模型。它们本质上是利用信号量（Semaphore）机制解决多进程对**临界资源**的互斥访问与**时序协调**问题。南邮考试中，重点考察如何用 $P$（wait）、$V$（signal）操作正确实现这些逻辑。

## 为什么需要

在多道程序环境下，进程并发执行会导致数据不一致或死锁。
1. **互斥**：防止多个进程同时修改共享缓冲区（如生产者-消费者）。
2. **同步**：确保操作顺序，如“先生产后消费”、“无读者时才写”。
若不加控制，会出现数据覆盖、读脏数据或系统死锁。

## 怎么做：核心模型解析

### 1. 生产者-消费者问题
这是最基础的同步互斥混合模型。需设置三个信号量：
- `mutex`：初值 1，保证对缓冲区的**互斥**访问。
- `empty`：初值 $k$（缓冲区大小），表示空位数量，用于**同步**生产者。
- `full`：初值 0，表示产品数量，用于**同步**消费者。

> [!IMPORTANT]
> ==P 操作顺序至关重要==：必须先执行资源信号量（`empty`/`full`），再执行互斥信号量（`mutex`）。若颠倒，可能导致死锁。

```mermaid
flowchart TD
    P["生产者"] -->|P(empty)| E["申请空位"]
    E -->|P(mutex)| M1["进入临界区"]
    M1 --> A["放入产品"]
    A -->|V(mutex)| L1["离开临界区"]
    L1 -->|V(full)| F["增加满位"]
    
    C["消费者"] -->|P(full)| G["申请产品"]
    G -->|P(mutex)| M2["进入临界区"]
    M2 --> R["取出产品"]
    R -->|V(mutex)| L2["离开临界区"]
    L2 -->|V(empty)| H["增加空位"]
```

### 2. 读者-写者问题
核心矛盾是：**读-读允许并行**，但**写-写、读-写必须互斥**。
通常引入计数器 `readcount` 和互斥信号量 `rw_mutex`。第一个读者负责加写锁，最后一个读者负责释放写锁。

### 3. 哲学家进餐问题
5 位哲学家围坐，左右各一支筷子。仅当左右筷子均空闲时才能进餐。
**常见解法**：限制最多 4 人同时拿左筷；或奇偶号哲学家不同取筷顺序，避免循环等待导致死锁。

## 常见的坑

| 易错点 | 正确做法 | 后果 |
| :--- | :--- | :--- |
| **P 操作顺序颠倒** | 先 `P(empty)` 后 `P(mutex)` | **死锁**：持有 mutex 等待 empty，而消费者持有 full 等待 mutex |
| **忘记 V 操作** | 临界区出口必须 V | 永久阻塞其他进程 |
| **读者写者饥饿** | 未公平调度 | 写者长期等待，或读者长期无法读取 |

> [!WARNING]
> 在综合题中，若题目要求“互斥地对缓冲区存取”，务必检查是否遗漏了 `mutex` 信号量。仅有 `empty/full` 只能保证同步，不能保证互斥。

## 算对了的例子

以真题为例：$m$ 个生产者，$n$ 个消费者，缓冲区大小 $k$。

**初始化：**
```c
semaphore empty = k; 
semaphore full = 0;   
semaphore mutex = 1;  
```

**生产者进程：**
```c
while(true) {
    produce();
    P(empty);   // 1. 申请空位（同步）
    P(mutex);   // 2. 申请锁（互斥）
    add_to_buffer();
    V(mutex);   // 3. 释放锁
    V(full);    // 4. 增加满位（同步）
}
```

**消费者进程：**
```c
while(true) {
    P(full);    // 1. 申请产品（同步）
    P(mutex);   // 2. 申请锁（互斥）
    remove_from_buffer();
    V(mutex);   // 3. 释放锁
    V(empty);   // 4. 增加空位（同步）
    consume();
}
```

==关键点==：注意 `P` 操作的成对出现顺序，以及 `V` 操作在临界区外执行以提高并发度。
