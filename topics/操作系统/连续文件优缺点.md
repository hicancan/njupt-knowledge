# 连续文件的优缺点

连续文件（顺序文件）是把逻辑文件中的信息==顺序地存储到连续的物理盘块中==的文件物理结构。在目录项里，只需记录文件的**始址**和**块数**两个信息，就能唯一定位整个文件。

为什么需要它？磁盘是机械装置，磁头移动（寻道）很慢。如果物理块挨在一起，读完一块顺势就能读下一块，几乎不需要额外寻道，这正是连续文件最大的存在价值。

## 工作原理与示例

系统怎么找到连续文件的第 $i$ 个逻辑块？直接算：

$$\text{物理块号} = \text{始址} + i$$

以南邮真题为例，文件 `tr` 的始址为 14，块数为 3：

```mermaid
flowchart LR
    D["目录:始址14"] --> B0["物理块14\n逻辑块0"]
    B0 --> B1["物理块15\n逻辑块1"]
    B1 --> B2["物理块16\n逻辑块2"]
```

> [!TIP]
> 访问逻辑块 2 时，无需遍历，直接定位到 $14 + 2 = 16$ 号物理块，既支持顺序存取，也支持随机存取。

## 优缺点剖析

> [!IMPORTANT]
> **优点**
> - **顺序存取容易**：只要知道首块地址，顺藤摸瓜即可。
> - **顺序存取速度快**：物理块在同一或相邻磁道，寻道时间最少，速度在所有物理结构中==最快==。

但硬币的另一面是什么？如果要在 `tr` 的逻辑块 0 和 1 之间插入一个新块，会发生什么？

> [!WARNING]
> **缺点**
> - **要求定量的连续存储空间**：插入新块时，原 15、16 号块必须整体后移腾出空间；若后方无足够连续空闲块，甚至要把整个文件搬走。极易产生无法利用的==外零头（外部碎片）==。
> - **必须事先估计文件的长度**：创建时需一次性申请足够大的连续区域。动态增长的文件很难预估大小，估小了装不下，估大了浪费空间。

因此，连续文件不宜存放经常被修改的用户文件或数据库文件，更适合只读或固定长度的场景。

## 与相近结构的区别

既然连续文件有这些痛点，其他物理结构是怎么解决的？

| 对比维度 | 连续文件 | 串联文件（链接文件） | 索引文件 |
| :--- | :--- | :--- | :--- |
| **物理块分布** | 必须连续 | 可离散，用指针串联 | 可离散，用索引表映射 |
| **随机存取** | 支持，$O(1)$ | ==不支持==，只能从头遍历 | 支持，查表即可 |
| **增删改** | 需大量移动数据 | 只改指针，极方便 | 只改索引表，方便 |
| **空间预知** | 必须事先估计长度 | 无需预估，动态分配 | 无需预估，动态分配 |
| **额外开销** | 无 | 指针占空间，可靠性差 | 索引表占内外存空间 |

> [!NOTE]
> 回顾真题选择题：逻辑记录按任意次序存放在不相邻存储块中的是**链接结构**（串联文件），它正是为了克服连续文件“必须连续”的缺点而诞生的。

> [!CAUTION]
> 常见误区：把“逻辑上的顺序文件”和“物理上的连续文件”混为一谈。逻辑上的顺序文件指记录按关键字有序排列，它在物理上完全可以用串联或索引结构存放；而连续文件专指物理块的连续分配方式。
