# 查表程序设计（DPTR+变址寻址）

## 为什么需要查表

有些输入输出关系很难用几条算术指令算出来，例如数码管段码、非线性函数值、ASCII 码转换。与其现场计算，不如==先把结果按顺序存成表，再用“表首地址＋偏移量”取出对应项==。这就是查表程序设计。

例如，输入数字 $x=0\sim9$，要得到共阴极数码管段码，可以建立：

```asm
TAB: DB 3FH,06H,5BH,4FH,66H
     DB 6DH,7DH,07H,7FH,6FH
```

第 $0$ 项对应数字 $0$，第 $1$ 项对应数字 $1$，所以偏移量就是输入数字本身。

## DPTR 怎样与变址寻址配合

MCS-51 常用两条查表指令：

```asm
MOVC A, @A+DPTR
MOVC A, @A+PC
```

前者是 DPTR 查表的重点。执行前：

- `DPTR` 存放**表首地址**；
- `A` 存放**相对于表首的偏移量**；
- 指令从程序存储器地址 $\text{DPTR}+\text{A}$ 读取一个字节，送入 `A`。

```mermaid
flowchart LR
    A["取得输入 x"] --> B["A ← 偏移量"]
    B --> C["DPTR ← 表首地址"]
    C --> D["MOVC 查表"]
    D --> E["A 中得到结果"]
```

注意：`MOVC` 读取的是==程序存储器==中的常数，不是片内 RAM，也不是片外数据存储器。表格通常用 `DB` 定义在代码区。

## 一个完整例子

设 `R0` 中存放数字 $0\sim9$，要求查出对应段码并送到 `P1`：

```asm
        MOV  A, R0        ; A = x，即表内偏移量
        MOV  DPTR, #TAB   ; DPTR = 表首地址
        MOVC A, @A+DPTR   ; A = 第 x 项段码
        MOV  P1, A        ; 输出段码
        SJMP $

TAB:    DB 3FH,06H,5BH,4FH,66H
        DB 6DH,7DH,07H,7FH,6FH
        END
```

若 `R0=03H`，则有效地址为 $\text{TAB}+3$，读到第 $3$ 项 `4FH`，所以最终 `A=4FH`，`P1=4FH`。这里“第 $3$ 项”从 $0$ 开始计数，对应数字 $3$。

> [!TIP]
> 写 DPTR 查表程序时记住三句话：**偏移量送 A，表首送 DPTR，MOVC 取结果**。若偏移量已在 `A` 中，不要再重复传送。

## 与相近寻址方式的区别

| 指令或方式 | 地址来源 | 主要用途 |
|---|---|---|
| `MOVC A,@A+DPTR` | $\text{DPTR}+\text{A}$ | 查程序存储器中的表 |
| `MOVC A,@A+PC` | $\text{PC}+\text{A}$ | 短距离查表，偏移处理较麻烦 |
| `MOVX A,@DPTR` | `DPTR` 所指地址 | 读片外数据存储器 |
| `MOV A,@R0` | `R0` 所指地址 | 读片内 RAM |

DPTR 查表不要求表格紧跟在指令之后，表可放在程序存储器的合适位置；`PC` 查表则受当前 `PC` 和偏移量范围影响，常需计算“表首到查表指令下一条指令”的距离。

## 常见的坑

> [!WARNING]
> `A` 中是**字节偏移量**，不是表项内容，也不一定等于十进制显示值。每项占 $n$ 个字节时，第 $x$ 项的偏移量通常为 $x\times n$；查表前还要保证索引没有越界。

例如每项为 16 位数据、占两个字节，第 $x$ 项低字节地址为 $\text{TAB}+2x$，高字节地址为 $\text{TAB}+2x+1$，不能仍用 `x` 直接查表。

> [!CAUTION]
> 不要把 `MOVC A,@A+DPTR` 写成 `MOV A,@A+DPTR`。MCS-51 没有后一种合法指令形式；查表指令执行后，==原来的偏移量会被查得的结果覆盖==，后续若还要使用索引，应提前保存。
