# 相对地址重定位方式（符号解析后的地址修改）

## 为什么需要重定位

链接器完成符号解析后，每个符号引用都已绑定到唯一定义，但各 .o 文件中的地址仍是从 0 开始的相对地址，互相重叠。重定位的任务就是把它们放到统一的虚拟地址空间中，并**回填所有引用处的地址**。

```mermaid
flowchart LR
    A["符号解析完成"] --> B["合并节 分配地址"]
    B --> C["遍历重定位条目"]
    C --> D["计算重定位值"]
    D --> E["回填引用处"]
```

> [!IMPORTANT]
> 重定位条目由汇编器生成，存放在 `.rel_text`（指令引用）或 `.rel_data`（数据引用）中；链接器只是按公式计算并回填，==PC 相对重定位的核心是"下一条指令的地址"==。

## 重定位条目与两种基本类型

| 类型 | 含义 | 典型场景 |
|---|---|---|
| `R_X86_64_64` | 64 位绝对地址 | 数据指针 `&x` |
| `R_X86_64_PC32` | 32 位 PC 相对地址 | call、jmp |
| `R_X86_64_PLT32` | 经 PLT 延迟绑定 | 调用共享库函数 |

每条目含三个关键字段：`r.offset`（引用在节内的偏移）、`r.sym`（引用的符号）、`r.addend`（修正值，常为 −4）。

## 相对地址重定位怎么做

以 `call swap` 为例。call 采用 PC 相对寻址，CPU 执行时：

$$\text{转移目标} = PC + \text{偏移量}$$

这里的 PC 是**取下一条指令时的值**，即 call 指令地址 + 5（x86-64 call 指令长 5 字节）。链接器的计算分两步：

$$PC = ADDR(s) + r.offset - r.addend$$
$$\text{重定位值} = ADDR(r.sym) - PC$$

## 一个算对了的例子

已知 `main` 代码起始地址 $0x401106$，swap 紧跟 main 后、相距 $0x1C$，故 $ADDR(swap) = 0x401122$。main.o 中：

```assembly
d: e8 00 00 00 00    call 12 <main+0x12>
e: R_X86_64_PLT32    swap-0x4
```

代入公式（$r.offset = 0xe$，$r.addend = -4$）：

$$PC = 0x401106 + 0xe - (-4) = 0x401118$$
$$\text{重定位值} = 0x401122 - 0x401118 = 0xa$$

所以重定位后 call 的机器代码为 `e8 0a 00 00 00`。

> [!TIP]
> 记法：addend 为 −4 是"提前借"了 4 字节，先把 PC 拨到下一条指令，再用"目标 − PC"求偏移，两步合并正好抵消。

> [!WARNING]
> 常见错误：把 $r.offset$ 当成 call 指令内的操作数偏移。$r.offset$ 是**重定位条目所在节的偏移**（此处 0xe 是 `e:` 行的地址），不是 call 操作数的位置；另外 PC 必须用"下一条指令地址"，用 call 自身地址会差 4。
