# 高级语言程序转换为机器代码的过程（预处理、编译、汇编、链接）

## 从源码到可执行文件：四阶段转换

当你写下 `printf("Hello")` 时，CPU 并不认识这行代码。高级语言必须经过==预处理、编译、汇编、链接==四个阶段，才能变为机器可执行的二进制指令。理解这一过程，是读懂 `objdump` 反汇编代码、解决 50 分综合题的基石。

> [!IMPORTANT]
> 核心结论：编译器生成的是==可重定位目标文件（.o）==，只有链接器才能将其与库函数合并，生成最终的可执行文件。

```mermaid
flowchart LR
    A["源程序 .c"] -->|预处理| B["修改后源码 .i"]
    B -->|编译| C["汇编代码 .s"]
    C -->|汇编| D["可重定位 .o"]
    D -->|链接| E["可执行文件"]
```

### 各阶段核心任务辨析

这四个阶段常被混淆，尤其是“编译”与“汇编”的界限。下表梳理了南邮课程中的标准术语与产物：

| 阶段 | 输入 | 输出 | 核心操作 | 关键考点 |
| :--- | :--- | :--- | :--- | :--- |
| 预处理 | `.c` | `.i` | 展开宏、包含头文件 | 纯文本替换，无语法检查 |
| 编译 | `.i` | `.s` | 语法分析、优化、生成汇编 | ==将C逻辑转为汇编指令== |
| 汇编 | `.s` | `.o` | 指令编码、符号表生成 | 生成机器码，地址未确定 |
| 链接 | `.o` + 库 | 可执行文件 | 符号解析、重定位 | 合并段、解析外部引用 |

> [!WARNING]
> 易错坑：“链接器局部符号”≠“C语言局部变量”。链接器只关心==全局/静态符号==的定义与引用，栈上的临时变量由编译器在汇编阶段通过偏移量处理，链接器完全不感知。

### 为什么需要“可重定位”？

如果每个 `.o` 文件都使用绝对地址，那么两个模块就无法合并。汇编器在遇到外部引用（如调用 `printf`）时，会生成==重定位条目==（如 `R_X86_64_PLT32`），暂时留空地址。链接器在合并时，根据符号表将这些占位符替换为真实地址或 PLT 跳转入口。

对于动态链接，共享库必须是==位置无关代码（PIC）==。加载器通过 `.interp` 段找到 `ld-linux.so`，由动态链接器在运行时完成重定位，使同一份库代码能被多个进程共享。

### 实战：从反汇编追溯源码

综合题常给出 `objdump -d` 片段让你还原逻辑。例如看到如下循环结构：

```assembly
testl %edi, %edi
jle   .L1
.L2:
movl  %edi, %eax
andl  $1, %eax
addl  %eax, %esi
shrl  %edi
testl %edi, %edi
jg    .L2
```

如何对应到 C 代码？`testl %edi, %edi` + `jle` 对应 `while (x > 0)`；`andl $1` + `addl` 对应 `if (x%2==1) y++`；`shrl` 对应无符号右移即 `x /= 2`。这正是复习提纲中 `func` 函数的汇编实现——计算二进制中 1 的个数。

> [!TIP]
> 解题技巧：看到 `shr`/`sar` 优先考虑除法或位运算；看到 `test`+条件跳转优先考虑循环或 if 判断；寄存器 `%edi`/`%esi` 通常对应前两个整型参数或局部变量。

掌握四阶段转换的本质，就能在反汇编代码与高级语言之间自由切换，这正是本课程“软硬件综合视角”的核心体现。
