# 寻址方式详细列表与举例（立即数、寄存器、存储器寻址）

## 寻址方式的核心逻辑

在 x86-64 机器级表示中，==寻址方式==决定了 CPU 如何找到指令的操作数。你可以把它想象成“取快递”的不同策略：是直接拿在手边（寄存器），还是去特定柜子取（内存绝对/基址），亦或是根据地图坐标计算位置（变址）。

为什么需要多种寻址？因为数据可能存在于寄存器、栈、堆或全局区。灵活的寻址能让编译器高效访问数组、结构体和局部变量。

> [!IMPORTANT]
> 核心结论：x86-64 通用寻址公式为 $Effective Address = Imm + R[r_b] + R[r_i] \cdot s$。其中 $s \in \{1, 2, 4, 8\}$ 为比例因子。

## 常见寻址模式对比

| 语法示例 | 有效地址 (EA) 计算 | 适用场景 |
| :--- | :--- | :--- |
| `$Imm` | 无 EA (操作数即值) | 常量初始化 |
| `%rax` | 无 EA (寄存器内) | 高速临时变量 |
| `(%rax)` | $R[\%rax]$ | 指针解引用 |
| `D(%rax)` | $D + R[\%rax]$ | 结构体成员访问 |
| `(%rax,%rdx,s)` | $R[\%rax] + R[\%rdx] \cdot s$ | 数组元素访问 `A[i]` |
| `D(%rax,%rdx,s)` | $D + R[\%rax] + R[\%rdx] \cdot s$ | 二维数组或复杂索引 |

## 典型计算实例与避坑指南

假设寄存器 `%rax=0x100`, `%rcx=0x1`, `%rdx=0x3`，内存 `M[0x100]=0xFF`, `M[0x104]=0xAB`。

**案例 1：`movl 4(%rax), %edx`**
*   **分析**：这是基址+偏移量寻址。
*   **计算**：$EA = 4 + R[\%rax] = 4 + 0x100 = 0x104$。
*   **结果**：读取 $M[0x104]$，即 `0xAB`。

**案例 2：`leaq (%rax,%rcx,4), %rdx`**
*   **分析**：`LEA` 不访问内存，只计算有效地址。
*   **计算**：$EA = R[\%rax] + R[\%rcx] \cdot 4 = 0x100 + 1 \cdot 4 = 0x104$。
*   **结果**：`%rdx` 被赋值为 `0x104`。

> [!WARNING]
> 易错坑 1：`LEA` 与 `MOV` 的区别。`LEA` 将**地址本身**存入寄存器，而 `MOV` 将**地址指向的内容**存入寄存器。
> 易错坑 2：比例因子 $s$ 只能是 1, 2, 4, 8。若看到 `(%rax,%rcx,3)` 是非法指令。
> 易错坑 3：注意数据大小后缀。`movb` 取 1 字节，`movw` 取 2 字节，`movl` 取 4 字节（高位清零），`movq` 取 8 字节。

> [!TIP]
> 记忆技巧：括号 `()` 代表“去内存里找”，没有括号代表“直接用值或寄存器”。逗号前的通常是基址（Base），逗号后带乘数的是变址（Index）。

掌握这些规则，你就能准确解析编译器生成的汇编代码，理解程序如何在底层操作数据。
