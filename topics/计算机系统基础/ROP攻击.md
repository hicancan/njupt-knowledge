# 面向返回的编程（Return-Oriented Programming, ROP）

## 它是什么

==面向返回的编程（Return-Oriented Programming, ROP）==是一种代码复用攻击：攻击者**不注入新代码**，而是把程序已有的指令片段拼接起来执行。每个片段称为 **gadget**，通常以 `ret` 结尾；攻击者通过栈溢出改写返回地址及后续栈内容，使 `ret` 不断跳到下一个 gadget。

可以把它想成“用程序自己的积木搭出攻击流程”：栈里保存的不是普通局部变量，而是一串精心安排的地址和参数。

> [!IMPORTANT]
> ROP 的核心是：==劫持控制流 + 复用已有代码 + 用 `ret` 串联 gadget==。它主要用于绕过“栈不可执行”等防护，而不是让攻击者直接向栈中写入并执行 shellcode。

## 为什么需要它

早期栈溢出攻击常把 shellcode 放进栈中，再把返回地址改成 shellcode 地址。但若启用 **NX/DEP**，栈上的数据不能作为指令执行，这种方法就会失败。

ROP 不执行栈里的数据，而是跳到代码段中已有指令，因此能绕过 NX。若再配合调用 `system`、执行 `mprotect`，或构造系统调用，就可能进一步完成攻击。

```mermaid
flowchart LR
    A["输入溢出"] --> B["改写返回地址"]
    B --> C["gadget 1"]
    C -->|"ret"| D["gadget 2"]
    D -->|"ret"| E["gadget 3"]
    E --> F["目标函数"]
```

## 怎么做

以 x86-64 Linux 为例，典型过程如下：

1. **找到溢出点**：确认输入能覆盖保存的返回地址，并计算覆盖偏移。
2. **寻找 gadget**：在可执行文件及其已加载库中寻找短指令序列，例如 `pop rdi ; ret`、`ret`。
3. **布置栈内容**：依次写入 gadget 地址、所需参数、目标函数地址等。
4. **触发返回**： vulnerable 函数执行 `ret` 后，按布置好的链条运行。

例如，希望调用 `system("/bin/sh")`，常见链条是：

```text
原返回地址 → pop rdi ; ret
下一栈单元 → "/bin/sh" 的地址
下一栈单元 → system 的地址
下一栈单元 → 退出函数地址（可选）
```

`pop rdi` 把字符串地址送入第一个整型参数寄存器 `rdi`，随后的 `ret` 再进入 `system`。

## 一个算对了的例子

某函数栈帧中，从输入缓冲区起点到保存的返回地址共 **72 字节**。已知：

- `pop rdi ; ret` 地址：`0x400123`
- 字符串 `"/bin/sh"` 地址：`0x601050`
- `system` 地址：`0x400560`

则输入布局为：

| 偏移 | 长度 | 内容 |
|---|---:|---|
| 0～71 | 72 B | 填充字符 |
| 72～79 | 8 B | `0x400123` |
| 80～87 | 8 B | `0x601050` |
| 88～95 | 8 B | `0x400560` |

函数返回时先进入 `pop rdi ; ret`，使 `rdi = 0x601050`，再跳到 `system`，效果等价于 `system("/bin/sh")`。这里的“72 字节”必须包含缓冲区、对齐空间及保存的旧 `rbp`，不能想当然地只等于数组大小。

## 和相近概念的区别

| 技术 | 是否注入代码 | 控制流如何衔接 | 主要用途 |
|---|---|---|---|
| 栈中执行 shellcode | 是 | 跳到注入代码 | 无 NX 时直接攻击 |
| ret2libc | 否 | 返回到库函数 | 调用 `system` 等函数 |
| ROP | 否 | 多个 gadget 用 `ret` 串联 | 组合更复杂的操作 |

> [!NOTE]
> ret2libc 可看作代码复用攻击的一种形式；简单 ROP 链也常把调用库函数作为最终目标，两者并非完全互斥。

## 常见的坑

> [!WARNING]
> **地址不是只写一个。** 返回地址之后往往还要放参数、下一 gadget 地址或目标函数地址；顺序错了，`ret` 就会取错地址。

- **x86-64 参数不主要靠栈传递**：前几个整型参数依次使用 `rdi、rsi、rdx、rcx、r8、r9`，所以常需要 `pop rdi ; ret`。
- **注意栈对齐**：调用某些 libc 函数前可能需插入单独的 `ret` gadget，使栈满足 16 字节对齐要求。
- **ASLR 会改变地址**：程序或库基址随机化后，硬编码运行地址可能失效；PIE 也会影响代码地址。
- **栈保护可能先拦截**：若存在 Canary，直接覆盖返回地址前通常已破坏 Canary，函数返回时会触发检查。
- **gadget 必须真实存在**：不能凭指令名称臆造地址，还要确认它确实以合适的 `ret` 等指令结束。

> [!TIP]
> 解题时按“**溢出偏移 → 控制返回地址 → 准备参数 → 串联地址 → 检查对齐与防护**”书写，比只背 `system("/bin/sh")` 更稳妥。
