# Shader Program的编译、链接与使用 (Compile, Link & Use Shader Program)

## 它是什么

在 OpenGL（特别是现代 Core Profile）中，**Shader Program（着色器程序）**是把多个 **Shader Object（着色器对象）** 编译后再链接成的可执行 GPU 程序。典型至少要写 **Vertex Shader（顶点着色器）** 和 **Fragment Shader（片元着色器）**。

> [!IMPORTANT]
> Shader Program 是链接后的 GPU 可执行程序；单个 Shader Object 只是源码编译结果，不能直接用来绘制。

## 为什么需要

固定管线早已被弃用。GPU 上“怎么变换顶点、怎么算颜色”必须由你提供代码；因此必须先把 GLSL 源码放进 Shader Object 编译，再链接为一个 Program，并设置 **uniform** 与 **attribute** 后才能 `glDrawArrays` / `glDrawElements`。

## 怎么做

流程可记为：创建 → 源码 → 编译 → 创建 Program → 附加 → 链接 → 使用。

```mermaid
flowchart LR
  A["创建Shader"] --> B["绑定源码"]
  B --> C["编译Compile"]
  C --> D["创建Program"]
  D --> E["附加Attach"]
  E --> F["链接Link"]
  F --> G["使用Use"]
```

关键 C/C++ 风格步骤：

1. `glCreateShader(type)`：`type` 为 `GL_VERTEX_SHADER` 或 `GL_FRAGMENT_SHADER`。
2. `glShaderSource(shader, 1, &src, NULL)` 再 `glCompileShader(shader)`。
3. `glCreateProgram()` 得到 program ID。
4. `glAttachShader(program, shader)` 把两个 shader 加上去。
5. `glLinkProgram(program)`。
6. `glUseProgram(program)` 后，该 program 进入 **current program** 状态。

> [!TIP]
> 记忆：先 compile object，再 link program；==顺序不能反==。

## 和相近概念的区别

| 概念 | 含义 | 能否直接绘制 |
|---|---|---|
| Shader Object | 单个阶段编译结果 | 不能 |
| Shader Program | 链接后的完整管线程序 | 能 |
| VAO | 顶点属性配置状态 | 不能，只配合 Program |

> [!NOTE]
> Program 决定“算什么”，VAO 决定“数据怎么送进 attribute”。二者必须都正确才有画面。

## 常见的坑

- 编译/链接后不查日志：`glGetShaderiv(id, GL_COMPILE_STATUS, &ok)` 与 `glGetProgramiv(id, GL_LINK_STATUS, &ok)` 必做。
- 忘记 `glUseProgram`：写了 uniform 也不生效，因为修改作用于 0 号 program。
- attribute 未绑定 location：可用 `glGetAttribLocation` 或 layout 限定符。
- 链接后 detach 误区：==链接成功即可使用，不强制 detach==。
