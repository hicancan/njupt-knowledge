# MIPS五级流水线方式（IF、ID、EX、MEM、WB）与流水线寄存器

## 五级流水线是什么

把一条指令的执行过程分成 5 个阶段，每个阶段在一个时钟周期内完成，不同阶段使用不同的硬件部件，多条指令像工厂流水线一样重叠执行：

| 阶段 | 名称 | 主要工作 |
|---|---|---|
| IF | 取指令 | 按 PC 从指令存储器取指令，PC+4 |
| ID | 译码 | 译码、读寄存器堆、生成立即数 |
| EX | 执行 | ALU 运算，或计算访存有效地址、分支目标 |
| MEM | 访存 | load/store 访问数据存储器，其他指令直接通过 |
| WB | 写回 | 把 ALU 结果或读出的数据写回寄存器堆 |

```mermaid
flowchart LR
    IF["IF 取指"] --> ID["ID 译码"]
    ID --> EX["EX 执行"]
    EX --> MEM["MEM 访存"]
    MEM --> WB["WB 写回"]
```

> [!IMPORTANT]
> 流水线提高的是==指令吞吐率==，并不缩短单条指令的执行时间。理想情况下，每个时钟周期完成一条指令，即 $CPI \approx 1$；加速来自**时间并行**，而不是把一条指令拆快了。

## 为什么需要流水线寄存器

相邻阶段之间插入 **IF/ID、ID/EX、EX/MEM、MEM/WB** 四组流水线寄存器，在每个时钟周期末锁存上一段的全部结果，再交给下一段。它们保存的不只是数据，还包括：

- **PC 与指令**：如 IF/ID 保存 PC+4 和取出的指令；
- **数据信息**：寄存器读出的操作数、立即数、ALU 结果、访存地址、load 读出的数据；
- **控制信息**：该指令后续各段要用的控制信号，随指令逐级传递，例如 RegWrite 要一直传到 WB，MemRead/MemWrite 只需传到 MEM。

没有这些寄存器，后一条指令的信号会覆盖前一条指令的中间结果，各段无法独立并行工作。

```mermaid
flowchart LR
    A["IF"] --> R1["IF/ID"]
    R1 --> B["ID"]
    B --> R2["ID/EX"]
    R2 --> C["EX"]
    C --> R3["EX/MEM"]
    R3 --> D["MEM"]
    D --> R4["MEM/WB"]
    R4 --> E["WB"]
```

## 时空图与性能计算

课件中的三条指令时空图如下（每格一个时钟周期）：

| 指令 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| ADD | IF | ID | EX | MEM | WB | | |
| SUB | | IF | ID | EX | MEM | WB | |
| AND | | | IF | ID | EX | MEM | WB |

**算对的例子**：$n$ 条指令在理想五级流水线中需要
$$T = (n+4)\,\Delta t$$
（第一条用满 5 拍，之后每拍流出一条）。上例 $n=3$，共 $3+4=7$ 拍，与表格一致；非流水线串行执行需 $3\times5=15$ 拍。当 $n$ 很大时，加速比趋近于 5。

## 相关与相近概念辨析

影响流水线性能的因素主要是三类相关：**结构相关**（硬件资源冲突，如单端口存储器同时取指和访存）、**数据相关**（后条指令要用前条尚未写回的结果，常用转发/旁路，必要时插入气泡）、**控制相关**（分支改变 PC，可用分支预测、延迟槽等）。

| 概念 | 区别要点 |
|---|---|
| 流水线 vs 超标量 | 流水线是时间并行；超标量靠多套部件**空间并行**，一拍发射多条指令 |
| 流水 CPU vs RISC | 流水线**不一定是** RISC，也不等于多媒体 CPU；它是经济实用的时间并行技术 |
| 吞吐率 vs 单条延迟 | 加上流水线寄存器开销后，单条指令延迟甚至可能变长 |

> [!WARNING]
> 常见坑：① 说“流水线使每条指令执行更快”——错，是吞吐率提高；② 理想 $CPI=1$ 当成永远成立——相关引起的停顿会使实际 $CPI>1$；③ 把 WB 当成每条指令都必须写寄存器——store、分支等并无寄存器写回，MEM 段也并非每条都真正访存；④ 忘记流水线寄存器还要传递**控制信号**。

> [!TIP]
> 简答“提高整机速度的措施”中，控制器方面就写“指令流水线提高吞吐率”和“超标量多发射”，并与 Cache、多体并行存储器、快速运算部件、DMA、多总线等并列作答。
