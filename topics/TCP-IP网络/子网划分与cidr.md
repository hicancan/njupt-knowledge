# 子网划分与 CIDR 无类别域间路由

## 从字节边界到任意位掩码

在深入子网划分与 CIDR 之前，不妨先思考一个问题：为什么早期 C 语言中的 `in_addr` 被设计为一个包含 `s_net`、`s_host` 等字段的结构体，而不是直接用一个 32 位整数？

> [!IMPORTANT]
> ==核心原因==：在 RFC 950 引入子网划分之前，IP 地址的网络部分和主机部分**严格对齐在字节边界上**。

早期的 A/B/C 类地址中，网络号总是占据完整的 8 位、16 位或 24 位。因此，程序员可以通过宏直接按字节或字访问特定字段，这对应了当时 TCP/IP 网络的物理结构。然而，随着子网划分（Subnetting）和无类别域间路由（CIDR/Supernetting）的出现，网络前缀长度可以是任意位数（如 /20、/27），==基于字节的划分彻底过时==，现代编程中 `sin_addr` 通常仅作为 32 位整型处理。

## 子网划分与 CIDR 的核心机制

子网划分是在原有 IP 地址基础上“借用”主机位作为子网位，而 CIDR 则打破了分类地址的束缚，使用**前缀长度**（Prefix Length）统一表示网络范围。

```mermaid
flowchart LR
    A["传统分类地址"] -->|"RFC 950"| B["子网划分"]
    B -->|"打破字节边界"| C["CIDR/超网"]
    C -->|"任意位前缀"| D["聚合路由"]
```

| 特性 | 传统分类寻址 | 子网划分 (RFC 950) | CIDR / 超网 |
| :--- | :--- | :--- | :--- |
| 边界规则 | 固定字节边界 | 借主机位，仍受类限制 | ==任意位前缀== |
| 掩码形式 | 默认掩码 | 自定义子网掩码 | 前缀表示法 (/n) |
| 路由效率 | 低，表项膨胀 | 中等 | 高，支持路由聚合 |
| `in_addr` 访问 | 结构体宏访问 | 过渡期混合使用 | 纯 32 位整数运算 |

> [!TIP]
> 计算子网时牢记公式：可用主机数 = $2^{(32-n)} - 2$（全 0 为网络地址，全 1 为广播地址）。CIDR 聚合时，只需检查连续 IP 块是否能合并为更大的 $2^k$ 对齐块。

## 历史考题中的概念验证

回顾课件中的经典选择题：为什么 `sockaddr_in` 中的 `sin_addr` 最初定义为结构体？正确答案是 **B. 因为当时网络部分和主机部分必须在字节边界上**。这道题精准考察了从“字节对齐”到“位级掩码”的演进逻辑。如果误选 C（支持子网掩码灵活配置），则混淆了因果关系——==结构体设计是为了适应旧的字节边界，而非为了支持新的子网技术==。恰恰相反，正是子网和 CIDR 的普及，使得这种结构体访问方式变得不再必要。

> [!WARNING]
> 常见误区：认为 CIDR 只是“更灵活的子网划分”。实际上 CIDR 还包含了**超网（Supernetting）** 概念，即把多个小网络聚合成一个大前缀以减少全球路由表条目，这是单纯子网划分无法实现的。

> [!NOTE]
> 在现代 Socket 编程中，虽然 `sockaddr_in` 结构体仍被保留以维持 API 兼容性，但实际操作 IP 地址时应始终使用 `inet_pton()` / `inet_ntop()` 等函数进行转换，避免手动操作 `s_addr` 的字节序问题。
