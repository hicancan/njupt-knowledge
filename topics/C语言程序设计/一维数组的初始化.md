# 一维数组的初始化方法及长度省略规则

## 一维数组初始化与长度省略

在定义数组时，我们是否必须手动数清元素个数再填入方括号？如果后续增减数据，如何避免反复修改长度导致越界或未初始化？C 语言提供了==初始化列表自动推导长度==的机制来解决这一痛点。

### 基本语法与自动推导

当使用 `{}` 对数组进行完整初始化时，可以省略方括号内的长度，编译器会根据初值个数自动确定数组大小：

```c
int a[] = {1, 2, 3};      // ✅ 等价于 int a[3]
int b[5] = {1, 2};        // ✅ 剩余3个元素自动补0
int c[3] = {1, 2, 3, 4};  // ❌ 初值个数超过声明长度，编译报错
int d[];                  // ❌ 未提供初值时不能省略长度
```

> [!IMPORTANT]
> ==只有在使用初始化列表时才能省略长度==。若仅声明 `int a[];` 而不赋初值，编译器无法推断大小，将直接报错。

### 部分初始化的零填充规则

当显式指定了长度但初值不足时，C 语言保证==剩余元素自动初始化为 0==（对于整型）或 `\0`（对于字符型）。这与局部变量未初始化时的随机值完全不同：

| 写法 | 实际存储内容 | 说明 |
| :--- | :--- | :--- |
| `int a[5]={1,2};` | `{1,2,0,0,0}` | 后3位自动补0 |
| `int a[]={1,2};` | `{1,2}` | 长度推导为2 |
| `int a[3]={0};` | `{0,0,0}` | 全零初始化的简写 |
| `int a[3];` | 不确定值 | 未初始化，不可靠 |

> [!TIP]
> 想将整个数组清零？只需写 `int a[N] = {0};`，无需逐个赋值。这是南邮考试中高频出现的==数组清零惯用法==。

### 真题中的长度推导计算

来看一道典型填空题：若有说明 `int a[][4]={{1,2},{3,5},{6,7},{0}};`，则数组第一维大小为多少？

虽然这是二维数组，但其核心逻辑与一维相同：==编译器按第二维宽度分行，行数由初值组数决定==。花括号内有 4 组初值，即使最后一组只有 1 个元素，仍占据完整一行，因此第一维大小为 **4**。

> [!WARNING]
> 切勿将“元素总个数÷列数”作为唯一判断依据。上例共 7 个数值，$7 \div 4 = 1.75$，向上取整得 2，但正确答案是 4。==嵌套花括号的组数才是行数的直接依据==，而非简单除法。

### 常见错误辨析

以下三种写法在考试中频繁作为干扰项出现：

-   `int a[3]={,2,};` → ❌ 初始化列表中不允许出现连续逗号或首尾悬空逗号
-   `int a[]={};` → ❌ 空初始化列表在 C89/C99 标准中不合法（C23 才允许）
-   `int n=3; int a[n]={1,2,3};` → ❌ ==变长数组（VLA）不允许带初始化列表==，长度必须是常量表达式

> [!CAUTION]
> 选择题中若出现 `int a[3]={1,2,3,4}` 这类初值超长的选项，无论其他选项多可疑，该选项==必定错误==。编译器不会截断多余值，而是直接拒绝编译。

掌握以上规则后，面对数组初始化类题目，只需依次检查：**有无初值→长度是否匹配→花括号语法是否合法→剩余元素补零逻辑**，即可快速锁定正确答案。
