# 文本文件和二进制文件的区别

## 为什么要区分这两种文件？

先在脑中做一个实验：假如要把整数 `2024` 存到文件里，你会怎么存？

- **办法一**：把它看成 `'2'`、`'0'`、`'2'`、`'4'` 四个字符，依次存入。任何一个文本编辑器都能打开并显示 `2024`。
- **办法二**：把 `2024` 直接按 `int` 型的二进制形式存进去，占 4 个字节。用文本编辑器打开，你看到的可能是一串乱码。

这就是文本文件和二进制文件最根本的区别：==文本文件存的是“字符”，二进制文件存的是“内存中的二进制映像”==。

C 语言把文件看成**数据流**，按数据在流中的组织形式，分成两类：

- **文本文件**（也称 ASCII 文件）：每个字节存放一个字符的 ASCII 码，内容可直接阅读。存数字 `2024` 实际存了 4 个字节：`0x32 0x30 0x32 0x34`。
- **二进制文件**：按数据在内存中的原样存储，不经过字符转换。存 `int` 型 `2024` 只占 4 个字节（具体值依赖系统字节序），内容是它内部的二进制形式。

> [!IMPORTANT]
> 文本文件存储时进行“数值 → 字符串”的转换，读写都要经过转换层；二进制文件则原样搬运，==速度快、体积小，但不可直接阅读==。

## 如何用 `fopen` 指定文件类型？

`fopen` 的第二个参数（打开方式）不只是“读还是写”，还隐含了==以哪种文件类型打开==。

基本模式：
- `r` – 只读
- `w` – 只写（新建/清空）
- `a` – 追加

修饰符：
- `b` – 以**二进制**方式打开
- `+` – 允许**同时读和写**

| 方式  | 含义 |
|-------|------|
| `"r"` 或 `"rt"` | 只读，文本文件 |
| `"w"` 或 `"wt"` | 只写，文本文件（新建） |
| `"a"` 或 `"at"` | 追加，文本文件 |
| `"r+"` 或 `"rt+"` | 读写，==旧==文本文件（必须存在） |
| `"w+"` 或 `"wt+"` | 读写，==新==文本文件（创建或清空） |
| `"a+"` 或 `"at+"` | 读 + 末尾追加，文本文件 |
| `"rb"` `"wb"` `"ab"` | 对应上面的二进制版本 |
| `"rb+"` `"wb+"` `"ab+"` | 对应上面的读写，二进制版 |

> [!WARNING]
> 打开**新文件且要既能读又能写，必须用 `"w+"`**（文本）或 `"wb+"`（二进制）。`"r+"` 只能打开**已存在的文件**，文件不存在会直接失败。

所以，若考题问“打开一个新的文本文件，既能读又能写”，正确答案是 `"w+"`。

## 字符读写 vs 二进制读写

文本文件常用**字符级**读写：
- `fgetc(fp)` – 读一个字符
- `fputc(c, fp)` – 写一个字符

这些函数操作的单位是 `char`，适合逐字符处理文本。

二进制文件则用**数据块级**读写：
- `fread(buffer, size, count, fp)` – 一次读一块
- `fwrite(buffer, size, count, fp)` – 一次写一块

它们直接搬运内存数据，常用于结构体整体存取。

> [!TIP]
> 记住口诀：**“文本字符，二进制块；新建读写选 `w+`，旧文件读写 `r+` 来。”**

## 一个完整的例子

把学生信息用两种方式分别存入文件：

```c
#include <stdio.h>

typedef struct {
    char name[20];
    int age;
} Student;

int main() {
    Student s = {"Alice", 20};
    FILE *fp;

    // 文本方式写入（需手动格式化）
    fp = fopen("stu.txt", "w");
    fprintf(fp, "%s %d", s.name, s.age);
    fclose(fp);

    // 二进制方式写入（整块写，size=sizeof(Student)）
    fp = fopen("stu.dat", "wb");
    fwrite(&s, sizeof(Student), 1, fp);
    fclose(fp);

    return 0;
}
```

- `stu.txt` 打开后看到 `Alice 20`，占 8 个字节（含空格）。
- `stu.dat` 打开后乱码，但刚好 `sizeof(Student)` 字节（通常 24 字节，含对齐填充）。

> [!NOTE]
> 当结构体含 `int`、数组等复杂成员时，==二进制读写比格式化文本读写更简单、更精确==——你不需要操心字段分隔、类型转换，也不用担心读取时解析出错。缺点是可移植性稍差（不同平台上 `int` 大小/字节序可能不同）。

## 常见陷阱

1. **用错打开方式**：拿文本方式 (`"r"`) 去读二进制文件（`fread`），虽然有时能跑，但 Windows 对文本模式会做 `\n` ↔ `\r\n` 转换，导致==数据损坏==。
2. **文件结束判断**：二进制文件不能用 `EOF`（`-1`），因为文件中完全可能出现值为 `0xFF` 的单字节，转换成 `int` 后误判为结束。==必须用 `feof(fp)`==。
3. **忘记用 `b`**：默认就是文本模式。只要明确操作二进制，就写上 `"rb"` / `"wb"`，避免跨平台坑。
