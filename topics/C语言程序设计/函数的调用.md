# 函数的调用形式与实际参数

## 调用形式与“实参长什么样”

调用一个有参函数时，你需要给出三样东西：**函数名**、一对圆括号，以及圆括号里用逗号分隔的**实际参数（实参）**：

```c
函数名(实参1, 实参2, …);
```

实参可以是常量、变量、表达式，甚至是另一个函数的返回值。程序执行到这行时，会先计算每个实参的值，再跳转到函数体内部。

> [!IMPORTANT]
> ==实参是用来初始化形参的值，不是把变量本身“传进去”==。你在调用处写的是实实在在的数据或表达式计算结果，函数拿到的只是一个副本。

## 为什么需要关注调用形式

同一个函数，传不同实参会得到不同结果——这本身就是函数复用的意义。但很多 bug 的根源在于：**你以为传的是“那个变量”，实际上只传了它的值；你以为传了三个参数，实际上逗号表达式把多个参数压成了一个。**

## 实参的求值顺序与常见坑

### 坑 1：逗号表达式让实参个数“背叛”你的眼睛

```c
func((exp1, exp2), exp3, (exp4, exp5));
```

圆括号里的逗号是**逗号运算符**，取最后一个表达式的值；括号外的逗号才是分隔实参的语法符号。所以上面这行实际上有 **3 个实参**：

1. `(exp1, exp2)` → 整个括号的结果
2. `exp3`
3. `(exp4, exp5)` → 整个括号的结果

> [!CAUTION]
> 函数的实参列表用逗号分隔，逗号运算符的优先级比它更低。不加外层圆括号时，`exp1, exp2` 会被误当成两个实参。

### 坑 2：实参求值顺序是不确定的（C 标准未规定）

C 标准没有规定实参是从左往右还是从右往左计算。你唯一能确定的，是**所有实参在函数体执行前一定全部求值完毕**。

> [!WARNING]
> 不要在同一调用里写多个依赖彼此副作用的实参，比如 `fun(i++, i++)`——结果随编译器不同而不同，是未定义行为。

## 一个算得清的真题

```c
int fun(int x, int y) { return (x + y); }

int main() {
    int a = 2, b = 3, c = 4, sum;
    sum = fun((a++, b++, a + b), c++);
    printf("%d\n", sum);
    return 0;
}
```

我们来一步步拆解实参的计算过程：

**参数 1：`(a++, b++, a + b)` —— 逗号表达式**

- `a++` → 取值 2，随后 a 自增为 3
- `b++` → 取值 3，随后 b 自增为 4
- `a + b` → 3 + 4 = **7**（逗号表达式最终取值）

**参数 2：`c++`**

- 后缀自增：取值 4，随后 c 自增为 5
- 传给形参 y 的值是 **4**

调用等价于 `fun(7, 4)`，返回 7 + 4 = **11**。

## 形参与实参的类型必须“兼容”

编译器在调用时会检查实参类型是否==可以赋值给形参类型==。不兼容时，要么报警告，要么直接报错。

```c
void prt_char();   // 声明无返回值
int k = prt_char(5); // 试图用 void 函数的“返回值”赋值 → 矛盾
```

> [!NOTE]
> 调用处的“接收返回值”与声明处的“不返回”产生冲突，这就是语法／语义错误的典型来源。

## 一句话小结

==调用形式决定实参如何被解析和传递；实参的“长相”（常量、变量、逗号表达式）直接影响参数个数和最终计算值——宁可多写一对圆括号明确边界，也别让编译器替你“猜”。==
