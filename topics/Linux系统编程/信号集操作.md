# 信号集操作函数（sigemptyset、sigaddset）与信号屏蔽

## 什么是信号集与信号屏蔽

Linux 中，每个进程都有一个==信号屏蔽字（signal mask）==，用于决定哪些信号暂时被阻塞。信号屏蔽字本质上是一个“信号集合”。

信号集操作函数用于创建、添加和检查这个集合：

- `sigemptyset()`：把信号集初始化为空集。
- `sigaddset()`：把一个信号加入信号集。
- `sigdelset()`：从信号集中删除一个信号。
- `sigismember()`：判断某信号是否在集合中。

在 Linux 中，信号编号通常使用 `SIGINT`、`SIGTERM` 等宏表示；调用函数时需要使用对应的整数编号，例如 `SIGINT` 本身就是适合传入的整型常量。

## 为什么需要信号屏蔽

进程可能正在保存文件、修改关键数据结构或执行不可中断的操作。此时即使收到终止信号，也不希望程序立刻退出，因此可以先暂时屏蔽这些信号，处理完当前工作后再解除屏蔽。

典型场景是父进程等待子进程结束：

1. 父进程屏蔽 `SIGCHLD`；
2. 创建子进程；
3. 父进程继续执行其他工作；
4. 解除对 `SIGCHLD` 的屏蔽；
5. 通过 `sigwait()`、`sigtimedwait()` 或信号处理函数回收子进程。

```mermaid
flowchart LR
    A["屏蔽 SIGCHLD"] --> B["创建子进程"]
    B --> C["执行父进程任务"]
    C --> D["解除屏蔽"]
    D --> E["等待并处理 SIGCHLD"]
```

> [!IMPORTANT]
> ==信号屏蔽只表示“暂时不递送”，不会丢弃该信号。==

如果一个已被屏蔽的信号多次到达，一般会合并记录；解除屏蔽后，进程仍可能收到这个待处理信号。

## 怎么使用信号集函数

相关函数声明在：

```c
#include <signal.h>
```

一个常见写法如下：

```c
sigset_t mask;

sigemptyset(&mask);          // 清空信号集
sigaddset(&mask, SIGCHLD);  // 加入 SIGCHLD
sigprocmask(SIG_BLOCK, &mask, NULL); // 屏蔽集合中的信号
```

`sigprocmask()` 的典型操作有：

| 操作 | 含义 |
|---|---|
| `SIG_BLOCK` | 将 `set` 中的信号加入当前屏蔽字 |
| `SIG_UNBLOCK` | 从当前屏蔽字中删除 `set` 中的信号 |
| `SIG_SETMASK` | 用 `set` 完整替换当前屏蔽字 |

程序中还可以使用 `pthread_sigmask()` 设置线程的信号屏蔽字。Linux 线程属于同一进程组，但==每个线程都有独立的信号屏蔽字==。

> [!TIP]
> 初始化顺序要记牢：先 `sigemptyset()`，再 `sigaddset()`。  
> 常见口诀：**“先清空，再加入；空集不是未初始化。”**

## 与相近概念的区别

| 概念 | 作用 |
|---|---|
| 信号屏蔽 | 暂时阻止信号递送给进程或线程 |
| 信号忽略 | 递送后直接丢弃，通常不执行处理函数 |
| 信号默认动作 | 按系统规定处理，如多数终止信号终止进程 |
| 信号处理函数 | 信号递送后执行用户指定的代码 |
| 信号 pending | 信号已到达，但因屏蔽而尚未递送 |

屏蔽和忽略尤其容易混淆：屏蔽是在递送之前拦住信号；忽略是在递送之后让系统丢弃它。

## 常见坑

> [!WARNING]
> 不要把“信号集为空”当成“信号集未初始化”。`sigemptyset()` 是清空集合；未初始化的内存可能包含随机值。

另一个常见错误是只屏蔽 `SIGCHLD`，却没有在解除屏蔽后处理子进程。更稳妥的做法通常是先屏蔽，再创建子进程，并在适当时机解除屏蔽和调用 `wait()` 或 `waitpid()`。

> [!CAUTION]
> `sigaddset()` 的第二个参数应使用 `SIGCHLD` 等信号宏，不要随意把信号编号当成字符编号。

## 算对了的例子

假设程序要等待子进程退出，希望避免 `SIGCHLD` 在等待期间打断 `waitpid()`：

```c
sigset_t mask, oldmask;
pid_t pid;

sigemptyset(&mask);
sigaddset(&mask, SIGCHLD);

sigprocmask(SIG_BLOCK, &mask, &oldmask);

pid = fork();
if (pid == 0) {
    /* 子进程工作 */
    _exit(0);
}

/* 父进程执行其他任务 */

sigprocmask(SIG_SETMASK, &oldmask, NULL);

while (waitpid(pid, NULL, 0) == -1) {
    /* 处理被信号中断等情况 */
}
```

这里 `oldmask` 保存原来的屏蔽字，最后用 `SIG_SETMASK` 恢复，避免程序退出时仍遗留额外的屏蔽设置。整个过程的关键是：==信号集负责描述“屏蔽哪些信号”，`sigprocmask()` 才负责把集合应用到当前进程或线程。==
