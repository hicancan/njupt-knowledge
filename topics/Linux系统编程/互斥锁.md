# 互斥锁pthread_mutex_t的初始化、加锁与解锁

## 它是什么与为什么需要

在《Linux编程》第4章多线程编程里，多个线程常常共享全局变量或堆内存。如果同时读写，就会出现==竞态条件==（race condition），结果依赖线程调度顺序。`pthread_mutex_t` 就是 Pthread 提供的互斥锁类型，用来保护==临界区==，保证任一时刻只有一个线程进入。

先想一个问题：两个线程都执行 `cnt++`（读—改—写三步），不加锁为什么结果可能小于预期？因为它们会覆盖彼此的写入。

## 怎么做：初始化、加锁、解锁

```mermaid
flowchart LR
  A["pthread_mutex_init"] --> B["pthread_mutex_lock"]
  B --> C["临界区 cnt++"]
  C --> D["pthread_mutex_unlock"]
  D --> E["pthread_mutex_destroy"]
```

步骤与接口：

| 操作 | 函数原型要点 | 说明 |
|------|--------------|------|
| 初始化 | `pthread_mutex_init(&m, NULL)` | 动态初始化，属性默认 |
| 静态初始化 | `PTHREAD_MUTEX_INITIALIZER` | 全局/静态锁可直接赋值 |
| 加锁 | `pthread_mutex_lock(&m)` | 阻塞直到拿到锁 |
| 解锁 | `pthread_mutex_unlock(&m)` | 必须由==加锁线程==释放 |
| 销毁 | `pthread_mutex_destroy(&m)` | 释放资源 |

> [!IMPORTANT]
> 核心结论：`lock` 与 `unlock` 必须成对出现，且解锁者必须是加锁者。

## 相近概念区别

| 概念 | 用途 | 是否睡眠等待 |
|------|------|--------------|
| `pthread_mutex_t` | 互斥访问临界区 | 阻塞睡眠 |
| 自旋锁 | 短临界区忙等 | 不睡眠，耗CPU |

## 常见坑

> [!WARNING]
> 忘记 `unlock` 会导致其他线程永久阻塞；在临界区内再次 `lock` 同一把普通锁会==死锁==。

## 算对了的例子

两线程各加 $N$ 次全局 `cnt`，互斥保护后最终结果恒为 $2N$。

```c
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
int cnt = 0;
void* add(void* arg){
  for(int i=0;i<N;i++){
    pthread_mutex_lock(&m);
    cnt++;              // 临界区
    pthread_mutex_unlock(&m);
  }
  return NULL;
}
```

> [!TIP]
> 记忆：锁加在尽量小的临界区前后，像“进门落锁、出门解锁”。

用 `gcc -pthread` 编译。以上覆盖初始化、加锁、解锁与静态初始化写法，符合课件术语与考查方式。
