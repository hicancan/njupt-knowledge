# 无名管道pipe()的创建与半双工通信

## 它是什么

无名管道是 Linux 提供的一种**进程间通信（IPC）**机制，本质是内核维护的一块环形缓冲区。它用于在**有亲缘关系的进程**之间传递字节流，最典型的是父子进程。

`pipe()` 的函数原型为：

```c
#include <unistd.h>

int pipe(int pipefd[2]);
```

调用成功后，`pipefd[0]` 是读端，`pipefd[1]` 是写端；失败返回 `-1`，成功返回 `0`。

> [!IMPORTANT]
> 无名管道是==半双工、单向、字节流==通信：数据只能从写端流向读端，不能在同一管道中反向传输。

可以把管道记成：

```text
pipefd[1]（写端） → 内核管道缓冲区 → pipefd[0]（读端）
```

## 为什么需要它

`fork()` 后，父子进程拥有独立的用户地址空间，一个进程修改普通变量，另一个进程通常看不到。因此，父进程不能简单地靠全局变量把数据“传”给子进程。

但 `fork()` 会复制父进程的文件描述符表。若父进程先调用 `pipe()`，再调用 `fork()`，父子进程就会持有指向同一管道读、写端的描述符，从而可以通信。

```mermaid
flowchart LR
    P["父进程"] -->|"pipe()"| K["创建管道"]
    K --> F["fork()"]
    F --> PW["父留写端"]
    F --> CR["子留读端"]
    PW -->|"write()"| B["内核缓冲区"]
    B -->|"read()"| CR
```

## 怎么做

以“父进程发送、子进程接收”为例：

```c
#include <unistd.h>
#include <string.h>
#include <stdio.h>

int main(void)
{
    int fd[2];
    char buf[100];

    if (pipe(fd) == -1) {
        perror("pipe");
        return 1;
    }

    if (fork() == 0) {          /* 子进程 */
        close(fd[1]);           /* 不写入，关闭写端 */
        ssize_t n = read(fd[0], buf, sizeof(buf) - 1);
        if (n > 0) {
            buf[n] = '\0';
            printf("child: %s\n", buf);
        }
        close(fd[0]);
    } else {                    /* 父进程 */
        close(fd[0]);           /* 不读取，关闭读端 */
        const char msg[] = "hello pipe";
        write(fd[1], msg, strlen(msg));
        close(fd[1]);           /* 写完后关闭写端 */
    }
    return 0;
}
```

关键顺序是：==先 `pipe()`，后 `fork()`，再关闭各进程不用的端口==。

若需要父子进程双向通信，应创建两个管道：

| 管道 | 父进程 | 子进程 | 数据方向 |
|---|---|---|---|
| 管道 A | 写 | 读 | 父 → 子 |
| 管道 B | 读 | 写 | 子 → 父 |

## 一个算对了的例子

父进程写入字符串 `"NUPT"`，不包含字符串末尾的 `'\0'`，则：

```c
write(fd[1], "NUPT", 4);
```

子进程执行：

```c
char buf[10];
ssize_t n = read(fd[0], buf, sizeof(buf));
```

若管道中这 4 字节可用且读取成功，则 `n == 4`，`buf[0]` 到 `buf[3]` 依次为 `'N'`、`'U'`、`'P'`、`'T'`。

注意，此时 `buf` **不自动成为 C 字符串**。若要使用 `printf("%s", buf)`，应手动补终止符：

```c
buf[n] = '\0';
```

这里 `n` 是实际读到的字节数，不是写入字符串的长度加 1。

## 和相近概念的区别

| 对比项 | 无名管道 | 命名管道 FIFO |
|---|---|---|
| 创建方式 | `pipe()` | `mkfifo()` |
| 文件系统名称 | 没有 | 有路径名 |
| 典型使用进程 | 有亲缘关系进程 | 无亲缘关系进程也可 |
| 打开、使用方式 | 继承描述符后 `read/write` | `open` 后 `read/write` |
| 数据特性 | 字节流、通常单向使用 | 字节流 |

无名管道也不同于普通文件：它主要存在于内核中，读写通过文件描述符完成，不能用普通磁盘文件的思路理解其存储位置。

## 常见的坑

> [!WARNING]
> `read()` 返回 `0` 表示遇到管道 EOF，其条件是所有写端描述符都已关闭，而不只是当前进程关闭了自己的写端。

常见错误包括：

- **先 `fork()` 再分别 `pipe()`**：父子进程得到的是不同管道，不能据此通信。
- **读、写端记反**：`fd[0]` 读，`fd[1]` 写。
- **不关多余写端**：子进程可能一直阻塞在 `read()`，等不到 EOF。
- **期待保留消息边界**：管道是字节流，不保证一次 `read()` 对应一次 `write()`。
- **忽略返回值**：`read()`、`write()` 可能失败或返回实际处理的字节数。
- **向无读端的管道写入**：可能触发 `SIGPIPE`，使进程终止。

> [!TIP]
> 记忆口诀：**零读一写，先管后叉；不用就关，双向两管。**
