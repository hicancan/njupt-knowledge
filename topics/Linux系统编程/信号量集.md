# System V信号量集的创建semget、操作semop与控制semctl（PV操作）

## 信号量集：PV操作的系统级实现

如果多个进程需要协同访问共享资源，仅靠互斥锁能否解决“等待特定条件”或“批量原子操作”的问题？System V 信号量集正是为此设计的内核级同步原语。它不是单个计数器，而是==由一个或多个信号量组成的数组==，通过 `semget`、`semop`、`semctl` 三个系统调用实现经典的 PV 操作。

> [!IMPORTANT]
> System V 信号量集是**持久化内核对象**，以整数键值（key）标识，生命周期独立于创建进程，必须显式删除。

## 三大核心系统调用

-   **`semget(key, nsems, semflg)`**：创建或获取信号量集。`nsems` 指定集合中信号量个数；`IPC_CREAT | IPC_EXCL` 可确保独占创建，避免竞争。
-   **`semop(semid, sops, nsops)`**：执行 PV 操作的核心。`sops` 是 `sembuf` 结构体数组，==每个元素代表对集合中某个信号量的原子操作==。`sem_op > 0` 为 V 操作（释放），`sem_op < 0` 为 P 操作（申请），`sem_op == 0` 则阻塞等待信号量变为 0。
-   **`semctl(semid, semnum, cmd, ...)`**：控制与查询。常用 `SETVAL` 初始化单个信号量值、`GETVAL` 读取当前值、`IPC_RMID` 删除整个集合。

```mermaid
flowchart LR
    A["semget"] --> B["获取/创建集合"]
    B --> C["semctl SETVAL"]
    C --> D["初始化信号量"]
    D --> E["semop P/V"]
    E --> F["进程同步/互斥"]
    F --> G["semctl RMID"]
    G --> H["清理资源"]
```

## 与 POSIX 信号量的区别

| 特性 | System V 信号量集 | POSIX 命名信号量 |
| :--- | :--- | :--- |
| 标识方式 | 整数 key + semid | 文件系统路径名 |
| 操作粒度 | 支持多信号量原子操作 | 单信号量操作 |
| 初始化 | 需额外 `semctl(SETVAL)` | `sem_open` 时直接指定 |
| 自动清理 | ❌ 无，必须手动 `IPC_RMID` | ✅ 进程退出可自动回收 |
| 典型场景 | 复杂同步、老代码兼容 | 新开发、简单互斥 |

## 正确示例：生产者-消费者模型

假设缓冲区大小为 3，需用两个信号量：`empty`（初值 3）、`full`（初值 0）。

```c
// 创建含2个信号量的集合
int semid = semget(ftok("/tmp/shm", 'S'), 2, IPC_CREAT | 0666);
// 初始化：empty=3, full=0
union semun arg;
arg.val = 3; semctl(semid, 0, SETVAL, arg); // empty
arg.val = 0; semctl(semid, 1, SETVAL, arg); // full

// 生产者P(empty) + V(full) 原子执行
struct sembuf prod_ops[] = {
    {0, -1, 0},  // P(empty)
    {1, +1, 0}   // V(full)
};
semop(semid, prod_ops, 2); // ==两步操作不可分割==
```

> [!WARNING]
> `semop` 的 `nsops` 参数必须与实际 `sembuf` 数组长度一致，否则部分操作不会执行，导致死锁或数据错乱。

> [!CAUTION]
> 程序异常退出未调用 `IPC_RMID` 会导致信号量残留！调试时用 `ipcs -s` 检查，`ipcrm -s <semid>` 手动清除。

> [!TIP]
> 记忆口诀：`get` 建集合，`ctl` 设初值，`op` 做 PV，`rmid` 要牢记。P 为负 V 为正，零等变零才放行。
