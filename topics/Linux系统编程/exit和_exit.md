# exit()库函数与_exit()系统调用的区别

---
requires: [Linux编程/进程概念, Linux编程/系统调用与库函数]
---

## 它是什么

当一个进程需要结束时，我们通常调用 `exit()` 或 `_exit()`。虽然它们最终都会让进程终止并返回状态码给父进程，但两者的“身份”和“做事流程”截然不同：

- **`exit()`**：C 标准库函数（声明在 `<stdlib.h>`）。
- **`_exit()`**：Linux 系统调用（声明在 `<unistd.h>`）。

> [!IMPORTANT]
> ==核心区别==：`exit()` 在真正终止进程前会执行一系列**清理工作**（如刷新 I/O 缓冲区、调用 `atexit` 注册的函数），而 `_exit()` 直接进入内核终止进程，==不做任何用户态清理==。

用一张图看清两者的执行路径差异：

```mermaid
flowchart TD
    A["程序调用"] --> B{"选哪个？"}
    B -->|exit()| C["刷新 stdio 缓冲"]
    C --> D["调用 atexit 函数"]
    D --> E["_exit() 系统调用"]
    B -->|_exit()| E
    E --> F["进入内核"]
    F --> G["释放资源"]
    G --> H["进程终止"]
```

## 为什么需要两个

既然 `_exit()` 能直接终止进程，为什么还要封装一个 `exit()`？

想一想：如果程序刚用 `printf()` 往标准输出写了一段日志，但这段数据还停留在**用户态的 stdio 缓冲区**里，尚未真正写入文件描述符。此时若直接调用 `_exit()`，缓冲区的数据会发生什么？——会被直接丢弃，导致日志丢失。

`exit()` 的存在就是为了保证这些“收尾工作”被妥善完成。而在某些特殊场景下（例如 `fork()` 后的子进程中），我们又必须避免重复刷新父进程的缓冲区，这时就需要直接使用 `_exit()`。

## 怎么做与对比

两者在代码中的使用方式相似，都接收一个整型状态码 `status`（通常 $0$ 表示成功，非 $0$ 表示异常）：

```c
#include <stdlib.h>
#include <unistd.h>

exit(status);   // 库函数
_exit(status);  // 系统调用
```

| 对比维度 | `exit()` | `_exit()` |
| :--- | :--- | :--- |
| **类型** | C 库函数 | 系统调用 |
| **头文件** | `<stdlib.h>` | `<unistd.h>` |
| **刷新 stdio 缓冲区** | ✅ 是 | ❌ 否 |
| **调用 `atexit` 注册函数** | ✅ 是 | ❌ 否 |
| **进入内核终止进程** | ✅ 最终会调用 `_exit()` | ✅ 直接进入 |

> [!TIP]
> 记忆口诀：**库函数做善后，系统调用直接走**。

## 常见的坑

> [!WARNING]
> 在多进程编程中，`fork()` 产生的**子进程**如果不需要继承父进程的缓冲区状态，结束时应优先使用 `_exit()`。若误用 `exit()`，可能导致父进程未输出的缓冲区内容被子进程重复刷新输出，造成终端打印错乱或文件数据重复。

> [!NOTE]
> 结合考题辨析：“会话开始于程序启动运行，结束于程序运行完毕。（×）”
> 这句话错在混淆了“程序运行完毕”与“会话结束”。程序通过 `exit()` 或 `_exit()` 运行完毕后，只是该**进程**终止；而**会话**（Session）的生命周期与会话首进程（Session Leader）及控制终端绑定，并非简单等同于单个程序的起止。

## 算对了的例子

来看一段验证缓冲区行为的经典代码：

```c
#include <stdio.h>
#include <unistd.h>

int main() {
    printf("NJUPT"); // 注意：没有换行符 \n
    _exit(0);        // 直接调用系统调用
}
```

**分析过程**：
1. `printf("NJUPT")` 将字符串写入标准输出的**用户态缓冲区**。因为行缓冲模式下没有遇到 `\n`，且全缓冲模式下缓冲区未满，数据不会立即触发 `write` 系统调用。
2. 紧接着调用 `_exit(0)`，进程跳过缓冲区刷新，直接进入内核终止。
3. **结果**：屏幕上==什么都不会输出==。

如果把 `_exit(0)` 换成 `exit(0)`，`exit()` 会在进入内核前自动调用 `fflush()` 刷新所有打开的流，"NJUPT" 就能正常打印出来。这就是两者最直观的体现。
