# UDP协议（无连接特性、报文段格式、伪首部校验和计算）

## 无连接特性与复用分用

如果 IP 协议只负责把数据报送到目的主机，那么传输层还需要解决什么问题？答案是==复用/分用==。UDP 在 IP 服务之上仅增加了端口寻址和差错检测功能，是一种无连接的传输协议。

- **无连接**：发送前无需握手，不维护状态，不保证可靠交付、顺序或流量控制。
- **面向报文**：应用层交给 UDP 多长的报文，UDP 就原样封装发送，既不合并也不拆分。
- **套接字标识**：IP 地址定位主机，端口号定位进程，二者组合构成套接字（Socket），实现端到端通信。

> [!IMPORTANT]
> UDP 的核心价值是==低开销、高效率==，适用于 DNS、DHCP、TFTP、SNMP、RIP 及 RTP 等对实时性敏感或需广播的应用。

## 报文段格式

UDP 首部仅 8 字节，包含四个字段：

| 字段 | 长度 | 说明 |
| :--- | :--- | :--- |
| 源端口 | 2B | 可选，不用时置 0 |
| 目的端口 | 2B | 必需，用于分用 |
| 长度 | 2B | UDP 首部+数据总字节数 |
| 校验和 | 2B | 检测首部与数据差错 |

> [!NOTE]
> 与 TCP 不同，UDP 没有序号、确认号、窗口等字段，这正是其“轻量”的原因。

## 伪首部校验和计算

为什么 IP 层已有首部校验和，UDP 还要再算一次？因为 IP 只验首部，而传输层必须同时验证==首部和数据==的完整性。为此引入 12 字节“伪首部”，它仅参与计算，不实际传输。

```mermaid
flowchart LR
    A["伪首部12B"] --> B["UDP首部8B"]
    B --> C["数据部分"]
    C --> D["16位反码求和"]
    D --> E["取反得校验和"]
```

### 计算步骤详解

1.  **构造伪首部**：源 IP (4B) + 目的 IP (4B) + 全零 (1B) + 协议号 17 (1B) + UDP 长度 (2B)。
2.  **拼接数据**：伪首部 + UDP 首部 + 数据，按 16 位对齐；奇数字节时末尾补 0。
3.  **反码求和**：所有 16 位字累加，最高位进位回卷到最低位。
4.  **取反码**：将累加结果按位取反，即为校验和字段值。若结果为全 0，则置为全 1（区分未启用校验）。

> [!WARNING]
> 计算时务必使用==二进制反码加法==（进位回卷），而非普通十六进制加法！这是考试最常见的失分点。

### 正确计算示例

已知：源 IP `c0a80064`，目的 IP `c0a80066`，协议 17 (`0x11`)，UDP 长度 12 (`0x000C`)，UDP 数据部分为 `0035 0035 0008 0000`。

1.  伪首部划分：`c0a8` `0064` `c0a8` `0066` `0011` `000C`
2.  UDP 部分划分：`0035` `0035` `0008` `0000`
3.  反码求和（含进位回卷）得中间结果 `3AC7`
4.  取反：`~3AC7 = C538`

最终 UDP 校验和为 ==`C538`==。

> [!TIP]
> 记忆口诀：“伪首十二不传送，反码求和进位卷，取反填零辨未用”。做题时先列竖式对齐 16 位，再逐步累加，避免心算出错。
